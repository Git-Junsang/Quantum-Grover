# 자원 ablation — 5구성 공통조건 합성

## 무엇인가

6단계 ablation 의 다섯 컴파일 구성을 **같은 조건으로 합성**해서 각 단계가
자원을 얼마나 더 쓰는지 잰 표입니다. 조건은 Vivado 2024.2,
`xc7a100tcsg324-1`, 공통 소스·공통 XDC, 합성까지만(구현·배치배선 없음)입니다.

논문에 쓰는 주 수치는 **가속기만 떼어 낸 `u_main_ip` 계층 사용량**입니다.
standalone top 전체 수치는 참고용으로 같이 둡니다.

## 확정 수치 — Main IP 계층

| 단계 | LUT | FF | BRAM tile | DSP |
|---|---:|---:|---:|---:|
| Normal-E1 / K4/H4-E1 | 13,804 | 13,611 | 66.0 | 64 |
| K4/H4-E4 | 30,294 | 25,822 | 83.0 | 64 |
| K3/H3-E4 | 29,959 | 25,655 | 83.0 | 64 |
| K3/H3-E4-M1 | 33,547 | 28,195 | 84.0 | 128 |
| **K3/H3-E4-M2** | **33,730** | **28,258** | **84.0** | **128** |

Normal-E1 과 K4/H4-E1 이 같은 줄인 이유는 둘이 같은 비트스트림이기 때문입니다 —
런타임 mode 로만 갈립니다.

읽는 법:

- **E1 → E4 에서 LUT 이 2.2배** 뜁니다 (13,804 → 30,294). 연산기를 네 벌 두는
  값이고, 6단계 표에서 이 단계가 -38.71% 를 벌었습니다.
- **K4/H4 → K3/H3 은 오히려 조금 줄어듭니다** (30,294 → 29,959). 체크포인트와
  지평을 줄였으니 당연하고, 그러면서 사이클은 -7.66% 벌었습니다. 공짜 이득입니다.
- **M1 에서 DSP 가 64 → 128** 로 두 배가 됩니다. 측정 경로에서 한 사이클에
  두 행을 처리하게 만든 대가입니다. M2 는 그 위에 계층적 행 선택을 얹은
  것이라 자원이 거의 안 늘고(LUT +183) 사이클만 -18.94% 벌었습니다.

## 저장소 소스로 확인한 것

`hardware_bram/synth/run_main_ip.sh` 로 우리 `src/` 를 최종 파라미터
(K3/H3-E4-M2) 로 OOC 합성해 봤습니다. 2026-09-09, Vivado 2026.1, 합성 2분 14초.

| | OOC 합성 | 위 표 (공통조건) | 차이 |
|---|---:|---:|---:|
| LUT | 34,713 | 33,730 | +2.9% |
| FF | 28,202 | 28,258 | -0.2% |
| BRAM tile | 84.0 | 84.0 | 0 |
| DSP | 128 | 128 | 0 |

BRAM 과 DSP 가 정확히 맞고 FF 가 0.2% 안에 듭니다. LUT 이 2.9% 더 나오는 것은
OOC 단독 합성과 standalone top 안의 계층 추출이라는 조건 차이 때문입니다
(Vivado 버전도 2026.1 대 2024.2 로 다릅니다). **우리 `src/` 가 M2 구성이
맞다는 확인**으로는 충분하지만, 논문에 인용할 값은 위 표 쪽입니다.

## 이 숫자를 쓸 때의 경계

- **합성 결과이지 구현 결과가 아닙니다.** 배치배선을 거친 최종 수치는
  `hardware_bram/vivado/vivado_bbht_grover_fpga/reports/` 에 있고, 그쪽은
  RVX SoC 까지 포함한 전체라 LUT 45,284 / FF 45,223 / BRAM 116 / DSP 132 입니다.
- Vivado 버전과 합성 전략이 바뀌면 값이 달라집니다. 같은 조건으로 다섯을
  나란히 재는 것이 이 표의 목적이지 절대값을 못박는 것이 아닙니다.
- 합성 스크립트는 `hardware_bram/synth/` 에 있고, 대상 top 5벌은 재현 패키지
  `04_PUBLICATION_6STAGE/tops/` 에만 있습니다.
