## 필수 정정 (검증자가 원문 대조로 적발)

### 정정 1

- **틀린 주장**: equations 항목 (식 14)의 해설: "U_M(β_k)U_C(γ_k) = (H^⊗n D_M)(H^⊗n D_C) — (앞선 H^⊗n H^⊗n = I 로 소거된 결과.)"

- **문제**: 논문에 없는 서술이며 수학적으로도 틀렸다. 논문 p.3 (14)는 U_M U_C = (H^⊗n D_M H^⊗n)(D_C)를 단순히 괄호만 다시 묶은 것(regrouping)이다. H^⊗n H^⊗n = I 로 소거되는 과정은 논문 어디에도 없고, 실제로 소거되는 항도 없다. (게다가 논문의 H는 정규화되지 않은 [[1,1],[1,-1]]이라 H^⊗n H^⊗n = 2^n I 이지 I 도 아니다.)

- **바른 서술**: 해설에서 소거 관련 괄호를 삭제. "H^⊗n D_M H^⊗n D_C 를 (H^⊗n D_M)(H^⊗n D_C)로 재그룹핑하면 동일한 기본 연산 U_A = H^⊗n·D 가 두 번 반복되는 형태가 된다"로 정정.

### 정정 2

- **틀린 주장**: method.architecture: "페리페럴(UART, SPI는 AXI, I2C는 APB)"

- **문제**: Fig. 4(p.5)의 실제 버스 라벨과 다르다. PDF에서 좌표로 확인한 결과 버스 라벨은 AXI(Rocket) / AXI(SRAM) / AXI(QMA) / APB(JTAG·IROM·FLASH 그룹) / APB(UART·SPI·I2C 그룹) 이다. 즉 AXI는 Rocket·SRAM·QMA에 붙고, 페리페럴 쪽은 둘 다 APB다. 본문에도 각 페리페럴의 버스 배정은 언급이 없다.

- **바른 서술**: "System Interconnect에 Rocket / SRAM / QMA가 AXI로 연결되고, JTAG·IROM·FLASH 및 UART·SPI·I2C 페리페럴 그룹은 APB로 연결된다(Fig. 4)"로 정정.

### 정정 3

- **틀린 주장**: method.details: "아다마르는 아예 저장 안 하고 부호 로직으로 생성(H₁[i][j]의 부호는 i·j의 비트 AND 팝카운트 패리티로 결정됨)"

- **문제**: 괄호 안의 구현 방식(비트 AND 팝카운트 패리티)은 논문에 전혀 없다. 수학적으로는 참인 성질이지만 논문의 근거가 아니다. 오히려 논문 p.6 N_ADD 의사코드는 `if(H_1[i][count_5th] == 1) ... else if(== -1) ... else printf("Error: Unexpected value in H_1")` 로 H_1을 배열로 인덱싱하며, 논문이 말하는 것은 "H1의 원소가 ±1이므로 곱셈 대신 sign inversion logic + parallel addition으로 구현했다"까지다.

- **바른 서술**: 괄호 안 팝카운트 패리티 서술을 삭제하고 "논문은 H₁ 원소가 ±1이므로 곱셈 대신 부호 반전 로직 + 병렬 덧셈으로 구현한다고만 서술하며, H₁ 부호의 구체적 생성 방식은 명시하지 않는다"로 정정. (팝카운트 패리티는 우리 쪽 설계 아이디어로 별도 표기.)

### 정정 4

- **틀린 주장**: method.details: "대각행렬도 저장하지 않고 각도를 그때그때 계산해서 CORDIC으로 만든다. 즉 '행렬은 하드웨어 로직, 메모리에는 상태벡터만'" / beginner_hooks: "메모리 512개 대신 팝카운트 회로 1개"

- **문제**: 논문과 배치된다. p.5: "Given NUM QUBIT, QEX determines the required register blocks for storing coefficients of basis states **and elements of diagonal matrices**" — 대각행렬 원소도 레지스터 블록에 저장한다고 명시되어 있다. 추출본의 architecture 절은 이를 올바로 적었는데("상태 계수·대각원소 레지스터 블록") details/beginner_hooks 절과 서로 모순된다. 또 cost_hamil_diag[0..N-1]도 명백히 저장되는 배열이다.

- **바른 서술**: "논문은 상태 계수와 대각행렬 원소 모두를 레지스터 블록에 저장한다(QEX가 NUM_STATE 개로 자동 구성). 다만 D_M의 각도는 HW 팝카운트로 즉석 계산되고, cos/sin은 CORDIC이 실시간 생성한다"로 정정.

### 정정 5

- **틀린 주장**: method.details: "DSP 31~32개라는 숫자는 이 복소수 곱셈기 1세트 + 각도 계산용 곱셈 + CORDIC 등을 합친 것으로 보인다."

- **문제**: 논문은 DSP 총량(31~32)만 보고할 뿐 어떤 모듈이 몇 개를 쓰는지 분해(breakdown)를 전혀 제시하지 않는다. 특히 CORDIC은 정의상 shift+add 알고리즘이라 DSP를 쓴다고 볼 근거가 없고, 기준 프로세서만으로도 이미 DSP 4개를 쓴다(Table II 각주). 추측을 논문 근거처럼 읽힐 수 있게 배치했다.

- **바른 서술**: "논문은 DSP 총량만 보고하고 모듈별 분해는 제시하지 않는다. 가속기 없는 기준 프로세서가 이미 DSP 4개를 쓰므로 QMA 자체의 순증분은 약 27~28개로 역산되나, 이 역시 논문에 명시된 값은 아니다"로 하고 추측임을 명시.

## 검증 결과 요약

**수치는 사실상 전부 정확하다.** Table I(6행 × 4열), Table II(기존 3행 + 제안 7행), Table III(6행), 각주 기준값(24853/24445/4, 12555/17154/4), 100MHz, N+1 사이클, CORDIC 16클럭, O(N²)→O(N), 2,182×, 852×, 1.53×, 1.56×, 78% LUT 감소, 9/8큐비트 한계 — PDF 원문 대조 결과 전부 일치. 저자 4인·제목·arXiv:2502.11316v2 [cs.ET] 2025-03-27도 일치. 수식 16개 중 LaTeX 표기는 (14) 해설을 제외하면 모두 논문과 일치. **결정적 허위(hallucination)는 없고, 위 7건은 대부분 세부 구현 추측이 논문 근거처럼 섞여 들어간 경우와 페이지 오기다.**

## 추출본이 놓친 중요 내용

**1) 논문 자체의 수식 오류 — 추출본이 그대로 베껴서 전파하고 있다.**
- **식 (6)이 물리적으로 뒤집혀 있다.** 논문은 "1 if the l-th bits of i and j are different, −1 if the same"이라 쓰지만, 올바른 정의는 (a) 주어가 반대다 — "l의 i번째 비트와 j번째 비트"여야 하고(i, j의 l번째 비트가 아니라), (b) 부호도 반대다 — Z_iZ_j(l,l)은 두 비트가 **같을 때 +1**, **다를 때 −1**이다. 그래야 식 (5)의 (1/2)ω(I − Z_iZ_j)가 "다를 때만 ω 기여"라는 MaxCut 정의(식 4)와 맞고, p.5의 `if (bit_i != bit_j) cost_hamil_diag[k] += 2.0*weight` 의사코드와도 맞는다. 추출본은 이걸 검증 없이 옮겼고 "하드웨어에서 XOR 한 게이트로 끝난다"는 해설까지 붙였다. **인용 시 반드시 부호를 바로잡을 것.**
- **식 (12)~(16)의 정규화가 엉성하다.** 논문은 [[1,1],[1,−1]](정규화 안 됨)을 그냥 "H"라 부르고 R_X = HΛ_M H 라 쓰는데, 엄밀히는 H_u Λ H_u^{-1} 이고 H_u^{-1} = H_u/2 이다. 즉 (12)의 우변 세 번째 항에 붙은 `^{-1}`이 (13)에서 슬그머니 사라진다. 결과적으로 (16)의 1/2ⁿ 팩터는 이 정규화 부기(bookkeeping)의 산물인데, 논문은 (15)의 H₁ 정의(1/√2ⁿ · H^⊗n)를 두 번 적용해 1/2ⁿ를 얻는 것처럼 서술해 유도가 매끄럽지 않다. 우리가 문서화할 때는 H^⊗n = (1/√2ⁿ)·(±1 행렬)로 일관되게 다시 유도하는 편이 안전하다.
- **식 (17) 첨자 오타**: `Σ_{k=0}^{∞} (−iγ_k)^m/m!` — 합 인덱스가 k인데 항은 m을 쓴다. m이 맞다.
- **식 (18)/(19)/(20)의 범위 오타**: "for l = 1, 2, ..., **n**"이라 쓰지만 대각원소는 N = 2ⁿ개이므로 l = 1..**N**이 맞다.
- **Fig. 1 캡션 그림 오타**: mixer가 U_M(γ₁), U_M(γ₂), U_M(γ_p)로 표기됨 — β여야 한다. 게다가 마지막이 "U_M(γ_p) U_M(γ_p)"로 중복 인쇄.
- **Table II/III 헤더 오타**: "(falied)" (failed).

**2) 비교 대상(Conventional)의 정체 — 추출본이 이 결정적 맥락을 빠뜨렸다.**
p.7: "hardware accelerators for **matrix-vector multiplication in universal QC** (Conventional), designed without our optimizations." 즉 Table II의 기존 방식은 QAOA 전용 최적화 가속기가 아니라 **범용 QC용 일반 행렬-벡터 곱 가속기**다. 이건 사과-오렌지 비교에 가깝다 — 제안 방식의 이득 중 상당 부분은 "파이프라인 잘 짜서"가 아니라 "MaxCut 전용이라 대각 구조를 쓸 수 있어서"에서 온다. 우리가 Grover 보고서에서 같은 표 포맷을 쓸 때, 베이스라인이 무엇인지 정직하게 밝히지 않으면 같은 비판을 받는다. **추출본의 limitations에 이 항목을 추가할 것.**

**3) 8큐비트 에너지 수치 누락.** Table I에서 8큐비트는 108 → 0.30 mJ/exec (360×)인데 추출본에 없다. 흥미로운 점: 제안 방식의 에너지가 8큐비트 0.30 → 9큐비트 0.48 mJ로 실행시간(0.30→0.34ms)보다 훨씬 가파르게 뛴다 — LUT가 79k→130k로 늘며 정적 전력이 급증했음을 시사한다. 즉 "에너지도 큐비트에 거의 무관"이 아니다. 우리 설계에서 BRAM 전환의 근거로 쓸 수 있는 숫자다.

**4) Fig. 3 (p.4) 자체가 누락됐다.** 2큐비트 예제로 1st op(1_MULT)와 2nd op(1_MULT + N_ADD)가 어떻게 겹쳐 도는지를 보여주는 그림인데, 추출본 method는 Fig. 5(레지스터 레벨)만 서술한다. 파이프라인 개념을 처음 잡을 때 Fig. 3이 훨씬 직관적이라 우리 해설서에 그대로 옮길 가치가 있다.

**5) 참고문헌 [30]의 의미.** 논문이 fixed-point를 정당화하며 인용한 [30]은 양자 관련이 아니라 **CNN FPGA 가속기 논문**(Zhang et al., FPGA'15)이다. 즉 고정소수점 선택에 양자 특유의 근거가 전혀 없다는 뜻이며, 추출본의 limitations("비트폭·정밀도 분석 부재")를 뒷받침하는 추가 증거다.

**6) 추출본 limitations 중 "논문은 이 한계를 인정하지 않고 있다"(9큐비트 확장 한계)는 정확하다.** 결론(p.8)에 future work가 전혀 없음을 재확인했다. 또 "Rocket 코어가 도는 최적화 알고리즘이 무엇인지조차 언급되지 않았다"도 정확 — p.5는 "enabling the user to optimize variational parameters based on the outcome"까지만 말한다.

**7) project_relevance 절은 대부분 논문 검증 대상이 아닌 우리 프로젝트 설계 제안이다.** 사실 오류는 없으나(참고문헌 [10] 서지사항 AIMS Mathematics vol.9 no.11 pp.30939–30971, 2024도 원문과 일치), 논문 근거와 우리 아이디어가 한 필드에 섞여 있어 나중에 인용할 때 혼동 위험이 크다. 문서화 단계에서 "논문이 말한 것 / 우리가 추론한 것"을 시각적으로 분리할 것을 권한다.
