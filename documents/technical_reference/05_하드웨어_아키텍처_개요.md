## 5.1 모듈 계층

<img src="../design_references/diagrams/final_design_stack.svg" alt="호스트 PC부터 Main IP까지의 계층" width="820">

RVX가 생성한 SoC에는 프로젝트의 user region이 포함됩니다. 내부 계층은 다음과 같습니다.

```
RVX SoC (bbht_grover_upgrade)
├── ORCA RV32 코어 + micro NoC          RVX 생성 (50 MHz도메인)
├── APB NI (sni_apb_asynch)             RVX 생성 · CDC 담당
├── AHB NI (mni_ahbm_asynch)            RVX 생성 · CDC 담당
├── 시스템 SRAM 128 kB                  RVX 생성
└── user region                         프로젝트 구현 (100 MHz도메인)
    └── bbht_rvx_wrapper                최상위. 계약 이름 bbht_grover_core에 연결
        ├── bbht_grover_mmio            APB 슬레이브 · CSR 38개
        ├── bbht_ahb_loader             AHB 마스터 · 데이터셋 DMA
        └── bbht_grover_core_adapter    계약 이름과 리셋 차이를 변환
            └── bbht_grover_main_ip     Main IP (8장~11장)
```

| [`bbht_grover_mmio.v`](../../hardware_bram/src/bbht_grover_mmio.v) | APB CSR. 생성 헤더 `bbht_grover_csr.vh`를 include |

| [`bbht_bram_top.v`](../../hardware_bram/src/bbht_bram_top.v) | 두 번째 최상위. 어댑터 없이 Main IP에 직접 연결 |
| [`bbht_grover_user_region.vh`](../../hardware_bram/src/bbht_grover_user_region.vh) | RVX에 넘기는 결선. 클럭 assign 두 줄이 여기 |

### 두 최상위 모듈의 용도

`bbht_rvx_wrapper`와 `bbht_bram_top`은 포트가 같고 둘 중 하나만 합성합니다.

| 최상단 | 쓰임 |
|---|---|
| `bbht_rvx_wrapper` | RVX 플랫폼에 들어가는 것. 어댑터를 거칩니다 |
| `bbht_bram_top` | 저장소 회귀용. mmio·loader를 Main IP에 직접 연결합니다 |

`bbht_bram_top`은 DRAM 갈래의 [`bbht_dram_top.v`](../../hardware_dram/src/bbht_dram_top.v)
와 짝입니다. 같은 테스트벤치 틀로 두 갈래를 비교할 수 있게 하려는 구조입니다
([18장](18_부록_DRAM_갈래와_용어집.md)).

## 5.3 클럭과 리셋 소유권

| 경계 | network 쪽 | user 쪽 | CDC | 소유 |
|---|---|---|---|---|
| APB CSR | `gclk_noc` | `i_grover_csr_clk = gclk_accel` | `sni_apb_asynch` | RVX 생성 |
| AHB DMA | `gclk_noc` | `i_grover_dma_clk = gclk_accel` | `mni_ahbm_asynch` | RVX 생성 |
| 가속기 내부 | — | `gclk_accel` 하나 | 없음 | 프로젝트 구현 |

`user_slaveif_apb_clkout`과 `user_masterif_ahb_clkout`을 사용하므로 클럭은 user region에서
공급합니다. 다음 두 줄이 각 인터페이스의 클럭을 연결합니다.

```verilog
assign i_grover_csr_clk = gclk_accel;
assign i_grover_dma_clk = gclk_accel;
```

리셋은 두 인터페이스가 같은 reset group에서 나오므로 함께 풀립니다. wrapper는
`i_grover_csr_rstnn` 하나를 받아 전체에 씁니다. 비동기 assert, 음논리입니다.

wrapper나 Main IP 내부에는 별도의 CDC를 추가하지 않습니다. RVX가 생성한 CDC 구조가
실제 보드에서 검증되었으며, CDC를 중복 삽입하면 기존 검증 결과를 적용할 수 없습니다. 2026-09-16 구현
리포트의 Inter Clock Table이 비어 있는 것으로 도메인 간 경로가 없음을 확인했습니다
([17장](17_합성_구현_비트스트림.md)).

### `gclk_accel`과 `clk_accel`

보드 정본(2026-09-07)의 user region은 가속기 클럭에 `clk_accel`을 연결하고, 현재 main
브랜치는 `gclk_accel`을 연결합니다. RVX 생성 RTL의
`assign gclk_accel = clk_accel;`을 보면 두 신호 사이에 게이팅이나 BUFG 없이 단순 별칭만
있습니다. 이 연결은 2026-09-16 구현 묶음의 `build_info.txt`와 2026-09-17 보드 세션에서
확인했습니다.

## 5.4 데이터 입출력 경로

들어오는 길: 데이터셋은 CSR로 넣지 않습니다.

```
호스트 배열 또는 보드 GEN
    → 코어가 시스템 SRAM (0xE0000000~0xE001FFFF)에 배치
    → CSR에 시작 주소·개수 기록, COMMAND로 적재 시작
    → bbht_ahb_loader가 AHB SINGLE로 워드를 순서대로 읽음
    → Main IP의 데이터 메모리에 P32 배치로 채움
```

AHB는 SINGLE 전송, single outstanding입니다. 버스트를 쓰지 않습니다. 적재 중의
오류(정렬 위반, SRAM 범위 밖, 개수 초과, 중복 주소)는 `DMA_STATUS`로 나옵니다
([12장](12_CSR_레지스터와_실행_모드.md)).

나가는 길: 단일 탐색은 `result_index` 하나, 열거는 결과 FIFO(깊이 256)에 쌓입니다.
펌웨어가 FIFO를 비울 때까지 다음 탐색이 시작되지 않습니다(5.5절).

## 5.5 시작 명령 수락 조건

```
start_accept = cmd_search_start     COMMAND 쓰기가 만든 1사이클 펄스
             && !search_busy        실행 중이 아닐 것
             && !load_busy          적재 중이 아닐 것
             && res_empty           직전 열거 결과가 남지 않았을 것
             && !done_pending       직전 완료가 아직 안 읽혔지 않을 것
```

start 큐는 두지 않습니다. 조건을 만족하지 못한 펄스는 저장되지 않으므로 펌웨어는
`COMMAND`를 쓰기 전에 `STATUS`를 확인해야 합니다. 큐에 대기 중인 요청이 있으면 실제 시작
시점을 소프트웨어에서 알기 어렵고, 서로 다른 실행의 카운터를 함께 읽을 수 있기 때문입니다.

`done_pending`은 mmio의 `done_sticky`입니다. `COMMAND` 쓰기가 그것을 클리어하고 한
사이클 뒤에 `cmd_search_start`가 나오므로 정상 순서(설정 → `COMMAND` → 폴링)는 항상
통과합니다. 걸리는 것은 앞 실행을 읽지 않고 곧바로 다음 start를 밀어 넣는 경우뿐입니다.

`search_busy`는 코어가 따로 내보내지 않습니다. 계약이 `busy = search_busy | load_busy`
로 정의하므로 `busy & ~load_busy`로 유도합니다.

## 5.6 어댑터의 합성 비용

`bbht_grover_core_adapter`는 계약 이름(`bbht_grover_core`)과 실물 모듈 이름
(`bbht_grover_main_ip`), 그리고 리셋 이름(`rstnn` ↔ `rstn`)을 연결하는 래퍼입니다. K·H·E·M
파라미터의 기본값이 여기 있습니다.

2026-09-16 구현의 계층 리포트에서 어댑터와 내부 Main IP의 LUT 수가 같습니다. 배선만
수행하므로 추가 논리가 합성되지 않았음을 의미합니다.
