# BBHT/Grover 다중 타겟 탐색 가속기 기술 레퍼런스

> 중앙대학교 학부인턴 · LPSoC BBHT/Grover 프로젝트
> RVX SoC 커스텀 IP + 호스트 UART 제어 (Arty A7-100T / Artix-7 `xc7a100tcsg324-1`)

---

## 0. 문서 목적과 범위

이 레퍼런스는 알고리즘, 소프트웨어 기준 모델, RTL, 인터페이스 계약, 검증 환경, Vivado
구현을 한 흐름으로 설명합니다. 팀 내부 인수인계와 설계 검토가 주된 목적이며, 처음 코드를
접하는 개발자도 시스템의 동작 원리와 구현 구조를 파악할 수 있도록 구성했습니다.

내용은 2026-09-17 보드 콘솔 검증 결과를 기준으로 합니다. 이 시점에 호스트 PC부터 실제
FPGA까지 전체 경로의 동작을 확인했습니다.

### 0.1 대상 독자

- 프로젝트에 새로 합류해 전체 구조를 빠르게 파악해야 하는 팀원
- 특정 RTL 모듈을 고치기 전에 그 모듈의 동작·포트·타이밍을 확인하려는 개발자
- 궤적이나 사이클이 어긋났을 때 데이터 포맷·메모리 맵·검증 전략을 거슬러 올라가야 하는 사람
- 보드에서 직접 명령을 넣어 보려는 사람

양자 알고리즘을 이미 알고 있다면 [3장](03_Grover와_BBHT_알고리즘.md)부터 읽어도 됩니다.
기초 설명부터 필요하다면 학습용 해설서
[`documents/study_references/`](../study_references/00_양자컴퓨팅_시작하기.md)의 0장부터
시작하는 편이 좋습니다.

### 0.2 현재 문서 범위

| 영역 | 상태 | 이 문서 수록 |
|---|---|---|
| BRAM 갈래 (`hardware_bram/`) RTL·검증 | 보드 실측 완료 | 본문 전체 |
| 통신 계층 교체 버전 | 2026-09-17 보드에서 명령 왕복 확인 | 본문 (16장) |
| 성능 세 축 (보드 시간 · RTL 사이클 · ORCA 대비) | 2026-09-08 정본 빌드 기준 | 본문 (1장 · 17장) |
| 교체 버전의 실경과 시간 · 500 워크로드 보드 실측 | 미측정 | 16장의 남은 검증 항목에 명시 |
| DRAM 갈래 (`hardware_dram/`) | RTL 초안 + 동작 수준 모델 위 회귀까지 | 부록 (18장) 개요 |
| 물리 DRAM 바인딩 · 열거 · RVX 설치 | 없음 | 18장에 계획으로 |

## 3. 문서 표기 규약

- 신호 · 포트 · 모듈명: 코드 식별자는 `cfg_predicate_mode`, `grover_bbht_shot_fsm`,
  `S_PASS1`처럼 표기합니다.
- 소스 인용: 가능하면 [`bbht_grover_main_ip.v`](../../hardware_bram/src/bbht_grover_main_ip.v)
  처럼 실제 파일을 상대 링크로 연결합니다. 라인 번호는 코드 변경에 따라 달라질 수 있으므로
  모듈명이나 신호명 같은 식별자를 기준으로 찾습니다.
- 수식: 본문에 LaTeX를 쓰지 않습니다. 필요한 식은 코드 블록이나 산문으로 풉니다.
- 다이어그램: 본문에 mermaid fence를 직접 쓰지 않고 HTML `img` 태그로 SVG를
  참조합니다. 어느 뷰어에서든 보이게 하려는 의도이고,
  [`check_docs.py`](../check_docs.py)가 이것을 검사합니다. 소스는
  [`../design_references/diagrams/src/`](../design_references/diagrams/src/)의 `.mmd`이고
  `render_diagrams.py`로 렌더합니다.
- 성능 수치: 보드 실경과 시간, RTL 사이클, 소프트웨어 대비 중 어느 기준인지 함께
  표시합니다. 서로 다른 기준을 섞어 배수를 계산하지 않습니다. 자세한 이유는
  [1장](01_프로젝트_개요.md)에서 설명합니다.
- 미확인: 검증하지 않은 항목은 해당 장에서 범위와 함께 명시합니다.
