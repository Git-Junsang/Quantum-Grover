## 17.1 구현 결과 비교

| 항목 | 2026-09-07 (보드 정본) | 2026-09-16 (통신 계층 교체판) |
|---|---:|---:|
| Vivado | 2024.2 | 2026.1 |
| WNS (100 MHz) | +0.126 ns | +0.196 ns |
| TNS / failing endpoints | 0 / 0 | 0 / 0 |
| Slice LUT | 45,284 | 45,116 |
| Block RAM tile | 116 | 116 |
| DSP48E1 | 132 | 132 |

가속기 도메인 엔드포인트 74,623개가 모두 통과했고 Inter Clock Table도 비어 있습니다.
이는 도메인 간 경로가 없으며 [5장 5.3절](05_하드웨어_아키텍처_개요.md)의 CDC 소유권
설계가 유지되었음을 보여 줍니다.

어댑터는 배선만 수행하므로 별도의 논리 자원을 사용하지 않습니다. 계층 리포트에서도
어댑터와 내부 Main IP의 LUT 수가 동일합니다.

### 결과의 해석 범위

이 결과는 통신 계층을 교체한 설계도 같은 칩에서 유사한 타이밍 여유로 구현됨을 보여
줍니다. LUT는 168개 줄었고 BRAM과 DSP 사용량은 같습니다.

다음 내용은 이 표만으로 판단할 수 없습니다.

- 두 비트스트림의 해시 비교. Vivado 판이 다릅니다. 원리상 불가능합니다.
- "보드 빌드가 재현됐다". 같은 도구로 같은 결과가 나온 것이 아닙니다.
- 성능. 이 묶음에는 실행 결과가 없습니다. 성능은 [1장 1.5절](01_프로젝트_개요.md).

근거는 [comm_layer_rebuild](../../hardware_bram/vivado/vivado_bbht_grover_fpga/2026-09-16_comm_layer_rebuild/evidence.md)
입니다.

## 17.2 자원 ablation 다섯 구성

다섯 구성을 같은 조건(Vivado 2024.2, `xc7a100tcsg324-1`, 공통 소스 · 공통 XDC,
합성까지)으로 재고 Main IP 계층만 떼어 낸 값입니다.

| 구성 | LUT | FF | BRAM tile | DSP |
|---|---:|---:|---:|---:|
| Normal-E1 / K4/H4-E1 | 13,804 | 13,611 | 66.0 | 64 |
| K4/H4-E4 | 30,294 | 25,822 | 83.0 | 64 |
| K3/H3-E4 | 29,959 | 25,655 | 83.0 | 64 |
| K3/H3-E4-M1 | 33,547 | 28,195 | 84.0 | 128 |
| K3/H3-E4-M2 | 33,730 | 28,258 | 84.0 | 128 |

주요 변화는 다음과 같습니다.

- E1에서 E4로 바꾸면 LUT 사용량이 2.2배가 되고 사이클은 38.71% 감소합니다
  ([9장](09_연산_경로와_E4.md)).
- K4/H4에서 K3/H3으로 바꾸면 자원 사용량과 사이클이 모두 감소합니다. BRAM 사용량이
  같은 이유는 물리 슬롯이 K와 관계없이 4개이기 때문입니다
  ([6장 6.5절](06_데이터_표현과_메모리_맵.md)).
- M1에서는 측정 BUILD를 사이클당 두 행으로 처리하기 위해 DSP 사용량이 두 배가 됩니다.
  M2는 LUT 183개만 추가로 사용합니다([10장](10_측정_경로와_M1_M2.md)).

근거는 [resource_ablation_5config](../../hardware_bram/results/2026-09-08_resource_ablation_5config/evidence.md)
입니다. 논문에 인용할 값은 이 표 쪽입니다.

## 17.3 Main IP 자원 재측정

저장소의 `src/`를 최종 파라미터로 OOC 합성하면 됩니다.

```bash
hardware_bram/synth/run_main_ip.sh      # Vivado, 2분쯤
```

결과는 BRAM과 DSP가 정확히 맞고 FF가 0.2% 안에 듭니다. LUT은 +2.9% 인데 합성
조건 차이입니다.

다섯 구성을 한꺼번에 재는 `run_resource.sh`는 standalone top 틀이 필요해서 태그
`board-k3h3-e4-m2`에 있습니다([2장 2.2절](02_개발_환경과_빌드.md)).

`grover_policy_ooc_top.v` · `grover_policy_impl_wrapper.v`는 정책 엔진만 따로 OOC
합성해 타이밍을 확인하는 용도이며 전체 설계 합성 소스에서는 제외합니다.

## 17.4 구현 리포트 위치

| 경로 | 내용 |
|---|---|
| [`vivado/vivado_bbht_grover_fpga/reports/`](../../hardware_bram/vivado/vivado_bbht_grover_fpga/) | 최종 구현 `route_{util,util_hier,timing_summary,timing_max,power}.rpt` |
| `vivado/vivado_bbht_grover_fpga/meta/` | 빌드 정보 · 소스 sha256 · 비트스트림 sha256 |
| `vivado/vivado_bbht_grover_fpga/2026-09-16_comm_layer_rebuild/` | 교체판 구현 리포트 |

`meta/source_sha256.txt`는 부분 기록입니다. 정본 빌드의 RTL 17개 가운데 7개만 적혀
있으므로, 그것만 보고 "전부 대조했다" 고 하면 안 됩니다. 17개 전부는
[`sha256_final_rtl.txt`](../../hardware_bram/results/2026-09-09_repro_package_v1.0/evidence.md)
에 있고 태그 `board-k3h3-e4-m2`와 17/17 일치합니다.
