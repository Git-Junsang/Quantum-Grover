## 2.1 툴체인 실측 판본

2026-09-09에 이 환경에서 직접 확인한 값입니다.

| 도구 | 판본 | 쓰임 |
|---|---|---|
| `verilator` | 5.020 | 저장소 회귀 전체 실행 |
| `vsim` (Questa) | 2022.1_2 | RVX SoC 전체 RTL 시뮬 |
| `vivado` | 2026.1 (노드락) | `xc7a100tcsg324-1` 합성·구현·비트스트림 |
| RISC-V GCC | RVX 동봉 | ORCA 코어용 펌웨어 |
| `iverilog` / `vvp` | 12.0 | 보조 |
| RVX | `/opt/rvx`로컬 전체 설치 | 플랫폼 생성·시뮬·구현 |

보드 정본 비트스트림(2026-09-07)은 Vivado 2024.2로 구웠습니다. 지금 환경은 2026.1
이라 두 빌드의 비트스트림 해시를 비교할 수 없습니다([17장](17_합성_구현_비트스트림.md)).

### 환경 제약

- 헤드리스입니다. `gtkwave`와 Vivado GUI는 설치돼 있어도 띄울 수 없습니다. Vivado는
  `-mode batch` 전용입니다.
- 저장소 경로에 공백이 있습니다 (`중앙대학교 학부인턴`). verilator가 생성한 Makefile을
  제자리에서 돌릴 수 없어서, [`sim/Makefile`](../../hardware_bram/sim/Makefile)이
  `--Mdir /tmp/...`로 빌드 디렉터리를 분리합니다. 이 설정은 유지해야 합니다.

## 2.2 저장소 회귀: Verilator

`hardware_*/testbench/`에는 테스트벤치 소스만 있고 Makefile이 없습니다. 모든 진입점은
`sim/Makefile`입니다.

```bash
# 통신 계층 회귀 (몇 초)
make -C hardware_bram/sim ports lint regress driver

# 통신 계층 + 어댑터 + Main IP (몇 분)
make -C hardware_bram/sim real

# 최상단 bbht_bram_top 회귀 (1분 30초쯤)
make -C hardware_bram/sim top

# 250쌍 궤적 벤치 (20분쯤)
make -C hardware_bram/sim bench250

# DRAM 갈래 회귀 (1분 30초쯤). equiv는 BRAM 정본과 궤적 대조까지 (40초 더)
make -C hardware_dram/sim
make -C hardware_dram/sim equiv
```

모든 타깃은 `csr:`를 선행 조건으로 실행합니다. RTL 네 곳과 테스트벤치 세 곳이
`bbht_grover_csr.vh`를 include하고, `bbht_grover_driver.h`가
`bbht_grover_regs.h`를 include하므로 회귀 전에 CSR 정합성을 먼저 확인해야 합니다.
CSR 생성 파이프라인은
[12장](12_CSR_레지스터와_실행_모드.md).

6단계 ablation과 K/H 단독 실험은 standalone top을 사용하므로 main 브랜치에 포함되지
않습니다. 다음과 같이 태그에서 별도 worktree를 만들어 실행합니다.

```bash
git worktree add /tmp/board board-k3h3-e4-m2
make -C /tmp/board/hardware_bram/sim anchor      # publication · kh도 같은 자리
```

## 2.3 RVX 플랫폼

RVX는 `/opt/rvx`에 전부 설치되어 있어 원격 접속이 필요 없습니다. 따를 예제는
`platform/tip_quantized_cnn/` (커스텀 IP + `user/rtl` · `user/api` 구조가 우리와 같습니다).

```bash
source /opt/rvx/rvx_setup.sh
hardware_bram/rvx/install_to_platform.sh
cd $RVX_MINI_HOME/platform/bbht_grover_upgrade
make syn        # XML로부터 RTL·시스템 소프트웨어 생성
make sim_rtl    # Questa 시뮬 환경
```

[`install_to_platform.sh`](../../hardware_bram/rvx/install_to_platform.sh)가 저장소의
`src/` (통신 계층 · 어댑터 · Main IP)와 user region 결선, 그리고 앱별 설정 파일을 플랫폼
쪽으로 옮깁니다. 플랫폼 정의는
[`bbht_grover_upgrade.xml`](../../hardware_bram/rvx/bbht_grover_upgrade.xml)이고 여기서
가속기 클럭 100 MHz가 정해집니다.

`rvx/bbht_grover_user_region.vh.generated`는 RVX `make syn`이 생성한 빈 템플릿입니다.
RVX가 IP를 변경했을 때 현재 user region과 대조하는 용도이며, 실제 합성에는
`src/bbht_grover_user_region.vh`를 사용합니다.

### SoC 시뮬레이션의 콘솔 입력

`bbht_console`의 UART 버전은 SoC 시뮬레이션에서 `read_line()`에 멈춥니다. RVX의
`ncsim_printf.v`가 `uart_tx`를 1로 묶어 두어 보낼 쪽이 없기 때문입니다. 그래서
[`firmware/bbht_console/rvx_each.mh`](../../hardware_bram/firmware/bbht_console/rvx_each.mh)
가 RTL 시뮬 빌드(`TARGET_IMP_CLASS=rtl`)에만 `-DBBHT_CONSOLE_SCRIPT`를 넣고, 콘솔은
명령을 컴파일 시점 배열에서 읽습니다. 보드 빌드 ELF는 바이트 단위로 그대로입니다.

명령줄에서 `DEFINE_CFLAGS`를 전달해도 `make bbht_console.sim`이 시뮬레이션 직전에 앱을
다시 빌드하면서 해당 정의가 사라집니다. 따라서 스크립트 모드 적용 여부는 로그에서
확인해야 합니다.

```bash
(cd $RVX_MINI_HOME/platform/bbht_grover_upgrade/sim_rtl && make bbht_console.sim)   # 3분쯤
grep -c BBHT_CONSOLE_SCRIPT $RVX_MINI_HOME/platform/bbht_grover_upgrade/sim_rtl/rvx_app_build.log
```

0이 나오면 스크립트 모드가 아닙니다. 이 증상을 한동안 "원인 미확인 멈춤" 으로 잘못
기록했던 적이 있어서, 진단 순서를
[soc_rtl_console evidence](../../hardware_bram/results/2026-09-16_soc_rtl_console/evidence.md)
에 남겨 두었습니다.

## 2.4 소프트웨어 기준모델

파이썬 가상환경에 [`software/requirements.txt`](../../software/requirements.txt)를 설치한
뒤 돌립니다.

```bash
bash software/experiments/common500_benchmark/run_full_benchmark.sh
```

NumPy와 Qiskit까지 모두 실행하면 수 시간이 걸립니다. 중단된 경우 같은 명령으로 이어서
실행할 수 있습니다. 모델
구성과 결과는 [4장](04_소프트웨어_기준모델과_정답_벡터.md).

호스트 CLI는 보드가 없어도 두 가지 대체 트랜스포트로 돌릴 수 있습니다.

```bash
python3 software/host/bbht_cli.py --port mock selftest             # 파이썬 모델
python3 software/host/bbht_cli.py --port replay:<트랜스크립트> -c ID -c RUN
```

`mock`은 동작 확인용이라 수치를 인용하면 안 됩니다. `replay:`는 RTL 시뮬
트랜스크립트를 그대로 재생합니다. [13장](13_호스트_인터페이스와_UART_프로토콜.md).

## 2.6 보드에 굽고 앱 올리기

실물은 [`hardware_bram/bitstream/2026-09-17_comm_layer_rebuild/`](../../hardware_bram/bitstream/2026-09-17_comm_layer_rebuild/evidence.md)
에 굽기·적재 스크립트까지 같이 들어 있습니다.

```bash
# 1. 비트스트림 (Vivado 배치 모드)
vivado -mode batch -source program_fpga.tcl

# 2. 앱: JTAG 어댑터가 붙어 있는 PC에서
cp /opt/rvx/local_setup/ocd/openocd_rvp ocd/
ocd/ocd_keep.sh &        # OpenOCD를 붙여 둔 채 유지

# 3. 호스트에서 명령
python3 software/host/bbht_cli.py --port /dev/ttyUSB1 selftest
```

OpenOCD를 종료하면 앱이 사라집니다. JTAG 어댑터가 분리될 때 플랫폼이 리셋되고, 앱은
SRAM이미지로만 적재되므로 SPI 플래시에서 다시 부팅되지 않습니다. 보드 RESET 버튼도
같은 결과를 냅니다.
자세한 절차와 보드에서만 나온 문제는 [16장](16_보드_확인과_실측.md).
