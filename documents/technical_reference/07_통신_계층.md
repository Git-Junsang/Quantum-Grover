통신 계층은 다음 네 파일로 구성됩니다. RVX가 생성한 포트를 Main IP에 연결하고 CSR 접근과
데이터 적재를 처리합니다.

| 파일 | 역할 |
|---|---|
| [`bbht_rvx_wrapper.v`](../../hardware_bram/src/bbht_rvx_wrapper.v) | 셋을 묶는 결선판 |
| [`bbht_grover_mmio.v`](../../hardware_bram/src/bbht_grover_mmio.v) | APB 슬레이브 · CSR 38개 |
| [`bbht_ahb_loader.v`](../../hardware_bram/src/bbht_ahb_loader.v) | AHB 마스터 · 데이터셋 DMA |
| [`bbht_grover_core_adapter.v`](../../hardware_bram/src/bbht_grover_core_adapter.v) | 계약 이름·리셋 차이 흡수 |

## 7.1 wrapper의 제어 로직

```
i_grover_csr (APB slave)  → bbht_grover_mmio  → Main IP 설정·상태
i_grover_dma (AHB master) ← bbht_ahb_loader   → Main IP loader 포트
```

대부분은 배선이며, wrapper가 직접 처리하는 제어는 다음 세 가지입니다.

1. start 수락 조건 ([5장 5.5절](05_하드웨어_아키텍처_개요.md))
2. `checkpoint_auto_enable = burst_enable && auto_shot`
3. manual checkpoint 입력 전부 0 tie-off (production 설정)

두 번째 조건에 따라 `auto_shot = 0`인 수동 모드에서는 체크포인트를 사용하지 않습니다.
수동 모드는 `j`를 펌웨어가 지정하는 검증용 경로라서, 정책 엔진이 끼어들면 무엇을 재는지
알 수 없게 되기 때문입니다.

클럭은 하나(`clk_accel` 100 MHz)만 사용합니다. CDC는 RVX 계층에서 처리하므로 이
모듈에는 추가하지 않습니다([5장 5.3절](05_하드웨어_아키텍처_개요.md)).

## 7.2 mmio의 레지스터 접근 방식

APB 슬레이브를 받아 레지스터 파일로 만듭니다. 주소 맵의 정본은
[`bbht_grover_csr.json`](../../software/contract/bbht_grover_csr.json)이고, 이 파일이
include하는 `bbht_grover_csr.vh`가 이 JSON에서 생성됩니다. RTL에는 오프셋 숫자를 직접
작성하지 않으며, `gen_csr.py --check`의 세 번째 검사가 이를 확인합니다
([12장](12_CSR_레지스터와_실행_모드.md)).

| 성격 | 뜻 |
|---|---|
| `RW` | 설정. 저장되고 값이 출력 와이어로 상시 나갑니다 |
| `W1P` | 명령. 저장 공간이 없고 쓰면 1사이클 펄스만 나갑니다. 읽으면 0. 무엇을 썼는지는 무시합니다: 쓰는 행위 자체가 명령입니다 |
| `RO` | 상태. 저장하지 않고 코어가 내보내는 와이어를 읽기 응답에 실어 보냅니다 |

### `FIFO_DATA`만 예외

읽기 완료 자체가 pop입니다. 부작용이 있는 유일한 읽기라서 별도 POP 레지스터가
없습니다.

값 0도 정상 결과일 수 있습니다(인덱스 0). 따라서 0을
비어 있음으로 해석하면 안 되고, `STATUS`의 `fifo_empty` 비트를 봐야 합니다.

## 7.3 loader의 사전 검사

시스템 SRAM의 signed 16비트 배열을 AHB 마스터로 읽어 Main IP의 generic loader
포트(`data_wr_en` / `data_wr_addr` / `data_wr_data`)로 넘깁니다.

전송은 32비트 AHB SINGLE read, single outstanding입니다. 옛 문서에 남아 있는
`INCR16` 버스트 계획이 아닙니다. 버스트로 올리는 것은 DMA가 실제 병목임이 측정된 뒤에
볼 일이고, 지금은 적재가 Q14 전체에서 246 us 정도인데 탐색 한 번이 그보다 훨씬
깁니다([6장 6.6절](06_데이터_표현과_메모리_맵.md)).

워드 매핑은 리틀엔디안입니다.

```
word[k][15:0]  -> data[2k]
word[k][31:16] -> data[2k+1]
```

`data_count`가 홀수면 마지막 워드의 상위 16비트는 쓰지 않습니다.

### 시작 전 검사 네 가지

하나라도 걸리면 전송을 시작하지 않은 채 오류 비트만 세웁니다.

| 검사 | 조건 | 오류 비트 |
|---|---|---|
| 정렬 | `data_addr[1:0] == 0` | `align_error` |
| 개수 | `1 <= data_count <= N` | `count_error` |
| 범위 | `[data_addr, data_addr + 4*words)`가 SRAM 안 | `range_error` |
| 상태 | Main IP가 busy가 아닐 것 | `busy_error` |

배열이 일부만 적재된 상태에서 오라클을 실행하면 오류 없이 잘못된 인덱스가 반환될 수
있습니다. 결과만 보고 원인을 찾기 어렵기 때문에 전송을 시작하기 전에 설정을 검사합니다.

전송 중 AHB 응답 오류는 `resp_error`, 완료는 `dma_done_sticky`로 나옵니다. 전체 비트
표는 [12장](12_CSR_레지스터와_실행_모드.md).

## 7.4 어댑터

계약 이름 `bbht_grover_core`와 실물 모듈 `bbht_grover_main_ip`, 그리고 리셋 이름
(`rstnn` ↔ `rstn`) 사이를 변환하는 래퍼입니다. K·H·E·M 파라미터의 기본값도 여기에서
정의합니다.

배선만 하므로 논리가 생기지 않습니다: 2026-09-16 구현의 계층 리포트에서 어댑터와 그
안의 Main IP가 같은 LUT 수를 갖습니다.

`bbht_bram_top`은 어댑터를 거치지 않고 Main IP에 직접 연결됩니다
([5장 5.2절](05_하드웨어_아키텍처_개요.md)). 두 경로가 같은 결과를 내는지는 회귀에서
`CORE=stub|real`로 대조합니다([15장](15_검증_체계.md)).

## 7.5 통신 계층 검증

| 묶음 | 대상 | 무엇을 |
|---|---|---|
| T1~T9 | [`tb_bbht_rvx.v`](../../hardware_bram/testbench/tb_bbht_rvx.v) | CSR 읽기·쓰기, DMA 적재, 결과 FIFO, start 거절 조건 |
| D1~D11 | [`tb_driver.cpp`](../../hardware_bram/testbench/tb_driver.cpp) | 실제 드라이버 C 코드와 RTL을 같이 돌려 둘의 해석이 같은지 |
| H1~H15 | [`tb_bbht_bram_top.v`](../../hardware_bram/testbench/tb_bbht_bram_top.v) | 최상단에 APB로 호스트 순서를 흉내 내고 Q14 전체 적재, NORMAL/CKPT 궤적 비교, 열거까지 |

두 통신 계층 구현(보드 정본과 현재 버전)이 같은 테스트벤치에서 T1~T9 · D1~D11을 모두
통과했고, D5의 단일 탐색 사이클이 63,963으로 같았습니다. 그 위에 SoC 전체 시뮬과
보드 실측이 얹혀 있습니다([15장](15_검증_체계.md) · [16장](16_보드_확인과_실측.md)).

포트 배선 자체는 `check_ports.py`가 wrapper 19신호 + core 61신호를 세
갈래(`stub` · `real` · `dram`)로 대조합니다.
