## 6.1 입력 데이터

signed 16비트 2의 보수입니다.

| 실제 값 | 16비트 HEX |
|---:|---|
| 0 | `0000` |
| 1 | `0001` |
| 32767 | `7FFF` |
| -1 | `FFFF` |
| -32768 | `8000` |

골든 벡터 파일은 전역 인덱스 순서로 한 줄에 네 자리 HEX 하나를 씁니다.

`index >= data_count`인 칸은 메모리에 어떤 값이 남아 있어도 오라클과 후보 검증에서
항상 비타겟입니다. 데이터 개수를 16,384보다 작게 줄 수 있고, 그때 남은 자리의 쓰레기
값이 결과에 영향을 주지 않습니다.

---

## 6.2 P32 뱅크/행 매핑

전역 인덱스 `i`를 32레인 × 512행에 이렇게 펼칩니다.

```
bank = i mod 32       =  index[4:0]
row  = i / 32         =  index[13:5]
```

| 인덱스 | bank | row |
|---:|---:|---:|
| 0 | 0 | 0 |
| 31 | 31 | 0 |
| 32 | 0 | 1 |
| 63 | 31 | 1 |
| 16383 | 31 | 511 |

한 행에서 레인과 뱅크는 1:1입니다. packed row 버스에서 레인 `b`는
`row_bus[b*WIDTH +: WIDTH]`이고, 레인 0이 최하위 비트 슬라이스입니다.

이 매핑에 따라 한 행을 읽을 때 32개 원소를 동시에 가져오고, 512개 행을 읽으면 전체
상태를 한 번 순회합니다. 이후 장에서 사용하는 512행 단위도 이 구조에서 나옵니다.

## 6.3 진폭 형식

저장 진폭은 signed 23비트, 소수부 22비트 입니다. 실수값과의 관계는 `raw / 2^22`
입니다. `Q1.22 계열`이라고 부르지만, Q 표기 관례가 갈릴 수 있으므로 "signed 23비트,
fractional 22" 라는 정의를 우선합니다.

| 값 | raw | 23비트 코드 (6자리 HEX) |
|---|---:|---|
| Q14 초기 진폭 `1/128` | 32768 | `008000` |
| `1/64` | 65536 | `010000` |
| 사용하는 최대 | 4194303 | `3FFFFF` |
| 사용하는 최소 | -4194303 | `400001` |
| 제외한 2의 보수 최솟값 | -4194304 | `400000` |

대칭 포화를 위해 `-4194304`는 쓰지 않습니다. 양끝이 대칭이어야 확산의 부호 처리가
한쪽으로 치우치지 않습니다. 포화가 일어나면 `amp_overflow`가 sticky로 섭니다.

Q14 초기값은 정확히 표현됩니다. `1/sqrt(16384) = 1/128`이고 `2^22 / 128 = 32768`이라
나누어떨어집니다. 반올림 오차 없이 시작한다는 뜻입니다.

## 6.4 데이터패스 비트폭

각 값은 연산에 필요한 폭에 맞춰 정의했습니다. 한 항목의 폭이 바뀌면 이를 사용하는 하위
연산과 메모리 형식도 함께 검토해야 합니다.

| 값 | 폭 | signed | 역할 |
|---|---:|---|---|
| 입력 데이터 | 16 | signed | 술어 입력 |
| 저장 진폭 | 23 | signed | 상태벡터 |
| 32레인 부분합 | 28 | signed | 행 진폭 합 |
| 전역 누산기 | 39 | signed | 16,384개 진폭 합 |
| `two_mean` | 25 | signed | 반올림된 `2*mean` |
| 확산 중간값 | 25 | signed | `two_mean - oracle_amp` |
| 진폭 제곱 | 46 | unsigned | `raw^2` |
| 행 가중치 | 51 | unsigned | 제곱 32개 합 |
| 전체 가중치 | 60 | unsigned | 전체 Born가중치 |
| 인덱스 | 14 | unsigned | 0..16383 |
| 데이터 개수 | 15 | unsigned | 1..16384 |
| `j` | 7 | unsigned | 0..127 |

`j`가 7비트인 것이 [8장](08_Main_IP_최상위와_BBHT_제어.md)의 LFSR 7스텝 점프와 직접
연결됩니다.

## 6.5 논리 메모리 구조

| 메모리 | 논리 구성 | raw 용량 | 용도 |
|---|---|---:|---|
| `data_mem` | 32뱅크 × 512 × 16비트 | 32 KiB | 오라클 입력과 후보 재검증 |
| 진폭 · 체크포인트 | 상태 한 벌 = 512행 × 32레인 × 23비트, 물리 슬롯 4벌 | 46 KiB × 4 | 상태벡터와 되돌아갈 지점 |
| 행 가중치 | 512 × 51비트 | 약 3.2 KiB | Born 행 CDF |

E4 구성에는 따로 떨어진 작업용 진폭 메모리가 없습니다. 계산은 슬롯 안에서
제자리(in-place)로 하거나, 한 반복만 다른 슬롯으로 건너 씁니다(bridge). 구간 규약은
[11장](11_체크포인트와_정책_엔진.md).

측정은 진폭 메모리를 읽기 전용으로 쓰므로 측정 직전 상태가 그대로 남습니다. 슬롯은
그 상태를 되돌아갈 지점으로 복사해 두는 것입니다.

### 물리 BRAM 배치

위 표는 논리 비트 수이고, 실제 개수는 구현 리포트로 확인합니다.

| 무엇 | 개수 |
|---|---|
| 진폭 상태 한 벌 | 10 × (512 × 69비트) + 1 × (512 × 46비트) = RAMB36 11개 |
| 물리 슬롯 4벌 | 행 위상 뱅크 4개(각 512 × 736비트)에 담아 RAMB36 44개 |
| 정책 memo | RAMB36 4 |
| found mask | RAMB36 2 |
| 행 가중치 | RAMB36 2 |
| `data_mem` | RAMB18 64 |
| Main IP 합계 | RAMB36 52 + RAMB18 64 = BRAM 84 tile |
| 풀 SoC | BRAM 116 tile |

물리 슬롯은 K 값과 관계없이 4개입니다. 따라서 K4에서 K3으로 바꿔도 BRAM 사용량은
줄지 않았습니다(자원 ablation 83.0 → 83.0 tile). 성능 개선은 저장 공간 감소가 아니라
정책 결정 비용 감소에서 발생했습니다([1장 1.4절](01_프로젝트_개요.md)).

## 6.6 시스템 SRAM과 적재

데이터셋은 CSR로 넣지 않고 시스템 SRAM에 두었다가 가속기가 끌어갑니다.

| 항목 | 값 |
|---|---|
| SRAM 범위 | `0xE0000000` ~ `0xE001FFFF` (128 kB) |
| 패킹 | `word[15:0] = data[2k]`, `word[31:16] = data[2k+1]` |
| 전송 | 32비트 SINGLE, single outstanding |
| 비용 | 워드당 3사이클(주소 1 + 데이터 1 + 쓰기 1) |
| Q14 전체 | 16,384항목 = 8,192워드 → 24,576사이클, 100 MHz에서 약 246 us |

버스트를 쓰지 않습니다. 옛 세대의 16비트 `HSIZE` · `INCR16` 버스트 경로는 폐기됐습니다.

`DATA_COUNT`가 홀수이면 마지막 상위 halfword를 어떻게 할지 loader가 정해야 합니다.
권장은 그 halfword를 쓰기 인에이블로 전달하지 않는 것이고, 전달해도 `addr >= data_count`
라서 Main IP 쪽 loader가 무시합니다.

Main IP loader는 주소 중복을 검출하지 않습니다. 따라서 어댑터는
`0..data_count-1`을 정확히 한 번씩 생성해야 하며, 이 조건은 회귀 테스트에서 확인합니다
([7장](07_통신_계층.md)).
