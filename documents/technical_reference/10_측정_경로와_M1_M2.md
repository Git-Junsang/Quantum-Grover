# 10장. 측정 경로와 M1 · M2

> [← 9장 연산 경로와 E4](09_연산_경로와_E4.md) · [11장 체크포인트와 정책 엔진 →](11_체크포인트와_정책_엔진.md)

---

반복이 끝나면 Born 측정으로 인덱스 하나를 선택합니다. 기존 구조는 512개 행을 두 차례
순회하므로 측정 비용이 반복 연산에 버금갔습니다. 6단계 ablation에서 M1과 M2를 적용한
결과, K3/H3-E4 대비 사이클이 33.7% 감소했습니다.

---

## 10.1 세 단계

| 단계 | 무엇을 |
|:-:|---|
| BUILD | 512행을 훑으며 행마다 32레인 진폭을 제곱해 더하고, 누적 CDF를 만듦 |
| SELECT | 난수와 전체 가중치로 문턱값을 만들고, CDF를 훑어 문턱을 넘는 첫 행을 찾음 |
| REREAD | 그 행을 다시 읽어 레인 하나를 고르고 인덱스를 확정 |

그 뒤에 고전 재검증이 붙습니다. 확정된 인덱스의 데이터 값을 술어로 다시 검사하고,
틀리면 실패한 샷이 됩니다([8장 8.6절](08_Main_IP_최상위와_BBHT_제어.md)).

재검증은 오라클과 같은 판정기(`grover_predicate`)를 씁니다. 둘이 다른 구현을 쓰면
경계 조건에서 어긋날 수 있기 때문입니다.

---

## 10.2 확률을 보존하는 제곱 연산

제곱은 23×23 곱셈을 DSP로 합니다. 32레인을 더할 때 47/48/49/50/51비트로 정확히 필요한
폭만 써서 감산 트리로 줄입니다([6장 6.4절](06_데이터_표현과_메모리_맵.md)).

절단도 반올림도 정규화도 없고 레인 순서도 바뀌지 않습니다. 그래서 확률이 이론값에서
벗어나지 않습니다. Born 규칙을 지키는 것이 이 설계의 전제이므로
([3장 3.4절](03_Grover와_BBHT_알고리즘.md)), 여기서 정밀도를 깎으면 BBHT 통계가
어긋나고 소프트웨어 기준모델과의 500/500 대조가 무너집니다.

타이밍을 위해 지연 전용 경계를 네 곳에 넣었습니다.

1. 메모리 출력 → 레지스터
2. 제곱 → 레지스터
3. 32→16→8 감산 → 레지스터
4. 8→4→2→1 → 행합 레지스터

값을 바꾸지 않고 지연만 늘리는 경계입니다.

## 10.3 M1: 사이클당 두 행 BUILD

E4의 4행 동시 읽기 포트가 이미 있습니다([9장 9.4절](09_연산_경로와_E4.md)). 그러니
제곱기 한 벌을 더 두고 행 가중치 메모리를 2쓰기 포트로 바꾸면 BUILD가 절반이 됩니다.

| | BUILD |
|---|---|
| M0 | 512사이클 |
| M1 | 256사이클 |

`grover_row_weight_mem_m1_2w`가 그 2쓰기 포트 메모리입니다.

이 단계에서 DSP가 64 → 128로 두 배가 됩니다. 제곱기를 한 벌 더 두는 값이고,
이것이 프로젝트 전체에서 DSP를 쓰는 거의 유일한 자리입니다(확산·오라클·INIT 경로에는
곱셈기가 없습니다).

---

## 10.4 M2: 계층형 SELECT

512행을 32행씩 16그룹으로 나눕니다. BUILD 중에 각 그룹의 마지막 행에서 그때까지의
전체 누계를 그대로 그룹 CDF 끝점으로 기록해 둡니다.

추가 제곱도, BUILD 사이클 추가도 없습니다. 이미 만들고 있던 누계를 16번 더 적어 두는
것뿐입니다.

SELECT는 두 단으로 바뀝니다.

```
① 16개 그룹 끝점만 훑어 문턱을 넘는 첫 그룹을 찾음
② 그 그룹 안의 32행만 기존 방식으로 훑음
```

| | SELECT 최악 |
|---|---|
| M1까지 | 512회 비교 |
| M2 | 16 + 32 = 48회 비교 |

M2는 자원 대비 효과가 가장 큰 단계입니다. LUT 183개를 추가해 사이클을 18.94%
줄였습니다.

---

## 10.5 두 스위치

`MEAS_M1_ENABLE` · `MEAS_M2_ENABLE`은 main의 `src/`에만 있는 컴파일 스위치입니다.
둘 다 1(기본)이면 보드 정본과 동작이 같습니다. 6단계 ablation을 한 벌의 소스로
돌리려고 추가한 것이고, 보드에 구운 정본에는 이 스위치가 없습니다.

## 10.6 자원과 이득

| 구성 | LUT | FF | BRAM tile | DSP | 직전 대비 사이클 |
|---|---:|---:|---:|---:|---:|
| K3/H3-E4 | 29,959 | 25,655 | 83.0 | 64 | — |
| K3/H3-E4-M1 | 33,547 | 28,195 | 84.0 | 128 | -18.15% |
| K3/H3-E4-M2 | 33,730 | 28,258 | 84.0 | 128 | -18.94% |

M1은 DSP 사용량을 두 배로 늘리고 LUT 3,588개를 추가해 사이클을 18.15% 줄였습니다.
M2는 LUT 183개를 추가해 다시 18.94% 줄였습니다. 두 단계를 함께 적용하면 K3/H3-E4 대비
33.7% 감소합니다.

근거는 [resource_ablation_5config](../../hardware_bram/results/2026-09-08_resource_ablation_5config/evidence.md)
와 [publication_6stage](../../hardware_bram/results/2026-09-08_publication_6stage/evidence.md)
입니다.

## 10.7 zero-weight 오류

Born 전체 가중치가 0이면 문턱값을 만들 수 없습니다. 진폭이 전부 0이라는 뜻이고,
정상 동작에서는 나오지 않습니다. `STATUS`의 `zero_weight_error`가 서고 탐색이 즉시
끝납니다. 종료 우선순위에서 성공 바로 다음입니다
([8장 8.6절](08_Main_IP_최상위와_BBHT_제어.md)).
