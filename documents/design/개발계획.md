## 배경

주제가 확정됐습니다: **`<`, `>`, `=`, 범위 네 가지 술어를 지원하는 Grover 탐색 에뮬레이터 가속기**를 RVX SoC 안의 커스텀 IP로 만들고, 호스트 PC가 UART로 술어와 찾을 값을 넣으면 결과 인덱스를 돌려받는 형태입니다. BBHT로 정답 개수 $M$을 모르는 상태에서 탐색하고, **검증에 실패한 샷의 진폭 배열을 버리지 않고 재사용해 불필요한 반복 계산을 없앱니다.**

기존 결정은 documents/design/ 에 이미 정리되어 있습니다(발표자료 22장 + [블록도.md](블록도.md) + [반복횟수_결정.md](반복횟수_결정.md)). 이번 조사에서 그 결정 중 몇 개가 실제 환경·실측과 어긋난다는 것이 확인됐고, 아래 §1이 그 차이입니다. 기존 문서는 그대로 두고 **새 설계문서를 따로** 씁니다.

### 발표자료 성능 모델의 구멍 (중요)

발표자료 13p의 "측정은 샷당 한 번뿐이라 전체의 약 7%"는 **$M$을 아는 단일 샷 기준** 수치입니다. BBHT는 $m$이 1부터 1.2배씩 커지므로 초반 샷이 거의 다 실패하고, **평균 24.5샷**입니다(n=15·M=1·몬테카를로 20,000회). 그래서 직렬 CDF 측정(N사이클 = 32패스)이 **전체 시간의 절반**을 먹습니다.

비용 단위 = 1 패스 = `N/P` 사이클. INIT = 1패스, Grover 반복 1회 = 2패스. 샷 통계는 전부 몬테카를로 20,000회 기준입니다.

| n | M | 측정 방식 | naive | 전진전용 캐시 | 평균 샷 |
|:-:|:-:|---|--:|--:|--:|
| **15** | 1 | 직렬 32패스 | 1296 | 1103 (**0.85**) | 24.5 |
| **15** | 1 | **병렬 2패스** | 554 | **362 (0.65)** | 24.5 |
| **15** | 4 | 병렬 2패스 | 294 | 195 (0.66) | 20.9 |
| **15** | 32 | 병렬 2패스 | 117 | 80 (0.68) | 15.5 |
| 12 | 1 | 병렬 2패스 | 215 | 143 (0.67) | 19.1 |
| 16 | 1 | 병렬 2패스 (스트레치 참고) | 774 | 504 (0.65) | 26.5 |

**캐시와 측정 병렬화는 한 쌍입니다.** 측정을 직렬 CDF로 두면 캐시가 아낀 반복이 측정에 묻혀 절감이 **15%**로 떨어지고(1,296 → 1,103패스), 2단 병렬 측정과 함께 쓰면 **35%**입니다(554 → 362패스. 둘 다 n=15·M=1·몬테카를로 20,000회).

## 2. 두 핵심 메커니즘

### 2.1 캐시 = 전진전용 제자리 재개 (결과가 절대 달라지지 않는 이유)

이 설계에서 `amp_mem`에 쓰는 것은 INIT·오라클·확산 **셋뿐**입니다. Born 측정은 진폭을 순차로 읽어 제곱을 누적할 뿐이고(읽기 전용), 검증은 `data_mem`의 한 칸만 봅니다. 즉 **샷이 실패한 뒤에도 진폭 배열에는 `j_prev`회 반복한 상태가 그대로 남아 있습니다.**

```
if (!cache_valid || force_init || j_target < j_cur)   INIT 후 j_target회 전진
else                                                   (j_target − j_cur)회 전진
```

$j$회 반복한 상태는 도달 경로와 무관하게 유일하고, 재개 경로는 **새로 INIT해서 $j$회 돌린 것과 문자 그대로 같은 연산열**입니다. 그래서 비트 단위 동일성이 증명 없이 보장됩니다 — 반올림·포화·드리프트 논의가 통째로 사라집니다. 측정 난수는 샷마다 LFSR에서 새로 뽑으므로 각 샷은 여전히 $\sin^2((2j+1)\theta)$의 독립 시행이고, BBHT 통계도 그대로입니다. 추가 BRAM은 **0개** — `j_cur`(16b)·`cache_valid`(1b) 레지스터 둘뿐입니다.

`j_target < j_cur`이면 되감지 않고 INIT부터 다시 합니다. 되감기(양방향)는 실측상 **오히려 1% 느리고**(`j`가 절반 넘게 줄어들 땐 INIT 후 전진이 더 쌈) 가역성 증명이 필요해서 채택하지 않습니다.

**무효화는 하드웨어가 합니다.** `mode`/`thr_a`/`thr_b`/`n_qubits`/`enum_mode`/`clear_mask`/데이터 재적재 CSR write 시 `cache_valid`를 자동으로 내립니다. 소프트웨어에 맡기면 반드시 새는 곳이 생깁니다.

**기각한 대안**: 스냅샷 버퍼(amp BRAM 2배, n=15에서 +16 BRAM36 — 비싸고 저장한 하나의 $j$로만 복귀 가능), `hit[]` 비트벡터 캐싱(`predicate_unit`이 조합논리이고 `data_mem` 읽기가 `amp_mem` 읽기와 동시라 사이클 절감이 0).

### 2.2 측정 2단 병렬화 (분포가 정확히 같은 이유)

Born 샘플링은 **인덱스 순서가 무관**합니다. CDF를 (addr, bank)가 아니라 (bank, addr) 순서로 잡아도 됩니다.

1. 패스 1: 32개 제곱기로 뱅크별 합 `S_b[0..31]`과 전체 `total`을 구함 (`N/P` 사이클)
2. 32항 prefix-sum으로 난수 `r`이 떨어지는 뱅크 `b*` 선택 (32 사이클)
3. 패스 2: `b*` 뱅크만 직렬 스캔, 잔여 `r`을 넘는 첫 인덱스 (`N/P` 사이클)

결합확률이 `S_b/total × a_i²/S_b = a_i²/total`로 정확히 일치합니다. n=15 기준 32,768 → 2,080 사이클. `rand_r`은 rejection sampling으로 `[0, total)` 균등하게 뽑습니다(곱셈기 불필요). 노름이 반올림 때문에 정확히 1이 아닐 수 있으므로 **끝까지 못 넘으면 마지막 인덱스를 반환하는 안전망**은 유지합니다([블록도.md](블록도.md) 4.7절 요구).

## 3. 자원 예산 (n=15, P=32, arty-50)

BRAM은 `max(N×DW, P × RAMB18)`이 지배합니다. **P=32면 뱅크가 32개라 n을 낮춰도 BRAM 개수가 안 줄어듭니다** — n을 낮추는 건 BRAM 절약이 아니라 시뮬레이션 시간과 골든 벡터 크기를 줄이는 것입니다. 초기 브링업에서 자원까지 아끼려면 P도 같이 낮춰야 합니다.

| 블록 | 구성 | RAMB18 | BRAM36 환산 |
|---|---|--:|--:|
| `amp_mem` | 32뱅크 × 1024 × 18b | 32 | 16 |
| `data_mem` | 32뱅크 × 1024 × 16b | 32 | 16 |
| `mask_mem` | 1024 × 32b | 2 | 1 |
| **IP 합계** | | | **33** |
| RVX SoC (`sram_size` + irom + 주변) | Phase 0에서 실측 | | ~15 (64 kB 기준) |
| **전체** | | | **~48 / 75** (64 kB 기준) |

SoC 몫 ~15는 예제 `lec_ahb` 기본값인 `sram_size` 64 kB 기준 추정치입니다. n=15 데이터 배열만으로 64 KB라 그 크기로는 프로그램과 스택 자리가 없어 [17.5절](../study_references/17_RVX_SoC_통합.md#175-데이터-적재--ahb-마스터)이 128 kB를 요구하고, 그만큼 BRAM이 더 붙으므로 합계는 다시 재야 합니다. 확정 경로는 Phase 0의 `make imp_fpga` utilization 리포트뿐입니다.

DSP: `born_sampler` 제곱기 32개 / 120. **확산·오라클 경로는 0개** — 2×평균은 `n−1`칸 산술 우시프트 한 번, 나머지는 뺄셈입니다.

스테이징: `n=12,P=8` (브링업) → `n=12,P=32` (성능 형태) → **`n=15,P=32` (주력)** → `n=16,P=32` @ arty-100t (스트레치, 보드 없으면 구현 리포트까지).

### Phase 1 — 골든 모델과 수치 스펙 확정 ★가장 중요

DW·Q포맷·반올림·캐시 정책을 실측으로 못 박고, RTL이 맞춰야 할 정답 벡터를 만듭니다.

1. `golden/grover_float.py` — float64 참조. 술어 4종, BBHT 외부 루프, Born 샘플링.
2. `golden/grover_fixed.py` — **RTL과 1:1 대응하는 비트정확 모델**. 인자 `NB, P, DW, f, rounding, sat`. 이후 모든 RTL tb의 정답 출처입니다.
3. `sweep_bitwidth.py` — f=8..24 × n∈{10,12,14,15} × M∈{1,4,64} × 술어 4종 → 성공률 곡선. **기준: M=1에서 성공률 ≥ 99%** (발표자료 S0-5). DW=18 확정 또는 반증.
4. `sweep_qformat.py` — **D1/D2 확정**. {Q1.17, Q2.16} × {half-up, half-even}에서 포화 횟수와 성공률. Q2.16이 소수부 1비트를 잃으므로 **성공률이 떨어지지 않는지 반드시 확인**.

6. `sweep_predicate.py` — 술어 4종 × 데이터 분포 3종(uniform/gaussian/편향)에서 M 분포와 샷 수.

9. **`M=0` 판정 방식 확정** — 고전 스캔 1패스 vs BBHT 상한 도달의 비용을 실측해 결정. [블록도.md](블록도.md) 7절 미결 항목.

**검증 기준** — float 모델이 [반복횟수_결정.md](반복횟수_결정.md) 3절 표(N=16, M=1, j=0..10)와 소수 4자리까지 일치 / 확정 DW에서 고정소수점 모델과 float 모델의 성공률 차이 ≤ 1%p / **Q2.16 + half-even에서 포화 0회** 재현 / `python3 golden/run_all.py` 한 번에 전부 통과하고 표·그래프 생성 / seed 고정으로 재현 가능

**산출물** — `software/golden/*.py`, `software/golden/vectors/*`, `documents/design/비트폭_실측.md`, **`documents/design/가속기_설계_v2.md`(신규 설계문서 초판 — §1의 D1~D9와 §2 메커니즘 확정본)**

### Phase 3 — 데이터패스 코어 (P=1, n≤12), 골든 대비 비트정확

산술이 골든 모델과 비트정확한지 가장 작은 구성에서 증명합니다.

1. `hardware/src/grover_param.vh` — `NB, DW, QF, W, P, ACCW, INIT_AMP`.
2. `grover_predicate.v` — [블록도.md](블록도.md) 4.5·4.6절 그대로. 비교기 IP 없이 `value − thr`의 MSB, `==`는 XOR-NOR, 범위는 두 비교의 AND, `found` 마스크 AND.
3. `grover_lane.v` — `sign_flip`(오라클) + `diffusion_unit`(`two_mean − amp`, 포화). 2배 곱은 4번의 시프트 폭에 이미 들어 있으므로 여기에는 시프트가 없습니다.
4. `grover_two_mean_calc.v` — 확산이 쓰는 값은 평균이 아니라 **2×평균**이므로 누산기를 `n_qubits−1`칸(n=15면 14칸) **한 번에** 밉니다. round-half-to-even이고, `n_qubits` 런타임 가변이므로 배럴 시프터입니다.
   ```verilog
   q        = total >>> (n_qubits-1);       // 산술 시프트 = floor
   rbit     = total[n_qubits-2];            // 버려지는 비트 중 최상위
   sticky   = |total[n_qubits-3:0];         // 그 아래에 1이 하나라도 있나
   two_mean = q + (rbit & (sticky | q[0])); // half-to-even
   ```
   `>>> n` 으로 밀었다가 `<<< 1` 로 되미는 2단 구현은 금지입니다. 떨어져 나간 최하위 비트가 0으로 채워지고 반올림 지점이 두 곳이 되어 골든 모델과 영원히 어긋납니다 ([13.5절](../study_references/13_오라클_확산_측정_데이터패스.md#135-diffusion--2mean--amp가-회로가-되는-순간) · [18.3절](../study_references/18_골든모델_검증.md#183-bit-exact가-성립하기-위한-조건)).
5. `grover_adder_tree.v`(P=1은 통과), `grover_sum_accum.v`. 누산기는 합성 시 상한인 `NB` 로 잡아 `ACCW = DW + NB + 2` = 36비트짜리 컨테이너가 되고, 런타임 큐비트 수 `n` 으로 재면 해설서 [12.3절](../study_references/12_고정소수점과_정밀도.md#123-정수부는-몇-비트인가--재는-대상이-셋이다)의 `ACCW = DW + n + 2` = 35비트(n=15)입니다.
6. `grover_ctrl_fsm.v` — `S_IDLE → S_LOAD → S_INIT → (phase0 → phase1) × j → S_MEAS → S_VERIFY → S_DONE`. 출력 신호명은 블록도 4.3절 그대로.
7. `grover_amp_mem.v` / `grover_data_mem.v` — P뱅크 래퍼. `(* ram_style = "block" *)`로 추론 통제.
8. `grover_data_gen.v` — 시프트와 XOR만 쓰는 xorshift/LFSR로 `data_mem` 채우기. 골든 모델에 같은 생성기 구현(D4).
9. `grover_verify.v` — `predicate_unit` 한 벌 재사용. 오라클과 완전히 같은 식이고 적용 범위만 다릅니다.

**검증 기준**
- `make -C hardware/testbench regress` (iverilog) → n=8,10,12 × 술어 4종 × j=0..R 전부에서 **amp 배열이 `golden/vectors/expect_amp_j*.hex`와 전 워드 일치**, PASS
- `tb_two_mean_calc.v`: 무작위 `total` 10⁶개 + **tie 케이스(`t ≡ 2^(n−2) mod 2^(n−1)`, 즉 버려지는 부분이 정확히 절반) 1000개**에서 파이썬 모델과 일치
- `tb_predicate.v`: 술어 4종 × 경계값(`thr_a`, `thr_a±1`, MIN, MAX) 진리표 일치
- `data_gen` 이 같은 시드에서 골든과 동일 수열 생성

**산출물** — `hardware/src/*.v`, `hardware/testbench/*.v`, `hardware/sim/`

**리스크** — BRAM 동기 읽기 1사이클 지연 때문에 파이프라인 정렬이 어긋나기 쉬움 → tb 1차 기준은 사이클 단위 비교가 아니라 **패스 종료 시점의 배열 전체 비교** / iverilog와 ModelSim의 `$signed`·산술 시프트 해석 차이 → Verilog-2001 범위로 제한 / 포화 로직의 부호 처리(DW+2 → DW)

### Phase 4 — 병렬화 P=32 + 측정·검증

성능 목표(반복 1회 = `2N/P` 사이클)와 Born 샘플링을 완성합니다.

1. 뱅킹: 인덱스 하위 `log₂P` 비트로 뱅크 선택(발표자료 S2-5). `amp_addr` 폭 = `NB−5`.
2. `grover_adder_tree.v` 32입력 5단. 타이밍이 안 나오면 2단 파이프라인 + `sum_accum` 지연 보정.
3. **`grover_born_sampler.v` — §2.2의 2단 구조.** 제곱기 32개(DSP 32), 32항 prefix-sum, rejection sampling, 안전망 포함.
4. `grover_lfsr.v`, `grover_iter_rom.v`(m 수열 30항), `cycle_cnt`·`passes_run` 카운터. 앞의 둘은 Phase 5b의 바깥 샷 FSM이 씁니다.

**검증 기준**
- tb에서 **반복 1회 = 정확히 `2·(N/P)` 사이클** assert (n=12, P=32 → 256 사이클)
- 동일 seed에서 **P=1 결과와 P=32 결과가 비트 동일** → P가 성능 파라미터일 뿐임을 증명
- `tb_born_dist.v`: n=10, 고정 amp 배열로 10⁵ 샘플 → 이론 분포 대비 **χ² p > 0.01**
- 측정 사이클 = `2·N/P + 32 ± α` (직렬 대비 16배 단축 확인)

**산출물** — `grover_born_sampler.v`, `grover_lfsr.v`, `grover_iter_rom.v`, `tb_born_dist.v`

**리스크** — 확률 누산기 폭 결정(`Σ amp² = 2^{2f}`, f=16이면 2^32 → 34~36비트) / "뱅크 순서 CDF가 인덱스 순서 CDF와 분포가 같다"는 논리를 설계문서에 명시(심사 질문 예상) / D7의 문구 정정을 잊지 말 것

### Phase 5 — 재개 캐시와 BBHT 샷 루프 ★본 요구사항

**SW 먼저, HW를 그다음**으로 갑니다. 5a에서 펌웨어가 샷 루프를 돌려 캐시의 정확성부터 못 박고(샷 하나마다 멈춰 세워 골든 모델과 대조할 수 있어 디버깅이 쉽습니다), 5b에서 그 루프를 하드웨어 바깥 FSM으로 옮깁니다. 완성한 뒤에도 두 모드는 **공존**합니다 — 5a는 골든 모델 재생과 $M$을 아는 비교 모드에 계속 쓰고, 5b가 최종 형태입니다([16.4절](../study_references/16_반복제어와_재개캐시.md#164-바깥-fsm--샷-루프와-고전-검증) · [17.7절](../study_references/17_RVX_SoC_통합.md#177-하드웨어와-펌웨어의-경계)). 어느 쪽이든 `j_cur`과 `cache_valid`는 하드웨어가 소유하므로 같은 상태가 두 곳에 생기지 않습니다.

**5a — 펌웨어 구동 모드 (캐시 정확성 확정)**

1. app이 BBHT 수열을 계산해 매 샷 **절대값** `j_target`을 CSR에 씁니다: `m ← 1`, `λ = 6/5`, `j ~ U[0, m)`, 실패 시 `m ← min(1.2m, √N)`. **[반복횟수_결정.md](반복횟수_결정.md)의 정오표 주의 — 09번 논문 의사코드에 `m ← min(λm, √N)` 줄이 빠져 있습니다.** 이 줄을 빼면 m이 1에 고정돼 동작하지 않습니다.
2. CSR을 `j_target`(절대) + `j_cur`(RO) + `cache_valid`(RO) + `force_init`(W)로 전환 (D5).
3. `grover_cache_ctrl.v` — §2.1의 규칙 3줄.
4. **하드웨어 자동 무효화** — `mode`/`thr_a`/`thr_b`/`n_qubits`/`enum_mode`/`clear_mask`/데이터 재적재 write 시 `cache_valid` 클리어.
5. 절감률 실측 — 캐시가 줄이는 것은 벽시계뿐이므로 두 카운터를 갈라 읽습니다. `cycle_cnt` 는 벽시계($\sum|\Delta j|$ 에 대응), `passes_run` 은 알고리즘 지표($\sum j_k$ 에 대응)이고, SW는 naive 가정치를 같은 규칙으로 집계해 대조합니다([17.7절](../study_references/17_RVX_SoC_통합.md#177-하드웨어와-펌웨어의-경계)).

**5b — BBHT 자율 모드 (바깥 샷 FSM)**

6. `grover_shot_fsm.v` — `m` 레지스터 + Phase 4의 `grover_iter_rom.v`(30항)로 `m` 갱신 + `grover_lfsr.v`로 `j_target` 추첨 + 캐시 판정 + `S_VERIFY`까지 전부 하드웨어가 돕니다. 펌웨어가 보는 것은 설정 → `start` → 폴링 → 결과 읽기 네 줄입니다.
7. `ctrl.auto_shot`(§6) 한 비트로 두 경로를 고릅니다. 0이면 펌웨어 구동 모드로 앱이 쓴 `j_target`을 그대로 쓰고, 1이면 BBHT 자율 모드로 LFSR이 매 샷 그 레지스터를 갱신합니다.

**검증 기준**
- `tb_cache_bbht.v`: `golden/vectors/cache_walk.txt`의 j 시퀀스를 재생 → **각 샷 종료 시 amp 배열이 fresh-INIT 골든과 전 워드 일치** (핵심 — "결과가 달라지지 않는다"의 직접 증명)
- `tb_cache_invalidate.v`: `thr_a`를 바꾸면 다음 `start`에서 **반드시 `S_INIT`을 거침**. state 트레이스로 확인, 안 거치면 FAIL
- 캐시 on/off가 **같은 seed에서 동일한 `cand` 시퀀스**를 냄 (사이클 수만 다름)
- 성능: n=12·M=1에서 `cycle_cnt` 총합이 naive 대비 **≥ 30% 감소**(골든 예측치와 ±5% 이내)하고, `passes_run` 총합은 캐시 on/off에서 **동일**
- **5b**: 자율 모드가 같은 seed에서 5a의 펌웨어가 계산한 것과 **동일한 `j_target` 수열**을 만들고, 샷 수와 `cand`가 일치

**산출물** — `grover_cache_ctrl.v`, `grover_shot_fsm.v`, `tb_cache_bbht.v`, `tb_cache_invalidate.v`, `documents/design/캐시_설계.md`

**리스크·미결**
- `n_qubits` 런타임 가변 → `two_mean` 배럴 시프터 비용(누산기 컨테이너 36비트 × 5단 ≈ 200 LUT)
- `j ~ U[0, m)`의 균등성 규약이 5b의 미결 항목입니다. LFSR 값을 마스킹만 하면 `m`이 2의 거듭제곱이 아닐 때 균등하지 않고, BBHT의 "성공확률 ≥ 1/4" 보장이 균등성을 전제합니다. 기각 샘플링 등의 규약을 골든 모델과 똑같이 정해야 합니다
- **심사 대비 논거를 미리 준비할 것.** 발표자료 22p가 "측정 후 재시도 = 진폭 배열 전체를 INIT_AMP로 재기입"이라고 못박아 놨고 캐시는 이와 정면으로 충돌합니다. 방어 논리는 ① 측정 결과 분포와 각 샷의 상태가 모두 비트 단위로 동일하므로 알고리즘 충실도는 훼손되지 않고, ② 발표자료 S0-6에서 용도를 "A. 시뮬레이터 가속"으로 확정했으며, ③ **알고리즘 지표(총 Grover 반복 수)는 여전히 `Σ j_k`로 보고하고 벽시계 시간만 `Σ|Δj|`로 보고**한다는 것입니다. 카운터를 두 개 두는 이유가 이것입니다.
- 되감기(양방향)는 채택하지 않았으므로 `dir` 비트를 넣지 않습니다. 나중에 필요해지면 `sign_flip`을 phase mux 뒤로 옮기고 `flip_en = ~(dir ^ phase)`로 바꾸면 되고, 추가 하드웨어는 XNOR 하나입니다.

### Phase 6 — 데이터 적재(AHB 마스터)와 열거 모드

1. `grover_ahb_master.v` — `lec_simd.v`(521줄, `BURST_LENGTH=16`)를 참고한 AHB 버스트 마스터. app이 SRAM에 올려둔 배열을 `data_mem`으로 DMA. n=15면 64 KB.
2. `user_masterif_ahb_clkin` 심을 플랫폼 XML에 추가하고 user region에서 결선.
3. `grover_mask_mem.v` + `grover_result_fifo.v` — 열거 모드.
4. 열거 규칙: `if (조건(i) && !found[i])`로 마스크를 오라클에 AND. 한 해를 찾을 때마다 `found[cand] ← 1`, 캐시 무효화 후 다음 라운드. `M_max` 상한(예: 256) 초과 시 `TOO_MANY` 반환.

**검증 기준**
- `tb_ahb_load.v`: AHB 마스터가 64 KB를 옮긴 뒤 `data_mem` 내용이 소스와 전 워드 일치
- `make sim_rtl`에서 app이 SRAM에 채운 배열을 IP가 읽어 탐색까지 성공
- 열거 모드가 **발표자료 6p 예시(N=8, 술어 x=12, 정답 {1,3,5})를 그대로 재현** — 라운드마다 M이 3→2→1→0으로 줄고 중복 없이 셋 다 나옴
- `M_max` 초과 시 `TOO_MANY` 플래그

**산출물** — `grover_ahb_master.v`, `grover_mask_mem.v`, `grover_result_fifo.v`, 갱신된 `app/grover_search/src/main.c`

**리스크** — AHB 마스터 FSM이 이 프로젝트에서 가장 RVX 의존적인 부분이라 원격 시뮬 왕복이 잦아짐 / 열거 모드는 라운드마다 마스크가 바뀌어 **캐시 이득이 0**입니다(설계문서에 명시할 것) / SRAM 64 kB로는 n=16(128 KB) 데이터가 안 들어감 → n=16 스트레치 목표에서는 `data_gen` xorshift 경로만 사용

## 6. CSR 맵 (초안)

RVX mmio 생성기 규약상 레지스터 간격은 8바이트이고, write는 `*_write_cmd` 펄스, read는 `*_re` + `*_input` 포트로 나옵니다.

해설서 [17.4절](../study_references/17_RVX_SoC_통합.md#174-csr-맵)에도 CSR 맵 초안이 있고, 명령을 `ctrl` 한 워드에 비트로 모을지 `clear_mask`·`load_start`·`start` 각각의 W1P 레지스터로 나눌지, 소스를 `data_src` 하나로 둘지 `data_addr`+`data_words`로 나눌지가 서로 다릅니다. 두 초안 중 하나를 **Phase 2의 `documents/design/csr_맵.md`에서 확정**하며, 통합할 때 아래 표에만 있는 `force_init`(§2.1 판정식의 두 번째 조건)·`status.sat_sticky`(포화 관측)·`ctrl.auto_shot`(Phase 5b의 모드 선택)은 반드시 살립니다.

| offset | 이름 | 방향 | 폭 | 비고 |
|--:|---|:-:|:-:|---|
| 0x00 | `ctrl` | W | 32 | bit0 `start`, bit1 `force_init`, bit2 `clear_mask`, bit3 `load_data`, bit4 `auto_shot`(0=펌웨어 구동, 1=BBHT 자율) |
| 0x08 | `mode` | W | 2 | 술어 (블록도 4.6). **write 시 `cache_valid` 자동 클리어** |
| 0x10 | `thr_a` | W | 16 | 〃 |
| 0x18 | `thr_b` | W | 16 | 〃 |
| 0x20 | `n_qubits` | W | 5 | 〃 |
| 0x28 | `j_target` | W | 16 | **절대** 반복 횟수 |
| 0x30 | `enum_mode` | W | 1 | 〃 |
| 0x38 | `data_src` | W | 32 | AHB DMA 소스 주소 (또는 xorshift 시드) |
| 0x40 | `status` | R | 32 | bit0 `busy`, bit1 `done`, bit2 `verify_hit`, bit3 `cache_valid`, bit4 `sat_sticky`, bit5 `too_many` |
| 0x48 | `cand` | R | 16 | 측정 인덱스 |
| 0x50 | `j_cur` | R | 16 | 현재 캐시된 반복 수 |
| 0x58 | `cycle_cnt` | R | 32 | 벽시계 — 실제 소비 사이클(Δj 누적) |
| 0x60 | `passes_run` | R | 32 | 누적 패스 수 — 알고리즘 지표($\sum j_k$ 에 대응) |

## 8. 전체 검증 흐름

```bash
# 1. 골든 모델 — 모든 정답의 출처
cd software/golden && python3 run_all.py

# 2. RTL 회귀 (로컬, 빠름)
make -C hardware/testbench regress          # iverilog + vvp, 골든 벡터 대조

# 3. SoC 통합 시뮬 (원격 ModelSim)
source ~/rvx_lec_hw/rvx_setup.sh
cd $RVX_MINI_HOME/platform/grover_soc && make sim_rtl

# 4. 구현 (원격 Vivado)
make imp_fpga TARGET_IMP_CLASS=arty-50

# 5. 벤치마크
python3 software/bench/run_all.py

# 6. 보드 입수 후
python3 software/host/grover_cli.py --mode 2 --thr 42
```

**전체 성공 기준** — n=15 · P=32가 arty-50에 100 MHz로 들어가고, 술어 4종이 전부 동작하며, 캐시 on/off가 **동일한 결과에 30% 이상 짧은 사이클**을 내고, 그 모든 중간 상태가 골든 모델과 비트 단위로 일치할 것.
