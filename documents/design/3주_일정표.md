## 0. 3주에 들어가는 것과 안 들어가는 것

**들어갑니다** — 개발계획의 Phase 0(툴체인) · Phase 1(골든 모델) · Phase 2(SoC 껍데기) · Phase 3(P=1 코어) · Phase 4(P=32·측정) · Phase 5(캐시·샷 FSM).

**안 들어갑니다** — Phase 6(AHB DMA 완성·열거 end-to-end)은 3주차에 **착수만** 하고, Phase 7(구현 스테이징·타이밍 클로징·벤치마크·평가문서)은 통째로 4주차 이후입니다. 3주는 **"골든과 비트 단위로 맞는 P=32 코어 + 검증된 재개 캐시"** 까지가 정직한 목표입니다.

무리하게 밀어 넣지 않는 이유는 하나입니다. Phase 7의 타이밍 클로징에서 `adder_tree` 에 파이프라인을 추가하게 되면 **Phase 3~5 테스트벤치를 전부 재실행**해야 하므로, 그 전에 회귀가 튼튼히 서 있어야 합니다.

| 마일스톤 | 날짜 | 합격 기준 |
|:-:|---|---|
| **M1** 계약 + 골든 | 08/21 (금) | 빈 모듈 21개 iverilog 통과 · 골든 4갈래 각자 기준 통과 · 원격 왕복 확인 |
| **M2** P=1 코어 (통합 1) | 08/28 (금) | n=8,10,12 × 술어 4종 × j=0..R 에서 `amp` 전 워드 골든 일치 |

**사양** — `documents/`·`CLAUDE.md`·`.gitignore` 를 추적에 넣고 `origin/main` 에 푸시합니다. 현재 추적 파일이 `README.md` 하나뿐이라 이대로는 셋이 clone해도 아무것도 없습니다. `.gitignore` 에 `*.vcd` · `*.out` · `*.vvp` · `__pycache__/` · `software/soc/**/output/` 을 넣습니다. 골든 벡터(`software/golden/vectors/`)는 **커밋합니다** — 회귀의 정답이라 저장소 밖에 두면 재현이 깨집니다(크기가 n=12 기준 수 MB를 넘으면 그때 재검토).

## 3. B — 오라클 · 술어

### B-1 술어 경계 규약 (08/17)

**사양** — [인터페이스_계약.md §5](인터페이스_계약.md). 4종 전부 강부등호, `thr_a`/`thr_b` 16비트 signed, `RANGE` 에서 `thr_a >= thr_b` 는 정상적인 $M=0$.

### B-2 `golden/predicate.py` (08/18 ~ 08/19)

**사양** — 스칼라 `predicate()` 와 벡터 `predicate_vec()` 둘 다. 경계값 목록: `thr_a`, `thr_a±1`, `thr_b`, `thr_b±1`, `-32768`, `-32767`, `0`, `32766`, `32767`, 그리고 **부호가 교차하는 조합**(`value<0<thr_a` 등).

**합격** — 경계값 진리표 전수 통과. 이 진리표가 B-4 테스트벤치의 정답이 됩니다.

### B-3 `sweep_predicate.py` (08/20)

**사양** — 술어 4종 × 데이터 분포 3종(uniform / gaussian / 한쪽으로 치우친 분포) → 각 조합의 $M$ 분포와 필요 샷 수. n∈{10,12,15}.

**합격** — 4×3 표. D의 `sweep_cache.py` 가 이 $M$ 값을 받아 씁니다.

### B-4 `grover_predicate.v` + `tb_predicate.v` (08/24 ~ 08/25)

**사양** — [인터페이스_계약.md §4.1](인터페이스_계약.md). **비교기 IP 금지.** 17비트 부호확장 감산기 1개를 `LT`·`GT` 가 피연산자 교환으로 공유하고, `RANGE` 가 두 번째 감산기를 씁니다. `EQ` 는 `~|(value ^ thr_a)`. `found` 를 AND. 지연 목표 3 LUT 단.

**합격** — 무작위 10⁵개 + 경계값 전수에서 `predicate.py` 와 일치.
**주의** — 부호확장 17비트를 빠뜨리면 `value=-32768, thr_a=1` 에서 조용히 틀립니다. tb에 이 케이스를 명시적으로 넣으십시오.

### B-5 `grover_verify.v` + tb (08/27 ~ 08/28)

**사양** — `grover_predicate` 를 **한 벌 더 인스턴스화**해 후보 1칸에만 적용. 2사이클(주소 제시 → 판정), 핸드셰이크는 §2 규약. `data_mem` 포트 B의 `one_addr`/`one_rdata` 와 `mask_mem` 의 `one_bit` 를 씁니다.

**합격** — 오라클이 `hit=1` 로 표시한 인덱스는 검증도 반드시 통과(무작위 1,000케이스).

### B-6 `grover_mask_mem.v` (08/31 ~ 09/01)

**사양** — 1024 × 32b(BRAM36 1개). 병렬 읽기 `rdata[31:0]`, 검증용 `one_bit`, `set`/`set_idx` 로 한 비트 세우기, `mclr_start` 로 전체 클리어. **클리어는 1024사이클 스윕**이라 즉시가 아니고, `mclr_busy`/`mclr_done` 을 냅니다.

**합격** — set → read → clear → read 왕복 tb 통과.

### B-7 열거 라운드 (09/02 ~ 09/03)

**사양** — `hit = predicate(value) & ~found[i]`. 해 하나를 찾을 때마다 `found[cand] ← 1`, 캐시 무효화 후 다음 라운드. `M_max` 초과 시 `too_many`.

**합격** — 발표자료 6p 예시(N=8, `EQ` 12, 정답 {1,3,5})에서 라운드마다 $M$ 이 3→2→1→0 으로 줄고 **중복 없이** 셋 다 나옴.

## 4. C — 데이터패스 · 수치

### C-1 `grover_param.vh` + 누산 트리 순서 (08/17)

**사양** — [인터페이스_계약.md §1](인터페이스_계약.md) 전문. 트리 짝짓기는 1단 `(0,1)(2,3)…(30,31)`, 이하 같은 규칙으로 5단. **이 순서를 문서에 적고 골든이 그대로 따릅니다.**

### C-2 `grover_float.py` (08/18)

**합격** — [반복횟수_결정.md](반복횟수_결정.md) 3절 표(N=16, M=1, j=0..10)와 **소수 4자리까지 일치**. 이게 안 맞으면 그 아래 전부가 무의미합니다.

### C-3 `grover_fixed.py` (08/18 ~ 08/19)

**사양** — RTL과 1:1 대응. `init_amp`(§1.3 홀짝 분기) · `two_mean`(§4.5 half-to-even) · `tree_sum`(C-1 순서) · `iterate` · `measure`(2단, 안전망). 대칭 포화 `[-131071, +131071]`.

**합격** — 확정 DW에서 float 모델과 성공률 차 ≤ 1%p, seed 고정으로 재현.

### C-4 `sweep_bitwidth.py` · `sweep_qformat.py` (08/20 ~ 08/21)

**사양** — 비트폭: f=8..24 × n∈{10,12,14,15} × M∈{1,4,64} × 술어 4종. Q포맷: {Q1.17, Q2.16} × {half-up, half-even}에서 포화 횟수와 성공률.

**합격** — M=1에서 성공률 ≥ 99% (DW=18 확정 또는 반증) · **Q2.16 + half-even에서 포화 0회** 재현. Q2.16이 소수부 1비트를 잃으므로 **성공률이 떨어지지 않는지 반드시 확인**하십시오.

**경보 조건** — DW를 19~20으로 올려야 하면 BRAM 예산이 깨집니다. 그 판단이 서는 즉시 전원에게 알리고, 대안은 P를 16으로 낮추는 것입니다.

### C-5 `grover_two_mean_calc.v` + tb (08/24 ~ 08/25)

**사양** — [인터페이스_계약.md §4.5](인터페이스_계약.md). `n_qubits` 런타임 가변이므로 배럴 시프터(약 200 LUT). **`>>> n` 후 `<<< 1` 2단 구현 금지.**

**합격** — 무작위 `total` 10⁶개 + **tie 케이스 1,000개**(버려지는 부분이 정확히 절반인 값)에서 파이썬 모델과 일치.

### C-6 레인·트리·누산기·메모리 래퍼 (08/26)

**사양** — `grover_lane`(§4.2, 조합) · `grover_adder_tree`(P=1은 통과) · `grover_sum_accum` · `grover_amp_mem`/`grover_data_mem`(§4.11). 메모리는 `(* ram_style = "block" *)` 으로 추론을 통제합니다.

### C-7 `grover_ctrl_fsm.v` (08/27 ~ 08/28)

**사양** — [인터페이스_계약.md §4.6](인터페이스_계약.md). `S_IDLE → S_INIT → (S_PASS1 → S_MEAN → S_PASS2) × Δj → S_IDLE`. **`PIPE_LAT = 2` 정렬**이 이 태스크의 난점입니다. `pass_tick` 을 내서 D의 `passes_run` 이 받게 합니다.

**합격** — 통합 1(M2). 1차 기준은 사이클 단위 비교가 아니라 **패스 종료 시점의 배열 전체 비교**입니다.
**되적을 것** — 확정된 `ITER_OVH` 값을 [인터페이스_계약.md §6.3](인터페이스_계약.md)에 반영.

### C-8 P=32 뱅킹 + 32입력 트리 (08/31 ~ 09/01)

**사양** — 인덱스 하위 5비트가 뱅크, 상위 10비트가 뱅크 내 주소. 32입력 5단 트리, 부분합 23비트. 타이밍이 안 나오면 2단 파이프라인 + `sum_accum` 지연 보정(그러면 M2 tb 재실행).

**합격** — 같은 seed에서 **P=1 결과와 P=32 결과가 비트 동일**.

### C-9 `grover_born_sampler.v` (09/02 ~ 09/04)

**사양** — [인터페이스_계약.md §4.7](인터페이스_계약.md). 제곱기 32개(DSP 32), 뱅크 누산기 46비트 × 32, `total` 51비트, prefix-sum 32사이클, 기각 샘플링으로 `[0,total)` 균등 추출, **안전망 2줄**(prefix-sum이 못 넘으면 `b*=31`, 스캔이 끝에 닿으면 마지막 인덱스).

**합격** — `tb_born_dist.v`: n=10, 고정 amp 배열로 10⁵ 샘플 → 이론 분포 대비 **χ² p > 0.01**. 측정 사이클 = `2·(DEPTH+2) + 32 ± α`.

**주의** — 36비트 제곱을 **자르지 마십시오.** 잘린 하위 비트가 곧 확률 왜곡이고, 값이 작은 칸일수록 상대오차가 커져 분포가 체계적으로 기웁니다.

## 5. D — 캐시 · 반복 제어

### D-1 난수 소비 규약 (08/17) ★가장 먼저

**사양** — [인터페이스_계약.md §9](인터페이스_계약.md)의 빈칸 여섯을 채웁니다. LFSR 다항식과 폭 · 시드 출처와 리셋값 · 샷당 추출 횟수와 **순서** · `j ~ U[0,m)` 의 균등화(마스킹은 균등하지 않으므로 기각 샘플링 등) · 2단 측정의 잔차 재사용 여부 · **기각 시 소비하는 난수 개수**.

마지막 항목을 빠뜨리기 쉽습니다. 골든이 RTL과 **똑같은 개수**를 소비해야 수열이 어긋나지 않습니다.

**합격** — C가 `born_sampler` 를, A가 `data_gen` 을 이 규약 위에서 설계할 수 있음.

### D-2 `golden/bbht.py` (08/18 ~ 08/19)

**사양** — $m \leftarrow 1$, $\lambda = 6/5$, $j \sim U[0,m)$, 실패 시 $m \leftarrow \min(1.2m, \sqrt N)$. **[반복횟수_결정.md](반복횟수_결정.md)의 정오표 주의** — 09번 논문 의사코드에 `m ← min(λm, √N)` 줄이 빠져 있고, 이 줄을 빼면 $m$ 이 1에 고정돼 동작하지 않습니다.

**합격** — **평균 24.5샷** (n=15 · M=1 · 몬테카를로 20,000회) 재현. n=12는 19.1샷, M=4는 20.9샷.

### D-3 `sweep_cache.py` (08/20 ~ 08/21)

**사양** — naive / 전진전용 × 측정비용 {2패스, 32패스} 를 몬테카를로 20,000회. 비용 단위는 1패스 = `N/P` 사이클, INIT = 1패스, 반복 1회 = 2패스.

**합격** — n=15·M=1에서 554패스 → 362패스(**35%**), 직렬 측정이면 1,296 → 1,103(15%). M=4는 34%, M=32는 32%, M=256은 29%.
**산출물** — `cache_walk.txt`(j 시퀀스 재생용). 이게 D-8의 입력입니다.

### D-4 `grover_lfsr.v` + `grover_iter_rom.v` (08/24 ~ 08/25)

**사양** — LFSR은 D-1 규약대로. `iter_rom` 은 $m$ 수열 **30항**(n=15, $\sqrt N = 181.02$ 에서 클램프. n=12면 24항). $\lambda$ 를 실시간 곱하지 않고 ROM으로 굽는 이유는 1.2배가 시프트로 안 떨어지고 클램프도 2의 거듭제곱이 아니기 때문입니다.

**합격** — 같은 시드에서 골든 `lfsr32()` 와 **비트 동일 수열**, `m_rom()` 과 전 항 일치.

### D-5 `grover_cache_ctrl.v` + 단독 tb (08/26 ~ 08/27)

**사양** — [인터페이스_계약.md §4.9](인터페이스_계약.md)의 3줄. 자원은 `j_cur`(16b)·`cache_valid`(1b) 레지스터와 비교기·감산기 하나씩. **BRAM 0개.**

**합격** — 단독 tb에서 규칙 전수 확인: 무효 상태 / `force_init` / `j_req < j_cur` / `j_req >= j_cur` / `cfg_we` 로 무효화. 데이터패스 없이도 전부 검증됩니다 — **C를 기다리지 마십시오.**

### D-6 카운터 (08/28)

**사양** — `cycle_cnt` 는 벽시계($\sum|\Delta j|$ 에 대응), `passes_run` 은 알고리즘 지표($\sum j_k$ 에 대응). **둘 다 `start` 펄스로 클리어되고 `done` 까지 셉니다.** `passes_run` 은 C의 `pass_tick` 을 셉니다.

**합격** — 캐시 on/off에서 `cycle_cnt` 는 다르고 `passes_run` 은 **동일**.

### D-7 `grover_shot_fsm.v` (08/31 ~ 09/01)

**사양** — [인터페이스_계약.md §4.10](인터페이스_계약.md). `m` 레지스터 + `iter_rom` 으로 갱신 + LFSR로 `j_req` 추첨 + `cache_ctrl` 판정 + 측정·검증까지. `j_req = auto_shot ? lfsr_draw : cfg_j_target` 먹스. `shot_cap` 에 닿으면 `done` + `verify_hit=0`.

**합격** — 자율 모드가 같은 seed에서 펌웨어 구동 모드와 **동일한 `j_target` 수열**을 만들고 샷 수·`cand` 가 일치.

### D-8 `tb_cache_bbht.v` · `tb_cache_invalidate.v` (09/02 ~ 09/04)

**사양·합격 기준 넷** — 이 프로젝트 핵심 주장의 직접 증명입니다.

1. `cache_walk.txt` 의 j 시퀀스를 재생 → **각 샷 종료 시 `amp` 배열이 fresh-INIT 골든과 전 워드 일치**
2. `thr_a` 를 바꾸면 다음 `start` 에서 **반드시 `S_INIT` 을 거침**. state 트레이스로 확인, 안 거치면 FAIL
3. **측정 구간에서 `amp_we` 가 한 번도 서지 않음** — 재개 캐시가 성립하는 물리적 근거
4. 캐시 on/off가 같은 seed에서 **동일한 `cand` 수열**을 내고 사이클만 다름. n=12·M=1에서 `cycle_cnt` 총합이 naive 대비 **≥ 30% 감소**(골든 예측치와 ±5% 이내)

## 6. 늦어질 때 무엇을 자르는가

일정이 밀리면 **품질이 아니라 범위를 자릅니다.** 자르는 순서를 미리 정해 둡니다.

| 순위 | 자르는 것 | 잃는 것 | 지키는 것 |
|:-:|---|---|---|
| 1 | A-9 AHB 마스터 | 실사용 데이터 적재 | `data_gen` 으로 벤치마크는 전부 가능 |
| 2 | B-7 열거 라운드 | 열거 모드 시연 | 해 하나 반환은 온전 |
| 3 | C-9 `born_sampler` 를 **직렬 CDF**로 임시 구현 | 측정이 32,768사이클로 느려지고 캐시 절감이 15%로 떨어짐 | 분포는 동일 — 정확성은 안 잃음 |
| 4 | D-7 자율 모드 (5b) | 샷마다 CSR 왕복 | **펌웨어 구동 모드(5a)만으로 캐시 정확성 증명은 완결됩니다** |

**절대 자르지 않는 것** — C-3 `grover_fixed.py`, C-5 `two_mean_calc` tie 테스트, D-8의 네 기준. 이 셋이 무너지면 "골든과 비트 단위로 같다"는 주장 자체가 사라집니다.

## 7. 주간 동기 형식

매주 금요일 마일스톤 점검에서 각자 세 줄만 말합니다.

```
닫은 것 :
막힌 것 :
남에게 필요한 것 :
```

**세 번째 줄이 비어 있으면 병렬 작업이 아니라 각자 다른 프로젝트를 하고 있는 것입니다.** 계약(§인터페이스_계약)에 변경이 생겼다면 이 자리에서 반드시 공지하고, 공지 없이 바뀐 계약은 되돌립니다.
