## 1. 파라미터 — `hardware/src/grover_param.vh` (소유자 C)

```verilog
// ── 합성 시 고르는 것 (보드·스테이징에 따라 바뀜) ────────────────────────
`define GP_NB     15          // 인덱스 폭 = 지원하는 최대 큐비트 수
`define GP_DW     18          // 진폭 폭 (Q2.16)
`define GP_QF     16          // 소수부 비트 수
`define GP_W      16          // 데이터 워드 폭 (signed)
`define GP_P      32          // 병렬 레인 수

// ── 유도값 — 손으로 고치지 말 것 ────────────────────────────────────────
`define GP_LOGP   5                        // log2(P)
`define GP_AW     (`GP_NB - `GP_LOGP)      // 10   뱅크 내 주소 폭
`define GP_DEPTH  (1 << `GP_AW)            // 1024 뱅크 깊이
`define GP_N      (1 << `GP_NB)            // 32768
`define GP_PSW    (`GP_DW + `GP_LOGP)      // 23   adder_tree 부분합
`define GP_ACCW   (`GP_DW + `GP_NB + 2)    // 35   진폭 합 누산기
`define GP_TMW    (`GP_DW + 2)             // 20   two_mean · 확산 중간값
`define GP_SQW    (2 * `GP_DW)             // 36   진폭 제곱 (Q4.32)
`define GP_MACCW  (`GP_SQW + `GP_AW)       // 46   뱅크별 제곱합
`define GP_TOTW   (`GP_MACCW + `GP_LOGP)   // 51   전체 제곱합 total

// ── 상수 ────────────────────────────────────────────────────────────────
`define GP_ONE_Q216        18'sd65536      // 1.0
`define GP_INV_SQRT2_Q216  18'sd46341      // 1/√2  = round(0.70710678 × 2^16)
`define GP_AMP_MAX         18'sd131071     // +2.0 직전
`define GP_AMP_MIN        -18'sd131071     // 대칭 포화 (§1.2)
```

### 1.1 폭이 왜 그 값인가

| 이름      | 값 | 근거                                                                                                    |
| --------- | -: | ------------------------------------------------------------------------------------------------------- |
| `DW`    | 18 | Q2.16. 확산 중간값의 상한이 1을 넘어 정수부 2비트가 필요하고, BRAM36의 2048×18 구성에 딱 맞음          |
| `AW`    | 10 | 인덱스 하위 5비트가 뱅크, 상위 10비트가 뱅크 내 주소                                                    |
| `PSW`   | 23 | 32입력 5단 트리는 단마다 1비트씩 늘어`DW+5`                                                           |
| `ACCW`  | 35 | 진폭 크기 ≤ 2^17, N = 2^15 → 합 < 2^32. 부호 1 + 여유 2                                               |
| `TMW`   | 20 | `2·mean` 이론 상한 4.0, `2·mean − amp` 는 6.0까지 → 정수부 3 + 부호 1 + 소수부 16               |
| `SQW`   | 36 | 18비트 제곱은 정확히 36비트.**자르면 안 됩니다** — 작은 칸일수록 상대오차가 커져 분포가 기웁니다 |
| `MACCW` | 46 | 뱅크당 1024항을 더하므로`SQW + 10`                                                                    |
| `TOTW`  | 51 | 32뱅크 합이라`MACCW + 5`                                                                              |

`ACCW` 와 `TOTW` 는 **서로 다른 누산기**입니다. 하나는 진폭의 합, 다른 하나는 진폭 제곱의 합이라 자릿수 계산이 처음부터 다릅니다.

### 1.2 포화는 대칭입니다

`AMP_MIN` 을 `-131072`(컨테이너 최솟값)가 아니라 **`-131071`** 로 둡니다. 2의 보수에서 `-131072` 는 부호 반전이 불가능해(`+131072` 가 18비트에 안 담김) 오라클이 그 칸에서 조용히 항등이 되기 때문입니다. 대칭 포화를 쓰면 부호 반전이 언제나 정확합니다. 정상 동작에서 이 경로는 발현되지 않지만, 발현되지 않는 것과 방어하지 않아도 되는 것은 다릅니다.

### 1.3 초기 진폭은 상수가 아니라 함수입니다

`n_qubits` 가 런타임 가변이므로 `INIT_AMP` 를 헤더 상수로 굳히지 않습니다.

```verilog
wire [4:0] sh   = n_qubits[0] ? ((n_qubits - 5'd1) >> 1) : (n_qubits >> 1);
wire signed [`GP_DW-1:0] init_amp =
     n_qubits[0] ? (`GP_INV_SQRT2_Q216 >>> sh)      // 홀수 n
                 : (`GP_ONE_Q216       >>> sh);     // 짝수 n
```

|            n | 계산       |     초기 진폭 | 오차     |
| -----------: | ---------- | ------------: | -------- |
|            8 | 65536 ≫ 4 |          4096 | 0 (정확) |
|           10 | 65536 ≫ 5 |          2048 | 0        |
|           12 | 65536 ≫ 6 |          1024 | 0        |
|           14 | 65536 ≫ 7 |           512 | 0        |
| **15** | 46341 ≫ 7 | **362** | 0.011%   |

홀수 $n$ 만 $1/\sqrt2$ 를 반올림하는 대가를 치릅니다. 이 오차 때문에 노름이 정확히 1이 아니고, 그래서 Born 샘플러에 안전망이 필요합니다(§4.7).

## 2. 공통 핸드셰이크 규약

**모든 하위 블록이 같은 4신호 규약을 씁니다.** 예외를 두지 않습니다.

| 신호          |     방향     | 의미                                                                   |
| ------------- | :----------: | ---------------------------------------------------------------------- |
| `<x>_start` | 상위 → 하위 | **1사이클 펄스.** `<x>_busy` 가 1일 때 들어오면 **무시** |
| `<x>_busy`  | 하위 → 상위 | `start` 다음 사이클에 1, `done` 과 **같은 사이클**에 0       |
| `<x>_done`  | 하위 → 상위 | **1사이클 펄스.** 완료                                           |
| 결과 포트     | 하위 → 상위 | `done` 펄스와 같은 사이클부터 **다음 `start` 까지 유효**     |

적용 대상: `iter_*`(반복), `meas_*`(측정), `vfy_*`(검증), `load_*`(적재), `mclr_*`(마스크 클리어).

**금지**: 레벨 신호로 시작 걸기, `done` 을 유지형으로 두기, `busy` 와 `done` 이 겹치는 사이클 만들기. 하나만 어긋나도 통합에서 잡기 어려운 경쟁이 생깁니다.

리셋은 **동기 액티브 로우 `rstn`** 하나입니다. 비동기 리셋을 쓰지 않습니다.

## 4. 모듈별 포트 — 데이터 흐름 순

폭 표기: `[X-1:0]` 은 파라미터, 괄호 안은 `NB=15, DW=18, W=16, P=32` 일 때의 실제 비트 수입니다.

### 4.1 `grover_predicate` (B) — 조합논리, 레지스터 없음

| 방향 | 신호                 |      폭      | 비고                          |
| :--: | -------------------- | :-----------: | ----------------------------- |
|  in  | `mode`             |       2       | §5 인코딩                    |
|  in  | `value`            | signed W (16) | `data_mem` 한 칸            |
|  in  | `thr_a`, `thr_b` | signed W (16) | 임계값                        |
|  in  | `found`            |       1       | 1 = 이미 찾은 칸              |
| out | `hit`              |       1       | `predicate(value) & ~found` |

**구현 제약**: 비교기 IP 금지. `LT` 는 `{value[15],value} - {thr_a[15],thr_a}` 의 **17비트 결과 MSB**, `GT` 는 같은 감산기의 피연산자 교환, `EQ` 는 `~|(value ^ thr_a)`, `RANGE` 는 두 감산 MSB의 AND. 부호확장 17비트를 빠뜨리면 `value=-32768, thr=1` 에서 조용히 틀립니다.

**지연 목표**: 3 LUT 단 이내. 이 경로가 1패스의 임계 경로에 그대로 들어갑니다.

**인스턴스 수**: 레인당 1개 = **32개**. `RANGE` 때문에 레인당 17비트 감산기 2개, 총 64개.

### 4.2 `grover_lane` (C) — 조합논리, 레인 하나

| 방향 | 신호         |       폭       | 비고                                |
| :--: | ------------ | :-------------: | ----------------------------------- |
|  in  | `phase`    |        1        | 0 = 1패스, 1 = 2패스                |
|  in  | `hit`      |        1        | B의 출력                            |
|  in  | `amp_in`   | signed DW (18) | `amp_mem` 읽기                    |
|  in  | `two_mean` | signed TMW (20) | 2패스에서만                         |
| out | `amp_out`  | signed DW (18) | `amp_mem` 되쓰기                  |
| out | `amp_tree` | signed DW (18) | 1패스에서 트리로 (= 부호 반전 결과) |
| out | `sat`      |        1        | 포화 발생 (OR로 모아`sat_sticky`) |

1패스: `amp_out = (amp_in ^ {DW{hit}}) + hit` (조건부 2의 보수). 2패스: `amp_out = sat(two_mean - amp_in)`, TMW로 계산 후 DW로 대칭 포화.

### 4.3 `grover_adder_tree` (C) — 조합논리

| 방향 | 신호        |                   폭                   |
| :--: | ----------- | :------------------------------------: |
|  in  | `din`     | P·DW (576) — 레인 0이 최하위 비트 쪽 |
| out | `partial` |            signed PSW (23)            |

**짝짓기 순서를 고정합니다**: 1단 `(0,1)(2,3)…(30,31)`, 2단 `(01,23)(45,67)…`, 5단까지 같은 규칙. 골든 모델이 **정확히 같은 순서로** 더해야 하며(계약 항목 6), 그러지 않으면 float 참조와 마지막 비트가 어긋납니다.

### 4.4 `grover_sum_accum` (C)

| 방향 | 신호              |        폭        |
| :--: | ----------------- | :--------------: |
|  in  | `clear`, `en` |      1 / 1      |
|  in  | `partial`       | signed PSW (23) |
| out | `total`         | signed ACCW (35) |

### 4.5 `grover_two_mean_calc` (C) — 조합논리 배럴 시프터

| 방향 | 신호         |        폭        |
| :--: | ------------ | :--------------: |
|  in  | `total`    | signed ACCW (35) |
|  in  | `n_qubits` |        5        |
| out | `two_mean` | signed TMW (20) |

```verilog
localparam K = n_qubits - 1;                 // n=15 → 14
wire signed [ACCW-1:0] q  = $signed(total) >>> K;
wire rbit   = total[K-1];
wire sticky = |total[K-2:0];
wire signed [ACCW-1:0] tm = q + (rbit & (sticky | q[0]));   // half-to-even
```

**`>>> n` 후 `<<< 1` 로 되미는 2단 구현은 금지입니다.** 떨어져 나간 최하위 비트가 0으로 채워지고 반올림 지점이 두 곳으로 갈라져 골든 모델과 영원히 어긋납니다. **한 반복에서 소수부가 깎이는 곳은 여기 한 순간뿐**이고, round-half-to-even이 적용되는 자리도 오직 여기입니다.

**면적 예상**: 35비트 × 5단 배럴 시프터 ≈ 200 LUT.

### 4.6 `grover_ctrl_fsm` (C) — 안쪽 반복 FSM

| 방향 | 신호                         |   폭   | 비고                                    |
| :--: | ---------------------------- | :-----: | --------------------------------------- |
|  in  | `iter_start`               |    1    | 펄스                                    |
|  in  | `iter_do_init`             |    1    | 1이면 INIT 먼저                         |
|  in  | `iter_count`               |   16   | 돌릴 반복 수 Δj                        |
|  in  | `n_qubits`                 |    5    |                                         |
| out | `iter_busy`, `iter_done` |  1 / 1  | §2 규약                                |
| out | `state`                    |    4    | 트레이스용                              |
| out | `amp_raddr` | AW (10) | 읽기 주소 (발행) |
| out | `amp_waddr` | AW (10) | 쓰기 주소 (2사이클 지연) |
| out | `amp_re`, `amp_we`       |  1 / 1  |                                         |
| out | `data_addr`                | AW (10) |                                         |
| out | `phase`                    |    1    |                                         |
| out | `acc_clear`, `acc_en`    |  1 / 1  |                                         |
| out | `pass_tick`                |    1    | 패스 하나 끝날 때 펄스 →`passes_run` |

상태: `S_IDLE → S_INIT → (S_PASS1 → S_MEAN → S_PASS2) × Δj → S_IDLE`.

**파이프라인 정렬** — BRAM 동기 읽기가 1사이클 지연되므로 3단으로 봅니다.

```
 t   : amp_raddr / data_addr 제시, amp_re
 t+1 : rdata 유효 → predicate → sign_flip → adder_tree (전부 조합)
 t+2 : amp_mem 되쓰기 (주소는 2사이클 지연시킨 값), sum_accum 누적
```

`PIPE_LAT = 2` 이고 패스 하나가 `DEPTH + PIPE_LAT` 사이클입니다. 따라서 **반복 1회 = `2·(DEPTH + PIPE_LAT) + 1` = 2,053 사이클**($n=15$)이며, 예산표의 2,048은 정상화(steady-state) 값입니다. 테스트벤치 assert는 상수를 박지 말고 `2*DEPTH + ITER_OVH` 로 씁니다.

**확정: `ITER_OVH = 5`** (2026-08-15, C. `tb_ctrl_fsm.v` 실측). 내역은 패스마다 파이프라인이 빠져나가는 2사이클씩 4사이클과 `S_MEAN` 1사이클입니다. `S_INIT` 은 여기 안 들어가고 따로 `DEPTH` 사이클입니다. 또 이 파이프라인 때문에 `ctrl_fsm` 이 `amp_raddr` 과 별도로 **`amp_waddr` 을 냅니다** — 두 주소가 같은 사이클에 다르기 때문이고, §4.11 이 `amp_mem` 을 true dual port 로 둔 것과 같은 이유입니다.

### 4.7 `grover_born_sampler` (C) — 2단 병렬 측정

| 방향 | 신호                         |     폭     | 비고                      |
| :--: | ---------------------------- | :---------: | ------------------------- |
|  in  | `meas_start`               |      1      | 펄스                      |
|  in  | `n_qubits`                 |      5      |                           |
|  in  | `rnd`                      |     32     | LFSR 출력 (기각 샘플링용) |
| out | `rnd_draw`                 |      1      | 난수 요청 펄스            |
|  in  | `amp_rdata`                | P·DW (576) |                           |
| out | `meas_addr`                |   AW (10)   |                           |
| out | `meas_re`                  |      1      |                           |
| out | `meas_busy`, `meas_done` |    1 / 1    | §2 규약                  |
| out | `cand`                     |   NB (15)   |                           |

3단 동작: ① 32뱅크 동시 읽기 → 제곱기 32개 → 뱅크별 누산 `S_b[46b]` × 32 + `total[51b]` (`DEPTH + PIPE_LAT` 사이클) → ② 32항 prefix-sum으로 뱅크 `b*` 선택 (**32사이클**) → ③ `b*` 뱅크만 직렬 스캔 (`DEPTH + PIPE_LAT` 사이클). 합계 **약 2,084사이클**.

**안전망 2줄이 필수입니다.** prefix-sum이 `r` 을 끝까지 못 넘으면 `b* = 31`, 스캔이 끝에 닿으면 마지막 인덱스를 반환. 노름이 반올림 때문에 정확히 1이 아니므로 이 두 줄이 없으면 FSM이 배열 끝에서 매달립니다.

**DSP**: 제곱기 32개 = DSP 32/120. 이 모듈이 **IP 전체에서 DSP를 쓰는 유일한 곳**입니다.

### 4.9 `grover_cache_ctrl` (D)

| 방향 | 신호            | 폭 | 비고                                            |
| :--: | --------------- | :-: | ----------------------------------------------- |
|  in  | `shot_start`  | 1 | 샷 시작 펄스                                    |
|  in  | `j_req`       | 16 | 이번 샷의 목표 (절대)                           |
|  in  | `force_init`  | 1 | CSR 펄스                                        |
|  in  | `cfg_we`      | 1 | **● 레지스터 쓰기 스트로브 OR** (A 제공) |
|  in  | `iter_done`   | 1 | 반복 완료 →`j_cur` 확정                      |
| out | `do_init`     | 1 | 이번에 INIT 필요                                |
| out | `delta_j`     | 16 | 전진할 반복 수                                  |
| out | `j_cur`       | 16 | RO 상태로 나감                                  |
| out | `cache_valid` | 1 | RO 상태로 나감                                  |

```
do_init  = (!cache_valid) || force_init || (j_req < j_cur);

// iter_done 에서:  j_cur <= j_req;  cache_valid <= 1'b1;
// cfg_we 에서:     cache_valid <= 1'b0;
```

**자원: 레지스터 둘(`j_cur` 16b, `cache_valid` 1b)과 비교기·감산기 하나씩. BRAM 0개.**

### 4.11 메모리 세 개

**`grover_amp_mem`** (C) — 32뱅크 × 1024 × 18b, **true dual port**(RAMB18E1 TDP, 포트당 1024×18), 동기 읽기 1사이클.

| 포트 | 방향 | 신호 | 폭 | 쓰는 쪽 |
|:-:|:-:|---|:-:|---|
| A | in | `raddr`, `re` | AW (10) / 1 | 읽기 전용 |
| A | out | `rdata` | P·DW (576) | |
| B | in | `waddr`, `we` | AW (10) / 1 | 쓰기 전용 |
| B | in | `wdata` | P·DW (576) | |

**단일 포트로는 안 됩니다.** 데이터패스가 `PIPE_LAT = 2` 로 흐르므로 사이클 $t$ 에 주소 $c$ 를 읽으면서 동시에 주소 $c-2$ 를 되쓰고, 두 주소가 다릅니다. 읽기/쓰기 배타 포트를 쓰면 매 사이클 충돌해 패스가 두 배로 늘어납니다. 읽기 주소와 쓰기 주소를 **따로** 받는 것이 이 설계의 전제입니다.

**`grover_data_mem`** (C) — 32뱅크 × 1024 × 16b, **true dual port**.

| 포트 | 방향 | 신호              |      폭      | 쓰는 쪽                              |
| :--: | :--: | ----------------- | :-----------: | ------------------------------------ |

|  B  |  in  | `wr_addr`       |    NB (15)    | `ahb_master` / `data_gen` (적재) |
|  B  |  in  | `we`, `wdata` |     1 / W     |                                      |
|  B  |  in  | `one_addr`      |    NB (15)    | `verify` (1칸 읽기)                |
|  B  | out | `one_rdata`     | signed W (16) |                                      |

포트 B는 적재와 검증이 **시간적으로 겹치지 않습니다**(적재 중에는 실행 금지, §6.4). 먹스 하나로 충분합니다.

**`grover_mask_mem`** (B) — 1024 × 32b.

| 방향 | 신호                         |   폭   | 비고                                         |

### 4.12 `grover_top` 이 소유하는 조정 로직 (A)

두 마스터가 `amp_mem` 주소를 다투므로 먹스가 필요합니다. **`grover_top` 이 소유합니다.**

```verilog
assign amp_raddr = meas_busy ? meas_addr  : iter_raddr;
assign amp_re    = meas_busy ? meas_re    : iter_re;
assign amp_waddr = iter_waddr;                         // 측정은 쓰기 경로를 안 씀
assign amp_we    = meas_busy ? 1'b0       : iter_we;   // 측정은 읽기 전용
```

`amp_we` 가 측정 중 강제로 0인 것이 **재개 캐시가 성립하는 물리적 근거**입니다. 이 한 줄이 깨지면 캐시의 정당화가 통째로 무너지므로, `tb_cache_bbht.v` 가 측정 구간에서 `amp_we` 가 한 번도 서지 않는지 확인합니다.

반복과 측정은 `shot_fsm` 이 순서를 보장해 절대 동시에 돌지 않습니다.

## 5. 술어 인코딩 (B 소유, 전원 합의)

| `mode` | 술어                                   | `thr_a` | `thr_b`  |
| :-------: | -------------------------------------- | --------- | ---------- |
| `2'b00` | `LT` — `value < thr_a`            | 기준값    | 사용 안 함 |
| `2'b01` | `GT` — `value > thr_a`            | 기준값    | 사용 안 함 |
| `2'b10` | `EQ` — `value == thr_a`           | 찾을 값   | 사용 안 함 |
| `2'b11` | `RANGE` — `thr_a < value < thr_b` | 하한      | 상한       |

**네 술어 모두 강부등호입니다.** 열린 구간인지 닫힌 구간인지는 회로가 아니라 약속의 문제이고, 여기서 강부등호로 고정합니다. `thr_a`·`thr_b` 는 **16비트 signed** 이므로 호스트 파서와 CSR이 음수를 받아야 합니다. `RANGE` 에서 `thr_a >= thr_b` 이면 해집합이 공집합이고, 이것은 오류가 아니라 정상적인 $M=0$ 입니다.

### 6.2 바깥 경로 대역폭

| 경로       | 규약                                          |              대역폭 |                  64 KB 전송 시간 |
| ---------- | --------------------------------------------- | ------------------: | -------------------------------: |
| AHB 마스터 | `HBURST=INCR16`, `HSIZE=2B`, 1 beat/cycle |  **200 MB/s** | 32,768사이클 =**0.328 ms** |
| APB CSR    | 32b, 셋업+액세스 2상                          |  실행당 수십 바이트 |                        무시 가능 |
| UART       | 115200 8N1                                    | **11.5 KB/s** |                **5.69 초** |

> **`HSIZE` 가 4B 에서 2B 로 내려간 이유** (2026-08-15, A). `data_mem` 의 적재 쓰기 포트가 16비트 하나로 동결되어 있어(§4.11) 32비트 beat 하나를 받으면 되쓰기가 두 사이클 걸립니다. 버스에 `BUSY` 를 끼워 넣어 beat 를 한 칸 걸러 받는 방법도 있지만, 고정 길이 버스트에서 `BUSY` 가 마지막 전송이 되면 안 된다는 제약 때문에 버스트 경계 처리가 붙습니다. halfword 전송은 그 전부가 필요 없고, 대가는 적재가 0.164 ms 에서 0.328 ms 로 느려지는 것뿐입니다 — 같은 배열을 UART 로 보내면 5.69 초이므로 이 차이는 의미가 없습니다. 엔디안은 **하위 16비트가 짝수 인덱스**이고 `grover_data_gen` 도 같은 규약을 씁니다. 되돌리려면 `grover_ahb_master.v` 한 파일만 고치면 됩니다.

**온칩과 AHB의 비가 35배, 온칩과 UART의 비가 약 120만 배입니다.** 이 세 자릿수 차이가 "데이터는 한 번 올려 두고 임계값만 바꿔 가며 여러 번 탐색한다"는 사용 패턴의 근거이고, UART로 배열을 보내지 않는 이유입니다.

### 6.3 사이클 예산 ($n=15$, $P=32$, 100 MHz)

| 구간                                   |            사이클 |               시간 | 근거                                      |
| -------------------------------------- | ----------------: | -----------------: | ----------------------------------------- |
| `S_INIT`                             |             1,025 |           10.3 µs | `DEPTH + 1` (쓰기만)                    |
| 1패스                                  |             1,026 |           10.3 µs | `DEPTH + PIPE_LAT`                      |
| `S_MEAN`                             |                 1 |                 — |                                           |
| 2패스                                  |             1,026 |           10.3 µs |                                           |
| **반복 1회**                     |   **2,053** | **20.5 µs** | 예산표 값 2,048은 정상화 값               |
| 측정                                   |             2,084 |           20.8 µs | `2·(DEPTH+2) + 32`                     |
| 검증                                   |                 2 |                 — |                                           |
| 데이터 적재 (AHB)                      |            32,768 |            328 µs | `HSIZE=2B` (§6.2 주석)                    |
| 마스크 클리어                          |             1,024 |           10.2 µs |                                           |
| **탐색 전체 ($M=1$, 캐시 켬)** | **370,812** |   **3.7 ms** | 캐시 패스 362회, 몬테카를로 20,000회 평균 |

**UART 왕복이 탐색보다 오래 걸립니다.** `RUN\n`(4 B) + 탐색 3.7 ms + 결과 라인(약 54 B) = 0.35 + 3.7 + 4.7 ≈ **8.8 ms** 이고, 이 중 UART가 5.1 ms입니다. 호스트가 샷 루프를 돌면 24.5샷 × 8.8 ms = **약 210 ms** 로 탐색의 58배가 되므로, 샷 루프는 절대 호스트에 두지 않습니다.

반면 **펌웨어가 샷 루프를 도는 비용은 무시할 만합니다.** 샷당 CSR 쓰기 2회 + 읽기 2회 + BBHT 산술을 넉넉히 100사이클로 잡아도 24.5샷이면 2,450사이클 = 24.5 µs로 탐색의 **0.7%** 입니다. 폴링 루프는 하드웨어와 동시에 도니 시간을 더하지 않습니다. 그러니 BBHT 자율 모드를 최종 형태로 삼는 이유는 성능이 아니라 **`j_cur` 이라는 상태가 두 곳에 생기지 않게 하는 것**입니다. ([17.7절](../study_references/17_RVX_SoC_통합.md#177-하드웨어와-펌웨어의-경계)이 "왕복이 아깝다"고 적은 대목은 이 계산으로 보정합니다 — 상태 일원화 논거는 그대로입니다.)

| `csr_scenario.txt`     | `W <reg> <hex>` / `R <reg> <hex>` / `POLL <reg> <mask> <val>` | `W thr_a 04d2`      |

`$readmemh` 가 바로 읽습니다. 주석은 `//`.

## 9. 난수 소비 규약 (계약 항목 5 — **D가 채워 넣을 자리**)

**미정입니다. 스프린트 0을 넘기지 마십시오.** 어긋나면 골든 모델과 RTL이 영원히 비트정확이 되지 않습니다.

| 정할 것                                                               | 상태 |
| --------------------------------------------------------------------- | ---- |
| LFSR 다항식과 폭 (32비트 xorshift? 최대길이 LFSR?)                    | 미정 |
| 시드의 출처 (CSR? 상수?) 와 리셋 시 값                                | 미정 |
| 샷당 추출 횟수와**순서** (j 추첨 → 측정 문턱)                  | 미정 |
| `j ~ U[0,m)` 의 균등화 방법 — 마스킹은 균등하지 않음. 기각 샘플링? | 미정 |
| 2단 측정에서 뱅크 선택 후 잔차 재사용 vs 두 번째 추출                 | 미정 |
| 기각이 일어났을 때 소비하는 난수 개수 (골든이 똑같이 세야 함)         | 미정 |

## 11. 변경 절차

계약을 바꾸려면 **전원 공지 → 이 문서 갱신 → 통합 지점 테스트벤치 재실행** 순서를 밟습니다. 특히 다음 넷은 바꾸면 파급이 큽니다.

| 바뀌는 것                  | 다시 해야 하는 것                                              |
| -------------------------- | -------------------------------------------------------------- |
| `DW` · `QF` · 반올림 | 골든 스윕 전체, 모든`expect_amp_*.hex`, BRAM 예산            |
| `P` · 뱅킹              | `adder_tree` 단수, `born_sampler` prefix-sum 폭, BRAM 개수 |
| 누산 트리 짝짓기 순서      | 골든`tree_sum` 과 모든 기대 벡터                             |
| 난수 소비 규약             | `bbht.py`, `born_sampler`, `cache_walk.txt` 전부         |

`DW` 를 19~20으로 올려야 하는 상황(성공률 미달)이 오면 BRAM 예산이 깨지므로 **`P` 를 16으로 낮추는 것이 대안**이고, 그때는 위 표의 둘째 줄도 함께 발동합니다. C는 이 판단이 서는 즉시 전원에게 알립니다.
