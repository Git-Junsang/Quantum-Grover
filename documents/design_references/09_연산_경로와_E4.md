## 9.1 실행 상태

`grover_ctrl_fsm_ckpt_e4`의 상태는 다섯이고, 반복 한 번은 뒤의 셋을 씁니다.

| 상태 | 무엇을 |
|---|---|
| `S_INIT` | 진폭 전체를 균일값 raw 32768로 채움 |
| `S_PASS1` | 데이터에 술어를 걸어 오라클 부호를 뒤집고, 동시에 32레인 합을 누적 |
| `S_MEAN` | 누적된 전체 합에서 `2×평균`을 round-even으로 확정 |
| `S_PASS2` | 각 진폭을 `2×평균 − 진폭`으로 바꾸고 대칭 포화 |

`S_INIT`은 탐색을 시작하거나 사용할 체크포인트가 없을 때만 실행됩니다.

오라클과 확산이 한 번의 훑기에 하나씩 들어가서, 반복 한 번이 상태 전체를 두 번
지납니다. 오라클만 훑고 확산만 다시 훑는 구조가 아니라, PASS1이 오라클과 합계 누적을
같이 하고 PASS2가 확산을 합니다.

### 단일 상태 메모리 사용

PASS1에서 오라클 결과를 진폭 메모리에 쓰면서 그 같은 레지스터 출력을 덧셈 트리로도
보냅니다. 상태 한 벌을 더 두고 한쪽은 쓰고 한쪽은 읽는 것이 아니라, 같은 등록 출력이 두
갈래로 갈라지는 것입니다. BRAM을 아끼는 가장 큰 요령입니다.

## 9.2 산술 조각

[`grover_arithmetic.v`](../../hardware_bram/src/grover_arithmetic.v) 안의 모듈들입니다.

| 모듈 | 하는 일 |
|---|---|
| `grover_predicate` | 16비트 signed 비교 네 갈래 |
| `grover_oracle_flip` | 술어가 참이면 진폭 부호 반전 |
| `grover_adder_tree` | 32레인 진폭을 한 값으로 |
| `grover_sum_accum` | 512행 부분합을 전역 누산기(39비트)로 |
| `grover_two_mean_calc` | 전체 합에서 `2×평균`을 round-even |
| `grover_diffusion_sat` | `2×평균 − 진폭`과 대칭 포화 |

### 술어는 런타임 값입니다

`grover_predicate`의 판정은 조합 `case` 문 한 덩어리입니다.

```verilog
case (mode)
    `GP_MODE_LT:    pred = pred_lt;
    `GP_MODE_GT:    pred = pred_gt;
    `GP_MODE_EQ:    pred = pred_eq;
    `GP_MODE_RANGE: pred = pred_range;
    default:        pred = 1'b0;
endcase
```

네 갈래가 전부 회로로 깔려 있습니다. `generate`로 잘라 내지 않으므로, 비트스트림
하나로 네 술어를 전부 쓸 수 있습니다. 값은 `CONTROL` 레지스터 비트 [3:2]에서 와서
mmio → 어댑터 → Main IP → 측정 경로까지 그대로 흐릅니다([13장](13_CSR_레지스터와_실행_모드.md)).

같은 판정기를 측정 뒤 고전 재검증에서도 씁니다([10장](10_측정_경로와_M1_M2.md)).
오라클과 재검증이 다른 판정기를 쓰면 둘이 어긋날 수 있어서 하나로 묶었습니다.

### 포화는 대칭입니다

23비트 2의 보수에서 가장 음수인 코드(`-4194304`)를 쓰지 않고 `±4,194,303`으로
자릅니다([6장 6.3절](06_데이터_표현과_메모리_맵.md)). 포화가 일어나면 `amp_overflow`가
sticky로 섭니다: 진단용이고 종료 사유가 아닙니다.

## 9.3 100 MHz 타이밍을 위한 파이프라인 경계

PASS1의 `BRAM → 술어 → 오라클 → 32레인 덧셈 트리 → 누적기` 경로가 배치·배선 뒤 약
-6.574 ns로 가장 나빴습니다. 두 곳을 잘랐습니다.

1. 오라클 출력 레지스터를 경계로 씀
2. 덧셈 트리 5단을 3단 + 레지스터 + 2단으로 가름

그 대가로 PASS1 마지막 쓰기 뒤 드레인 한 사이클이 `S_MEAN` 진입 전에 들어갑니다.
산술 결과는 바뀌지 않고 지연만 늡니다: 파이프라인 경계는 값을 바꾸지 않으므로
소프트웨어 기준모델과의 bit-exact 대조가 그대로 섭니다.

## 9.4 E4의 4행 병렬 처리

`INTRA_ENGINES=4` 일 때 512행은 128개의 quad로 묶이고, 한 quad는 4행입니다. PASS1과
PASS2는 각각 128번만 발행하면 됩니다.

```
E1 : PASS1 512행 + PASS2 512행   →  반복 한 번에 1,024번 발행
E4 : PASS1 128쿼드 + PASS2 128쿼드 →  반복 한 번에   256번 발행
```

### 논리 궤적의 보존

E4는 물리 반복 안을 쪼갤 뿐이고 BBHT의 논리 요청 열(어떤 `j`를 몇 번째로 뽑는가)은
손대지 않습니다. 그래서 `trial_count` · `L_BBHT` · `actual_grover_iterations`가 E1과
완전히 같고, 줄어드는 것은 사이클뿐입니다.

궤적이 바뀌면 소프트웨어 기준 모델과의 500/500 대조를 통과할 수 없습니다. 회귀 테스트는
E4 최적화가 논리 동작을 바꾸지 않았는지 자동으로 확인합니다
([16장](16_검증_체계.md)).

2026-09-06에 시도했던 다중 엔진은 반대로 요청 열을 두 트랙으로 갈랐고, 분할 비용
+50% 와 슬롯 소유권 문제로 탈락했습니다. 실측과 E4 를 고른 근거(E1 사이클 분해)는
[23장 23.8절](23_설계_근거_실험.md#238-e1-프로파일링과-e4)과
[23.10절](23_설계_근거_실험.md#2310-다중-엔진과-pass2-융합-채택하지-않은-두-시도)에 있습니다.

### BRAM 절감 방식

PASS1의 오라클 결과를 별도 scratch 메모리에 두지 않고 목적지 체크포인트 슬롯에 바로
씁니다. PASS2는 그 슬롯을 다시 읽어 확산 결과로 덮습니다. 구간 실행 규약
(`PASS1: src→dst`, `PASS2: dst→dst`)이 원래 그렇게 되어 있어서 전체 상태 한 벌을 더 둘
필요가 없습니다([11장](11_체크포인트와_정책_엔진.md)).

### 측정과 포트를 나눠 씁니다

측정 중에는 물리 반복이 돌지 않으므로, 측정도 같은 4행 동시 읽기 포트를 빌려 씁니다.
읽기 응답에 태그를 달아 두어서 남아 있던 체크포인트 응답이 측정의 첫 행으로
오인되지 않습니다.

## 9.5 E4의 자원 비용

| 구성 | LUT | FF | BRAM tile | DSP |
|---|---:|---:|---:|---:|
| K4/H4-E1 | 13,804 | 13,611 | 66.0 | 64 |
| K4/H4-E4 | 30,294 | 25,822 | 83.0 | 64 |

LUT 사용량은 2.2배로 늘었고 사이클은 38.71% 감소했습니다
([15장](15_동작_과정과_사이클_구성.md)). DSP 사용량은 증가하지 않습니다. 이 경로에
곱셈기가 없기 때문입니다. 확산은 `2×평균 − 진폭`이라 시프트와 뺄셈이고, 오라클은 부호
반전입니다. DSP가 두 배가 되는 것은 측정 경로의 M1 단계입니다([10장](10_측정_경로와_M1_M2.md)).
