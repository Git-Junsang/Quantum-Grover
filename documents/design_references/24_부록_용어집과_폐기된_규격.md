## 24.1 폐기된 규격

다음 값은 이전 설계에서 썼으나 현재 규격에는 적용되지 않습니다. 옛 문서나 `trash_bin/` 에서
마주치면 무시하고, 현행 설계의 근거로 인용하지 않습니다. 문서 검사기가 이 값들의 부활을
자동으로 잡습니다([16장 16.8절](16_검증_체계.md#168-자동-정합성-검사)).

| 항목 | 폐기된 값 | 현행 |
|---|---|---|
| 큐비트 | n = 15 (N = 32,768) · n = 16, 런타임 `n_qubits` 가변 | Q = 14 (N = 16,384) 고정 + `data_count` 만 런타임 |
| 진폭 형식 | Q2.16 · Q1.17 · 18비트 진폭 | signed 23비트, 소수부 22 |
| 확장 후보 | Q15 · Q16 · P64 | Q14 / P32 로 굳힘 ([23장 23.11절](23_설계_근거_실험.md#2311-채택하지-않은-확장과-갈래)) |
| CSR 간격 | 8바이트 제안안 (`grover_regs.h`) | 4바이트, 38개 |
| CSR 이름 | `mode` `thr_a` `start` `cand` … | `CONTROL` `THRESHOLD_A` `COMMAND` `RESULT_INDEX` … |
| 통신 모듈 | `grover_mmio` `grover_ahb_master` (n=15 시절 초안) | `bbht_grover_mmio` `bbht_ahb_loader` |
| 데이터 적재 | AHB `INCR16` 버스트, 16비트 `HSIZE` | AHB SINGLE, single outstanding, 32비트 |
| 측정 | 진폭이 가장 큰 칸을 고름 (argmax) | Born 규칙 정수 CDF |
| 오라클 | 정답 인덱스를 받아 그 자리를 뒤집음 | 데이터와 임계값만 보고 술어로 뒤집음 |
| 재개 캐시 | 1칸 `j_cur` / `cache_j` + `cache_valid` (Burst) | 슬롯 3개 + 정책 DP (지평 3) |
| 열거 위치 | Main IP 밖 상위 계층 | Main IP 안. 결과 FIFO 256칸 포함 |
| 버스 | AXI4-Lite · AXI-Stream | APB 슬레이브 + AHB 마스터. RVX 에 AXI-Stream 심이 없음 |
| SoC | MicroBlaze | RVX rvc_orca |
| 목표 칩 | XC7S100 · Arty S7-50 | Arty A7-100T (`xc7a100tcsg324-1`) |
| 옛 GitHub 판 | commit `7b96551` 의 Q15/P32/Q2.16 wrapper 수치 | SoC 구조만 참고. 산술 · 폭은 Q14/F22 |

옛 소스 배치도 지금은 없습니다. `src_v2/`(K4/H4 freeze), `src_v3/`(PASS2 융합 포크), `src_f2/`(다중
엔진), `src_comm/` · `src_ablation/`(통신 계층과 ablation 공통소스)은 2026-09-09 ~ 2026-09-13 사이에
`src/` 한 벌로 합쳤고, 보드와 바이트 동일한 판은 태그 `board-k3h3-e4-m2` 에 있습니다. 태그 안의
폴더 이름은 옛 이름 `hardware_bram/` 그대로입니다.

### 중간 단계였던 것

K4/H4 · K4/H8 은 중간 단계입니다. 2026-09-01(K4/H8) · 2026-09-04(K4/H4) 보드 실측 묶음은 그 시점
근거로 남겨 두었지만 최종 성능을 인용할 자리가 아닙니다. 두 묶음은 250쌍(시드 50)이라 500
워크로드 캠페인과 총합을 맞댈 수도 없습니다. CSR 실행 모드 이름 `K4H8_*` 도 2026-09-10 에
`CKPT_*` 로 바꿨습니다([13장 13.7절](13_CSR_레지스터와_실행_모드.md#137-술어와-실행-모드)).

## 24.2 용어와 약어

| 용어 | 뜻 |
|---|---|
| BBHT | Boyer–Brassard–Høyer–Tapp. 정답 수를 모를 때의 Grover 탐색 ([3장](03_Grover와_BBHT_알고리즘.md)) |
| 샷 (shot) · attempt | BBHT 의 한 번의 시도. `j` 를 뽑아 돌리고 측정해 검증하는 한 덩어리 |
| `j` | 한 샷에서 돌릴 Grover 반복 횟수. `[0, m)` 균등 |
| `m` | `j` 를 뽑는 범위. 실패할 때마다 28엔트리 ROM 을 따라 커짐 |
| `L_BBHT` | 논리 반복 누적. 뽑힌 `j` 의 합. 체크포인트로 줄지 않음 |
| 물리 반복 | 실제로 돌린 반복 수(`ACTUAL_ITER`). 체크포인트가 줄이는 대상 |
| 오라클 | 술어를 만족하는 칸의 진폭 부호를 뒤집는 단계. 정답 인덱스를 모름 |
| 확산 | 평균 중심 반사. `2×평균 − 진폭` |
| Born 측정 | 진폭 제곱에 비례하는 확률로 인덱스를 뽑는 것 |
| 술어 | `LT` `GT` `EQ` `RANGE` 네 조건. 전부 strict |
| 패딩 | `DATA_COUNT` 이후 칸. 값과 무관하게 항상 비타겟 |
| K | 체크포인트 슬롯 수. 확정 3 |
| H | 정책이 내다보는 미래 요청 수. 확정 3 |
| E | 물리 반복 한 번에 협력하는 연산기 수. 확정 4. E1 은 한 벌 |
| M | 측정 경로 최적화 단계. 확정 2 (M1 두 행 BUILD, M2 계층 행 선택) |
| M (워크로드) | 데이터셋에 심은 타겟 개수. 1/4/16/64/256 |
| Normal | 체크포인트 없이 샷마다 균일 상태에서 시작하는 실행 |
| Burst | 진폭 메모리 자체를 1칸 체크포인트로 쓰던 옛 구조. 지금의 `burst_enable` CSR 비트 이름에만 남음 |
| quad | E4 가 한 번에 처리하는 4행 묶음 |
| memo | 정책 DP 의 부분 결과 저장소. 3,279 엔트리 |
| Shadow-J | 실제 LFSR 의 복사본으로 미래 `j` 를 예측하는 장치 |
| plan FIFO | 선행 계획을 담아 두는 큐 |
| found_mask | 열거에서 이미 찾은 인덱스를 표시하는 비트맵 |
| 짝맞춤 (paired) 검증 | 같은 시드로 Normal 과 체크포인트를 돌려 논리 축이 같고 물리 반복만 다른지 보는 검증 |
| 6단계 ablation | Normal-E1 → K4/H4-E1 → K4/H4-E4 → K3/H3-E4 → M1 → M2 의 RTL 사이클 사다리 ([15장](15_동작_과정과_사이클_구성.md)) |
| Common500 | 보드와 같은 500 워크로드(M 다섯 × 시드 100, EQ)로 소프트웨어 backend 와 보드를 맞댄 실험 |
| Predicate500 | Common500 모양을 네 술어에 각각 건 2,000 워크로드 ([19장](19_Predicate500_자동_테스트.md)) |
| bench250 · bench500 | 드라이버로 워크로드를 연달아 돌리는 Verilator 궤적 벤치 |
| 모델 · 체크포인트 판 · 체크포인트 없는 판 | `hardware_bram/models/` 아래 구성별 폴더. 체크포인트 판은 보통 최종 구성 `K3H3_E4_M2`, 체크포인트 없는 판은 `nocheckpoint` 모델 ([5장 5.2절](05_하드웨어_아키텍처_개요.md#52-모듈-계층과-파일-지도)) |
| RVX | 이 프로젝트가 쓰는 SoC 플랫폼 생성 환경 (`/opt/rvx`) |
| ORCA | RVX 의 RV32 코어. 순수 소프트웨어 기준선의 주체 |
| user region | RVX SoC 안에 우리 IP 가 들어가는 자리 |
| W1P | 쓰면 1사이클 펄스만 나가는 CSR 성격 |
| RPOP | 읽기 완료가 곧 pop 인 CSR 성격. `FIFO_DATA` 하나뿐 |
| OOC | Out-Of-Context 합성. 모듈 하나만 떼어 재는 방식 |
| WNS | Worst Negative Slack. 타이밍 여유 |
