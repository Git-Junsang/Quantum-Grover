이 장은 비트스트림을 만들고 Arty A7-100T 에 구워, 호스트 PC 에서 가속기를 부리는 절차입니다.
명령 문법은 [14장](14_호스트_인터페이스와_UART_프로토콜.md), 보드에서 실제로 잰 결과와 그
인용 경계는 [18장](18_보드_확인과_실측.md)에 있습니다. 예시는 체크포인트 판(`bbht_grover_upgrade`)
기준이고, 다른 두 판은 플랫폼 이름과 비트스트림 묶음만 다릅니다.

## 17.1 플랫폼 설치와 생성

### 설치 스크립트가 옮기는 것

```bash
source /opt/rvx/rvx_setup.sh
hardware_bram/models/hardware_bram_K3H3_E4_M2/rvx/install_to_platform.sh     # $RVX_MINI_HOME/platform/bbht_grover_upgrade
```

| 저장소 | 플랫폼 |
|---|---|
| `hardware_bram/models/hardware_bram_K3H3_E4_M2/rvx/bbht_grover_upgrade.xml` | `<플랫폼이름>.xml` (`<name>` 을 폴더 이름에 맞춰 넣음) |
| `hardware_bram/src/` Main IP 10개 + `grover_param.vh` | `user/rtl/src/` · `include/` |
| `hardware_bram/src/` 통신 계층 3개 + 모델의 `src/bbht_grover_core_adapter.v` | `user/rtl/src/` |
| `hardware_bram/src/bbht_grover_user_region.vh` | `user/rtl/include/<플랫폼이름>_user_region.vh` |
| `software/contract/generated/bbht_grover_csr.vh` | `user/rtl/include/` |
| `hardware_bram/firmware/bbht_grover_driver.{c,h}` · `generated/bbht_grover_regs.h` | `user/api/` |
| `firmware/bbht_console/` · `bbht_paper_bench/` · `orca_sw_baseline/` | `app/`. 다른 모델은 `bbht_console` 하나 |
| (스크립트가 만듦) | `user/env/set_rtl_syn_env.tcl`. `user/rtl` 을 합성 경로에 등록 |
| RVX 뼈대 `$RVX_DEVKIT/env/user/` 중 없는 것 | `user/env/` · `user/sim/include/` |

일은 전부 공용 설치기 [`hardware_bram/rvx/install_model.sh`](../../hardware_bram/rvx/install_model.sh) 가
하고, 모델의 `install_to_platform.sh` 는 모델 폴더와 앱 목록만 넘깁니다. 다른 모델은 그 모델의
스크립트를 부르면 되고, 설치기는 어떤 K · H · E · M 이 들어갔는지 어댑터 기본값을 찍어 줍니다.
설치할 때마다 `user/rtl/` 과 앱 폴더를 비우고 다시 채우므로 앞서 설치한 다른 모델의 흔적이
남지 않습니다. RVX 뼈대를 빠진 것만 채우는 이유는 RVX 가 `make syn` 때 `user/` 가 **없을 때만**
뼈대를 복사하기 때문입니다. 설치기가 `user/` 를 먼저 만들면 그 복사가 건너뛰어져 SoC 시뮬
컴파일이 user region 헤더를 못 찾습니다(2026-09-25 첫 시뮬이 이것으로 실패했습니다).

스크립트는 첫 줄에서 `gen_csr.py` 를 불러 생성 헤더 둘을 직접 만들므로, 저장소를 새로 받아도
따로 준비할 것이 없습니다. 합성 대상만 골라 옮깁니다. `grover_policy_ooc_top.v` ·
`grover_policy_impl_wrapper.v` 는 OOC 전용이고, `bbht_bram_top.v` 는 wrapper 와 같은 자리에 들어가는
다른 최상단이라 빠집니다.

### 플랫폼 폴더를 처음 만들 때

스크립트는 플랫폼 디렉터리를 만들지 않습니다. 없으면 안내만 하고 끝나므로 RVX 골격부터 만듭니다.

```bash
cd $RVX_MINI_HOME/platform
make copy_platform BEFORE=bbht_grover AFTER=bbht_grover_upgrade
```

복제본에는 다른 플랫폼의 RTL 이 이름만 바뀐 채 들어 있습니다(`rename.py` 가 파일명과 내용의
`bbht_grover` 를 전부 치환합니다). 특히 `bbht_grover_core_stub.v` 는 우리 어댑터와 모듈 이름이
겹쳐 elaboration 을 깨뜨리므로, 설치 전에 `user/rtl/{src,include}` · `user/api` ·
`user/template` 을 비우고 `app/bbht_console` 을 지웁니다.

체크포인트 없는 판은 `tip_hello` 의 Makefile 만 복사한 빈 폴더에서 시작하고, 그 설치 스크립트가
RVX `user/` 뼈대 중 빠진 것을 채웁니다. RVX 는 `make syn` 때 `user/` 가 없을 때만 뼈대를
복사하는데, 설치 스크립트가 `user/` 를 먼저 만들면 그게 건너뛰어져 SoC 시뮬이 user region 헤더를
못 찾기 때문입니다([21장 21.7절](21_체크포인트_없는_BRAM_판.md#217-돌리는-법)).

### 생성과 확인할 값

```bash
cd $RVX_MINI_HOME/platform/bbht_grover_upgrade
make syn
grep -E "I_GROVER_CSR_SLAVE_BASEADDR|I_SYSTEM_SRAM" arch/ssw/src/memorymap_info.h
grep SYSTEM_CLK_HZ arch/ssw/src/hw_info.h
```

| 무엇 | 값 (2026-09-02 실측) |
|---|---|
| `I_GROVER_CSR_SLAVE_BASEADDR` | `0xE2020000` (size `0x1000`) |
| `I_SYSTEM_SRAM` | `0xE0000000` ~ `0xE001FFFF` (128 KiB) |
| `SYSTEM_CLK_HZ` | 50 MHz (SoC 쪽) |
| `clk_accel` | 100 MHz (가속기 도메인, PLL0) |

클럭이 둘이라는 점이 자주 헷갈립니다. RISC-V 코어와 UART 는 50 MHz, 가속기와 CSR · loader 는
100 MHz 에서 돕니다. `CYCLE_COUNT` 는 뒤엣것 기준이라 시간 = 사이클 / 100 us 이고, 50으로 나누면
두 배 틀립니다.

## 17.3 보드 연결과 UART

Arty A7-100T 의 마이크로 USB 하나가 JTAG 과 UART 를 겸합니다(FT2232). 꽂으면 호스트에 시리얼
포트가 둘 잡힙니다.

```bash
ls -l /dev/serial/by-id/          # 안정적인 이름
dmesg | tail -20                  # 방금 잡힌 ttyUSB 번호
sudo usermod -aG dialout $USER    # 권한이 없으면. 로그아웃 후 다시 로그인
```

보통 `/dev/ttyUSB0` 이 JTAG 채널, `/dev/ttyUSB1` 이 UART 채널입니다. 둘 중 뒤 번호가 UART 이고,
앞 번호에 터미널을 붙이면 아무것도 안 나옵니다. Windows 에서는 `COM` 번호로 잡힙니다.

| 항목 | 값 |
|---|---|
| 보율 | 115200 |
| 데이터 · 패리티 · 정지 | 8 · 없음 · 1 |
| 흐름 제어 | 없음 |

보율은 RVX 의 `ervp_uart.c` 기본값(`UART_BAUD_RATE 115200`)이고 `UART_CLK_HZ` 50 MHz 에서
분주됩니다. `SYSTEM_CLK_HZ` 를 바꾸면 분주비가 같이 바뀌므로 클럭을 건드린 뒤에는 다시
확인합니다. 안 맞으면 깨진 글자만 나옵니다.

UART RX 는 표준 핀맵 그대로 양방향입니다. `imp_class_info/arty-100t/pinmap/uart_printf.xdc` 가
`printf_rx` 를 A9 핀(`uart_txd_in`)에 배정하고, RVX SSW 에 `uart_check_rx_data_ready()` ·
`uart_read_rx_buffer()` API 가 있습니다.

## 17.4 굽고 앱 올리기

### 비트스트림

```bash
cd hardware_bram/models/hardware_bram_K3H3_E4_M2/bitstream/2026-09-25_console_predicate500
vivado -mode batch -source program_fpga.tcl        # 헤드리스 가능
```

RVX imp 폴더에서는 `make program`(보드에 굽기) · `make program_flash`(SPI 플래시에 굽기, 전원을
내려도 남음)로도 굽습니다.

### 앱

앱은 JTAG 로 SRAM 에 올립니다. JTAG 어댑터(Olimex ARM-USB-TINY-H)가 붙은 PC 에서 합니다.
Windows 면 `usbipd` 로 WSL 에 넘긴 뒤입니다.

```bash
cp /opt/rvx/local_setup/ocd/openocd_rvp ocd/
cp bbht_console.sram.hex ocd/
ocd/ocd_keep.sh &          # 올린 뒤 OpenOCD 를 붙여 둔 채 유지
```

`ocd/` 는 RVX 가 imp 폴더에 내주는 OCD 환경이 `/opt/rvx` 절대경로를 읽어 다른 PC 에서 못 쓰기
때문에, 필요한 tcl 을 상대경로로 모아 둔 묶음입니다.

| 파일 | 역할 |
|---|---|
| `arty-100t.cfg` | OpenOCD 설정. Olimex ARM-USB-TINY-H, 10 MHz, JTAG tap `rvp.noc` |
| `run_bbht_console.tcl` | 플랫폼 리셋 → SRAM 에 write → `set_all_ready` |
| `set_ocd_env.tcl` | `arch/` · `rvx_env/` 를 상대경로로 읽도록 고친 판 |
| `load_app.sh` | 올리고 빠져나옴 |
| `ocd_keep.sh` | 올린 뒤 OpenOCD 를 붙여 둔 채 유지 |

OpenOCD 를 종료하면 어댑터 분리 과정에서 플랫폼이 리셋되어 SRAM 의 앱이 사라집니다. SPI 플래시
부팅은 아직 없으므로 보드 RESET 버튼을 눌러도 앱을 다시 올려야 합니다. `openocd_rvp` 실행
파일(12 MB)은 저장소에 두지 않았습니다. `/opt/rvx/local_setup/ocd/` 사본과 sha256 이 같습니다.

RVX imp 폴더에서 빌드와 실행을 한 번에 하려면 `make <앱>.run` 입니다.

## 17.5 두 가지 앱

| | proof app (`bbht_paper_bench` 등) | 콘솔 앱 (`bbht_console`) |
|---|---|---|
| 설정이 있는 곳 | C 코드 안 (`#define`) | UART 명령 |
| 조건을 바꾸려면 | 앱 재빌드 → 재적재 | 명령 한 줄 |
| 만든 사람 | PJK | SJS |
| 쓰는 자리 | 회귀 기준선, 보드 500런 성능 실측 | 실험, 브링업, 조건 스윕, 자동 테스트 |

두 앱 모두 비트스트림과 Main IP 는 건드리지 않고 앱만 바꿔 끼웁니다.

proof app 을 지우지 마십시오. PJK 가 보드에서 통과시킨 다섯 시나리오(APB / DMA / Single /
Enumeration / 체크포인트)가 회귀 기준선이고, 통신 계층을 고칠 때마다 그 다섯을 다시 통과해야
기준선 교체를 논의할 수 있습니다. 앱 이름에 남은 `K4H8` 은 그 시절 이름이고 가리키는 것은
체크포인트 경로입니다.

```bash
cd $RVX_MINI_HOME/platform/bbht_grover_upgrade/imp_arty-100t_<날짜>
make bbht_single.run
```

```
BBHT SINGLE SEARCH E2E TEST START
dataset addr = 0xe000597c
DMA_STATUS = 0x00000080
DMA LOAD PASS
SEARCH CONFIGURED
SEARCH START issued
STATUS = 0x0000080c
RESULT_INDEX = 120
TRIAL_COUNT  = 1
L_BBHT       = 1
ACTUAL_ITER  = 1
CYCLE_COUNT  = 2126
BBHT SINGLE SEARCH E2E TEST PASS
```

`STATUS = 0x0000080c` 는 bit2 `done_sticky`, bit3 `result_valid`, bit11 `fifo_empty` 입니다.
정상 완료 · 결과 유효 · FIFO 빔입니다([13장 13.5절](13_CSR_레지스터와_실행_모드.md#135-status-0x024)).
보드 500런은 `make bbht_paper_bench.run` 으로 돌린 것입니다.

## 17.6 콘솔로 부리기

터미널을 붙이면(`screen /dev/ttyUSB1 115200` 또는 `minicom -D /dev/ttyUSB1 -b 115200`) 이렇게
나옵니다.

```
# bbht_console -- HELP 를 치면 명령 목록이 나옵니다
OK
```

한 번 돌려 보는 순서입니다. 응답과 필드의 뜻은 [14장 14.5절](14_호스트_인터페이스와_UART_프로토콜.md#145-한-번-돌리는-전형적인-순서)에 있습니다.

```
ID
GEN COUNT=16384 TARGETS=1 VAL=12345
LOAD
SET MODE=EQ A=12345 AUTO=1 BURST=0 SEEDJ=0x7b1dcdaf SEEDM=0x24370df2
RUN
SET BURST=1
RUN
STAT
```

여러 명령을 한 번에 돌리거나 로그를 남길 때는 호스트 CLI 를 씁니다.

```bash
python3 software/host/bbht_cli.py --port /dev/ttyUSB1 selftest
python3 software/host/bbht_cli.py --port /dev/ttyUSB1 --script exp.txt --log run.log
```

네 술어 × 500 워크로드를 통째로 돌려 엑셀로 남기는 것은 `bbht_predicate500.py` 입니다
([19장](19_Predicate500_자동_테스트.md)).

짝 비교에서 두 모드의 결과가 하나라도 다르면 그 결과를 쓰지 않습니다. 같은 시드에서 Normal 과
체크포인트가 다른 답을 냈다는 것은 체크포인트 구현이나 통신 계층이 의미를 바꿨다는 신호입니다.

## 17.7 CSR 을 직접 두드릴 때 지킬 규약

RTL 과 드라이버가 이미 강제하지만, 직접 CSR 을 두드릴 때는 사람이 지켜야 합니다.

1. `COMMAND` 를 쓰기 전에 `STATUS` 를 확인합니다. start 큐가 없어서 조건이 안 맞으면 펄스가 조용히
   버려집니다. 시작한 줄 알고 폴링하면 직전 실행의 `done` 을 보고 낡은 결과를 읽습니다.
2. 완료 판정은 `done_sticky` 로 합니다. 그것을 지우는 것은 `COMMAND` 쓰기뿐입니다.
3. 결과는 `busy` 가 내려간 뒤에 읽습니다. 결과와 카운터는 APB 트랜잭션 여러 번에 나눠 읽히므로,
   그 사이 새 실행이 시작되면 서로 다른 시점의 값이 섞입니다.
4. 적재 중에는 시작하지 않습니다. 절반만 채워진 배열 위에서 오라클을 돌리면 경고 없이 그럴듯한
   오답이 나옵니다.
5. `FIFO_DATA` 는 읽는 것 자체가 pop 입니다. 인덱스 0 이 정상 결과일 수 있으므로 비었는지는
   `STATUS.fifo_empty` 나 `FIFO_COUNT` 로 봅니다. 열거에서는 실행 중에도 계속 뽑아야 합니다.

C 코드에서 base address 를 숫자로 박지 않습니다. `bbht_grover_regs.h` 가
`I_GROVER_CSR_SLAVE_BASEADDR` 를 쓰도록 되어 있습니다.

## 17.8 잘 안 될 때

| 증상 | 먼저 볼 것 |
|---|---|
| 터미널에 아무것도 안 나옴 | 포트를 잘못 골랐습니다. 뒤 번호(`/dev/ttyUSB1`) 쪽입니다 |
| 깨진 글자만 나옴 | 보율 불일치. `SYSTEM_CLK_HZ` 를 바꿨는지 확인합니다 |
| `# 경고: CSR 응답이 이상합니다` | 비트스트림이 안 올라갔거나 base address 가 다릅니다. `make syn` 뒤 `memorymap_info.h` 를 다시 봅니다 |
| `ERR NOT_LOADED` | `LOAD` 를 안 했습니다. `GEN` 이나 `POKE` 뒤에는 반드시 `LOAD` |
| `ERR DMA_ERROR` | `REG` 로 `0x060`(`DMA_STATUS`)을 봅니다 ([13장 13.6절](13_CSR_레지스터와_실행_모드.md#136-dma_status-0x060)) |
| `ERR TIMEOUT` | 탐색이 콘솔의 폴링 상한을 넘었습니다. `SET CAP=...` 을 조정합니다 |
| `MISS reason=SHOT_CAP` | 정상 동작입니다. 정답이 없거나 샷 상한에 걸린 것입니다 |
| 호스트 스크립트가 응답을 못 받음 | 탐색이 길면 대기 시간을 `SHOT_CAP` 에 맞춰 늘립니다 |
| 명령을 연달아 보냈더니 깨짐 | 흐름 제어가 없습니다. 응답을 받은 뒤 다음 명령이 규약입니다 |
| 포트를 다시 열었더니 에코조차 안 옴 (`ERR HOST_TIMEOUT`) | 포트를 열 때 DTR/RTS 가 켜지면 SoC 가 리셋됩니다. 앱이 JTAG 로 올린 SRAM 이미지뿐이라 다시 올려야 합니다. `bbht_cli.py` 는 2026-09-17 부터 열기 전에 둘을 내립니다. 다른 터미널을 쓴다면 같은 설정을 확인합니다 |
| Windows 에서 `--script` · `--log` 가 한글에서 죽음 | cp949 로 열던 것을 UTF-8 로 고쳤습니다. 옛 사본을 쓰고 있지 않은지 봅니다 |
| 호스트 자동 테스트가 `platform=` 이 없다고 멈춤 | 옛 콘솔입니다. 2026-09-25 판 `bbht_console.sram.hex` 를 올립니다 |
