# 6장. 데이터 표현과 메모리 맵

> [← 5장 하드웨어 아키텍처 개요](05_하드웨어_아키텍처_개요.md) · [문서 지도](00_문서_지도.md) · [7장 통신 계층 →](07_통신_계층.md)

---

이 장은 입력 데이터, 진폭, 데이터패스 비트폭, 메모리 배치의 정본입니다. 보드에서 검증된 RTL
(`hardware_bram/src/` 의 Main IP)과 bit-exact 기준모델
(`software/models/rtl_reference_model/`)이 같은 규격을 쓰고, 표의 값은
[`grover_param.vh`](../../hardware_bram/src/grover_param.vh)에서 직접 뽑았습니다.

| 항목 | 값 |
|---|---:|
| 상태 수 | 16,384 |
| 병렬도 | P32 |
| 행 수 | 512 |
| 입력 | signed16 |
| 저장 진폭 | signed 23비트, raw / `2^22` |
| 초기 진폭 raw | 32,768 |
| 평균 반올림 | nearest, ties-to-even |
| 진폭 범위 | `[-4194303, 4194303]` |
| 측정 | 정수 제곱 + LFSR rejection + 행/레인 CDF |

## 6.1 입력 데이터

signed 16비트 2의 보수입니다.

| 실제 값 | 16비트 HEX |
|---:|---|
| 0 | `0000` |
| 1 | `0001` |
| 32767 | `7FFF` |
| -1 | `FFFF` |
| -32768 | `8000` |

골든 벡터 파일은 전역 인덱스 순서로 한 줄에 네 자리 HEX 하나를 씁니다.

```text
0003
FFF8
0000
7FFF
```

`index >= data_count` 인 칸은 메모리에 어떤 값이 남아 있어도 오라클과 후보 검증에서 항상
비타겟입니다. 데이터 개수를 16,384보다 작게 줄 수 있고, 그때 남은 자리의 값이 결과에 영향을
주지 않습니다. 패딩 자리에 조건을 만족하는 값을 일부러 넣은 캠페인에서도 패딩 인덱스가
결과로 나온 경우는 0이었습니다([23장 23.1절](23_설계_근거_실험.md#231-골든-모델-캠페인-기능-정합성)).

## 6.2 P32 뱅크/행 매핑

전역 인덱스 `i` 를 32레인 × 512행에 이렇게 펼칩니다.

```
bank = i mod 32       =  index[4:0]
row  = i / 32         =  index[13:5]
```

| 인덱스 | bank | row |
|---:|---:|---:|
| 0 | 0 | 0 |
| 31 | 31 | 0 |
| 32 | 0 | 1 |
| 63 | 31 | 1 |
| 16383 | 31 | 511 |

한 행에서 레인과 뱅크는 1:1입니다. packed row 버스에서 레인 `b` 는
`row_bus[b*WIDTH +: WIDTH]` 이고, 레인 0이 최하위 비트 슬라이스입니다.

한 행을 읽으면 원소 32개를 동시에 가져오고, 512행을 읽으면 전체 상태를 한 번 훑습니다. 뒤
장에서 쓰는 512행 단위가 여기서 나옵니다.

## 6.3 진폭 형식

저장 진폭은 signed 23비트, 소수부 22비트이고 실수값은 `raw / 2^22` 입니다. "Q1.22 계열" 이라고
부르지만 Q 표기 관례가 갈릴 수 있으므로 "signed 23비트, fractional 22" 라는 정의를 우선합니다.

| 값 | raw | 23비트 코드 (6자리 HEX) |
|---|---:|---|
| Q14 초기 진폭 `1/128` | 32768 | `008000` |
| `1/64` | 65536 | `010000` |
| 사용하는 최대 | 4194303 | `3FFFFF` |
| 사용하는 최소 | -4194303 | `400001` |
| 제외한 2의 보수 최솟값 | -4194304 | `400000` |

대칭 포화를 위해 `-4194304` 는 쓰지 않습니다. 양끝이 대칭이어야 확산의 부호 처리가 한쪽으로
치우치지 않습니다. 포화가 일어나면 `amp_overflow` 가 sticky 로 섭니다.

Q14 초기값은 정확히 표현됩니다. `1/sqrt(16384) = 1/128` 이고 `2^22 / 128 = 32768` 이라
반올림 오차 없이 시작합니다. 이 폭(소수부 22)을 고른 근거 실험은
[23장 23.2절](23_설계_근거_실험.md#232-진폭-정밀도-q14-와-소수부-22비트)에 있습니다.

## 6.4 데이터패스 비트폭

| 값 | 폭 | signed | 역할 |
|---|---:|---|---|
| 입력 데이터 | 16 | signed | 술어 입력 |
| 저장 진폭 | 23 | signed | 상태벡터 |
| 32레인 부분합 | 28 | signed | 행 진폭 합 |
| 전역 누산기 | 39 | signed | 16,384개 진폭 합 |
| `two_mean` | 25 | signed | 반올림된 `2*mean` |
| 확산 중간값 | 25 | signed | `two_mean - oracle_amp` |
| 진폭 제곱 | 46 | unsigned | `raw^2` |
| 행 가중치 | 51 | unsigned | 제곱 32개 합 |
| 전체 가중치 | 60 | unsigned | 전체 Born 가중치 |
| 인덱스 | 14 | unsigned | 0..16383 |
| 데이터 개수 | 15 | unsigned | 1..16384 |
| `j` | 7 | unsigned | 0..127 |

한 항목의 폭이 바뀌면 그것을 쓰는 하위 연산과 메모리 형식을 같이 봐야 합니다. `j` 가 7비트인
것이 [8장](08_Main_IP_최상위와_BBHT_제어.md)의 LFSR 7스텝 점프와 직접 이어집니다.

## 6.5 한 번의 Grover 반복

```text
PASS1
  진폭 + 데이터 행 읽기
  -> 패딩 게이트 + signed 술어
  -> 타겟 진폭 부호 반전
  -> 오라클 결과를 진폭 메모리에 씀
  -> 32레인 합과 전역 누산

MEAN
  전역 합 -> 반올림된 two_mean

PASS2
  오라클 결과 행 읽기
  -> two_mean - oracle_amp
  -> 대칭 포화
  -> 다음 진폭을 진폭 메모리에 씀
```

오라클은 `i < DATA_COUNT` 이고 술어가 참인 칸만 부호를 뒤집습니다.

```
oracle_amp[i] = -amp[i]   if (i < DATA_COUNT) and predicate(data[i])
              =  amp[i]   otherwise
```

평균은 반올림한 뒤 두 배하지 않습니다. 전체 합에서 `2*mean` 을 한 번만 ties-to-even 으로
반올림합니다. Q14 에서는 signed 전역 합을 13비트 오른쪽 시프트하고 nearest-even 을 적용합니다.

```
two_mean = roundEven( sum(oracle_amp) / 2^(Q-1) )        Q = 14 이면 13비트 시프트
next_amp[i] = clip( two_mean - oracle_amp[i], -4194303, 4194303 )
```

한 번이라도 포화가 나면 `amp_overflow` 가 다음 accepted start 까지 유지됩니다. 진단용이고
종료 사유가 아닙니다.

## 6.6 파이프라인과 메모리 접근

```text
INIT / PASS2
t   : 행 발행
t+1 : BRAM 응답 / 데이터패스
t+2 : 진폭 메모리 쓰기

PASS1
t   : 진폭/데이터 행 발행
t+1 : BRAM 응답, 술어 메타데이터 레지스터
t+2 : 패딩 + 오라클, 진폭 행 레지스터
t+3 : 진폭 메모리 쓰기, 덧셈 트리 전반
t+4 : 덧셈 트리 후반, 전역 누산기
```

PASS1 뒤에는 마지막 부분합을 받기 위한 드레인 상태가 있습니다. `cycle_count` 는 이 파이프라인을
포함한 회귀 관측값이고, 파이프라인이 바뀌어도 고정되는 외부 포트 계약은 아닙니다. 파이프라인
경계를 자른 이유는 [9장 9.3절](09_연산_경로와_E4.md#93-100-mhz-타이밍을-위한-파이프라인-경계)에
있습니다.

## 6.7 메모리 구조

### 논리 구성

| 메모리 | 논리 구성 | raw 용량 | 용도 |
|---|---|---:|---|
| `data_mem` | 32뱅크 × 512 × 16비트 | 32 KiB | 오라클 입력과 후보 재검증 |
| 진폭 · 체크포인트 | 상태 한 벌 = 512행 × 32레인 × 23비트, 물리 슬롯 4벌 | 46 KiB × 4 | 상태벡터와 되돌아갈 지점 |
| 행 가중치 | 512 × 51비트 | 약 3.2 KiB | Born 행 CDF |

E4 구성에는 따로 떨어진 작업용 진폭 메모리가 없습니다. 계산은 슬롯 안에서 제자리(in-place)로
하거나, 한 반복만 다른 슬롯으로 건너 씁니다(bridge). 구간 규약은
[11장](11_체크포인트와_정책_엔진.md)에 있습니다.

측정은 진폭 메모리를 읽기 전용으로 쓰므로 측정 직전 상태가 그대로 남습니다. 슬롯은 그 상태를
되돌아갈 지점으로 남겨 두는 것이고, 관리 규칙은 [12장 12.8절](12_Main_IP_포트_계약.md#128-체크포인트-계약)에
있습니다.

### 물리 BRAM 배치

위 표는 논리 비트 수이고, 실제 개수는 커밋된 구현 리포트(`route_util_hier.rpt`)로 확인합니다.

| 무엇 | 개수 |
|---|---|
| 진폭 상태 한 벌 | 행 736비트 = 10 × 69비트 + 1 × 46비트 → RAMB36 11개 |
| 물리 슬롯 4벌 | 행 위상 뱅크 4개(각 512 × 736비트)에 담아 RAMB36 44개 |
| 정책 memo | RAMB36 4 |
| found mask | RAMB36 2 |
| 행 가중치 | RAMB36 2 |
| `data_mem` | RAMB18 64 |
| Main IP 합계 | RAMB36 52 + RAMB18 64 = BRAM 84 tile |
| 풀 SoC | BRAM 116 tile |

상태 한 벌은 16,384 × 23 = 376,832비트이고 RAMB36 하나가 36,864비트라 이론 하한이 10.22개,
즉 최소 11개입니다. 구현이 그 하한을 달성했습니다([23장 23.6절](23_설계_근거_실험.md#236-체크포인트-메모리-패킹)).

물리 슬롯은 K 와 관계없이 4벌입니다. 그래서 K4 에서 K3 로 바꿔도 BRAM 이 줄지 않았습니다(자원
ablation 83.0 → 83.0 tile). 성능 개선은 저장 공간이 아니라 정책 결정 비용에서 나왔습니다
([1장 1.4절](01_프로젝트_개요.md#14-최종-구성-k3h3-e4-m2)).

## 6.8 시스템 SRAM 과 적재

데이터셋은 CSR 로 넣지 않고 시스템 SRAM 에 두었다가 가속기가 끌어갑니다.

| 항목 | 값 |
|---|---|
| SRAM 범위 | `0xE0000000` ~ `0xE001FFFF` (128 KiB) |
| 패킹 | `word[15:0] = data[2k]`, `word[31:16] = data[2k+1]` (리틀엔디안) |
| 전송 | 32비트 AHB SINGLE, single outstanding |
| 비용 | 워드당 3사이클 (주소 1 + 데이터 1 + 쓰기 1) |
| Q14 전체 | 16,384항목 = 8,192워드 → 24,576사이클, 100 MHz 에서 약 246 us |

`DATA_COUNT` 가 홀수이면 마지막 상위 halfword 를 loader 가 쓰지 않습니다. 전달하더라도
`addr >= data_count` 라서 Main IP 쪽 loader 가 무시합니다.

Main IP loader 는 주소 중복을 검출하지 않습니다. 같은 주소를 여러 번 써도 쓰기 개수가
올라가므로, 어댑터는 `0..data_count-1` 을 정확히 한 번씩 생성해야 합니다
([12장 12.7절](12_Main_IP_포트_계약.md#127-loader-트랜잭션)).

## 6.9 정답 벡터와 비교 순서

기준 벡터는 `software/rtl_vectors/requested_j_bit_exact/requested_j_bit_exact_256_cases.zip`
입니다(파일 구성은 [4장 4.5절](04_소프트웨어_기준모델과_정답_벡터.md#45-rtl-정답-벡터)). 어긋날 때는
이 순서로 첫 불일치 단계를 찾습니다.

```text
loader data
-> initial amplitude
-> after Oracle
-> partial / global sum
-> two_mean
-> after Diffusion
-> Born total weight / threshold
-> selected row / lane / index
-> verification
-> L_BBHT / physical iteration / cycle count
```

최종 index 만 맞는 것으로 bit-exact PASS 를 선언하지 않습니다. BBHT 가 후보를 술어로 자가
검증하므로 진폭이 깨져도 답은 맞을 수 있습니다. 첫 불일치 단계에서 loader, 술어, 반올림, 포화,
LFSR, CDF 문제를 가릅니다. `bit-exact` 는 허용 오차 안에서 비슷하다는 뜻이 아니라 RTL 의
고정소수점 비트열이 기준모델의 값과 정확히 같다는 뜻입니다. Float64 비교는 수치 품질 검증에,
Q1.22 비교는 RTL 구현 검증에 씁니다.
