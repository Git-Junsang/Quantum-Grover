# 툴체인 사용법 — RVX · verilator · Qiskit

역할이 셋으로 갈립니다.

- **RVX** — 플랫폼 생성부터 RTL 시뮬, 합성·구현까지 **전 과정**.
- **verilator** — 저장소 회귀 **전용**. SoC 없이 wrapper 와 Main IP 만 빠르게 돌립니다.
- **Qiskit** — RTL 밖에서 도는 **기준자**. 나온 결과가 맞는지 대조하는 데만 씁니다.

이 환경에서 직접 돌려 확인한 명령입니다
(RVX·verilator 2026-08-21, Vivado 2026-08-22, Qiskit 2026-09-03, 회귀 2026-09-09).

| 도구 | 이 환경의 판 | 쓰는 자리 |
|---|---|---|
| verilator | 5.020 | `hardware_bram/sim` · `hardware_dram/sim` 회귀 |
| Questa `vsim` | 2022.1_2 | RVX `make sim_rtl` (SoC 전체) |
| Vivado | 2026.1 (노드락) | 합성·구현·비트스트림 |
| iverilog / vvp | 12.0 | 지금 저장소에서 쓰는 곳이 없습니다 |

**화면이 없습니다.** Vivado GUI · `make view` · `gtkwave` 는 설치 여부와 무관하게
못 띄웁니다. 파형은 파일로 남겨 내려받아 여십시오.

---

## 1. RVX — 플랫폼부터 합성까지

### 1.1 준비

새 터미널마다 한 번 실행합니다.

```bash
source /opt/rvx/rvx_setup.sh
```

합성·구현까지 갈 때 따로 준비할 것은 없습니다. Vivado 는 라이선스까지 이미 잡혀 있고 `vivado` 로
바로 부르면 됩니다(1.6절). 예전에 쓰던 `vivado_env.sh` 는 이제 source 하지 않아도 되고,
그 스크립트 자체도 `trash_bin/old_tools/` 로 내려갔습니다.

### 1.2 전 과정

```bash
source /opt/rvx/rvx_setup.sh

# (1) 플랫폼 만들기 -- 가속기 IP 예제를 복제하는 편이 빠릅니다
cd $RVX_MINI_HOME/platform
make copy_platform BEFORE=tip_quantized_cnn AFTER=grover_soc

# (2) SoC 서술 편집 -- IP 인스턴스와 파라미터를 여기서 정합니다
cd grover_soc
vim grover_soc.xml

# (3) 생성 -- XML 로부터 RTL·시스템 소프트웨어를 만듭니다
make syn

# (4) 앱 만들기
cd app && make new APP_NAME=grover
vim grover/src/main.c
cd ..

# (5) RTL 시뮬레이션
make sim_rtl
cd sim_rtl && make grover.sim
cd ..

# (6) 합성·구현
make arty-100t
cd imp_arty-100t_<날짜> && make imp
```

### 1.3 명령

명령은 **어디서 치느냐**로 갈립니다.

| 위치              | 명령                                                             | 하는 일                            |
| ----------------- | ---------------------------------------------------------------- | ---------------------------------- |
| `platform/`     | `make new PLATFORM_NAME=grover_soc`                            | 새 플랫폼                          |
| `platform/`     | `make copy_platform BEFORE=tip_quantized_cnn AFTER=grover_soc` | 복제                               |
| `<플랫폼>/`     | `make syn`                                                     | XML → RTL·SSW 생성               |
| `<플랫폼>/`     | `make sim_rtl`                                                 | 시뮬 작업방 생성                   |
| `<플랫폼>/`     | `make fpga_list`                                               | 보드 목록                          |
| `<플랫폼>/`     | `make arty-100t`                                               | 구현 작업방 생성                   |
| `<플랫폼>/`     | `make clean`                                                   | 산출물 정리                        |
| `<플랫폼>/app/` | `make new APP_NAME=grover`                                     | 새 앱                              |
| `sim_rtl/`      | `make grover.sim`                                              | 빌드 + RTL 컴파일 + 시뮬           |
| `sim_rtl/`      | `make grover.resim`                                            | 앱 지우고 다시                     |
| `sim_rtl/`      | `make grover.all`                                              | 전부 지우고 처음부터               |
| `sim_rtl/`      | `make grover.debug`                                            | 파형 남기며 시뮬                   |
| `sim_rtl/`      | `make grover.debug_init`                                       | 부팅 순간부터 파형                 |
| `sim_rtl/`      | `make compile_test`                                            | RTL 문법만 확인                    |
| `sim_rtl/`      | `make compile_test_all`                                        | 하나씩 컴파일 — 빠진 include 찾기 |
| `sim_rtl/`      | `make compile_check`                                           | 실패한 것만 추림                   |
| `imp_*/`        | `make project`                                                 | Vivado 프로젝트 생성               |
| `imp_*/`        | `make imp`                                                     | 프로젝트 + 비트스트림              |
| `imp_*/`        | `make check_imp`                                               | 구현 리포트 확인                   |
| `imp_*/`        | `make program`                                                 | 보드에 굽기                        |
| `imp_*/`        | `make printf`                                                  | UART 콘솔                          |
| `imp_*/`        | `make grover.run`                                              | 빌드 + 보드에서 실행               |

접미사 없는 `make grover` 는 `sim_rtl/` 에서는 `.sim` 과 같고, `imp_*/` 에서는 빌드만 합니다.

빌드 모드는 기본이 `debug` 이고, 뒤에 붙이거나 `rvx_each.mh` 에 박습니다.

```bash
make grover.sim BUILD_MODE=release      # debug | release | profile
```

### 1.4 시뮬레이션 결과 읽기

`make <앱>.sim` 이 끝나면 로그 끝에 이렇게 나옵니다.

```
# [RVX/START] SIM@RTL
# Hello World!
# [PROC_STATUS]  1 cores have finished @  426794000 ns
# Errors: 0, Warnings: 0
```

`[RVX/START]` 이후가 앱의 `main()` 입니다. 이 줄 앞에서 멈췄다면 앱이 아니라 플랫폼·부팅 문제입니다.
`main()` 이 return 하면 시뮬은 자동 종료됩니다.

파형은 `make <앱>.debug` 로 남기고 `make view` 로 엽니다. 뷰어는 화면이 필요하므로 이 환경에서는
열리지 않습니다 — `vsim.wlf` 를 내려받아 로컬에서 여십시오.

### 1.5 대상 보드

`make fpga_list` 로 확인합니다. 우리 보드는 **`arty-100t`**(Arty-A7-100T, `xc7a100tcsg324-1`)입니다.

```
arty-25  arty-35t  arty-50  arty-100t  edge  edge-19p  genesys2  genesys2-eb
```

RVX CLI 매뉴얼에는 지원 보드가 둘뿐이라고 적혀 있지만 이 설치본에는 여덟 개가 들어 있습니다.
매뉴얼보다 `make fpga_list` 를 믿으십시오.

### 1.6 Vivado

RVX 의 `make project` · `make imp` 가 안에서 부르는 것이 Vivado 입니다. 별도 준비 없이
`vivado` 로 바로 부르면 됩니다.

| 항목          | 값                                                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 버전          | `vivado v2026.1` (`/usr/local/bin/vivado` 래퍼가 실체 `/tools/Xilinx/2026.1/Vivado/bin/vivado` 를 부릅니다)         |
| 라이선스      | 노드락`/opt/xilinx-lic/Xilinx.lic`. `XILINXD_LICENSE_FILE` 은 `/etc/profile.d/eda-tools.sh` 에서 이미 잡혀 있습니다 |
| 라이선스 기능 | `Vivado_Synthesis` · `Vivado_Implementation` · `Vivado_Simulation` · `Vivado_Basic_Package`                    |
| 만료          | 2027-08-21                                                                                                                |
| 부품          | Artix-7 설치됨. 우리 부품`xc7a100tcsg324-1` 사용 가능 (2026-08-28 `synth_design` 실측)                                |

라이선스는 이 컨테이너 `eth0` 의 MAC(`bc2411359cb8`)에 묶여 있습니다. 컨테이너를 새로 만들어
MAC 이 바뀌면 AMD 라이선스 포털에서 새 호스트 ID 로 다시 발급받아 `/opt/xilinx-lic/` 에 넣어야
합니다. 호스트 ID 는 `cat /sys/class/net/eth0/address` 로 확인합니다.

**GUI 는 못 씁니다.** 화면이 없으므로 `-mode batch` 또는 `-mode tcl` 로만 돌립니다.

RVX 를 거치지 않고 IP 하나만 합성해 자원을 재 보고 싶을 때는 이렇게 씁니다.

```bash
cat > run.tcl <<'EOF'
read_verilog [glob ../src/*.v]
synth_design -top bbht_rvx_wrapper -part xc7a100tcsg324-1 -include_dirs {../src}
opt_design
place_design
route_design
report_utilization -file util.rpt
report_timing_summary -file timing.rpt
EOF

vivado -mode batch -nojournal -nolog -source run.tcl
```

`src/` 를 통째로 읽으면 `grover_policy_ooc_top.v` 와 `grover_policy_impl_wrapper.v`
때문에 최상위가 셋이 됩니다. `-top` 을 줬으므로 합성 자체는 되지만, 최상위를 하나로
두고 싶으면 두 파일을 빼십시오.

Main IP 만 최종 파라미터로 재는 것은 스크립트로 있습니다 —
`hardware_bram/synth/run_main_ip.sh` 가 OOC 로 합성해
`results/2026-09-08_resource_ablation_5config/` 의 기대값과 나란히 보여 줍니다.

`report_utilization` 의 BRAM36·DSP 칸이 [15.5절 자원 예산](../study_references/15_논문지도와_설계결정표.md#155-확정-플랫폼과-자원-예산)과
맞는지, 그리고 커밋된 구현 리포트
(`hardware_bram/vivado/vivado_bbht_grover_fpga/reports/route_util.rpt`)와 어긋나지
않는지 보는 것이 이 단독 합성의 목적입니다. 비트스트림까지 필요하면 `write_bitstream -force out.bit`
를 뒤에 붙이되, 핀 제약(XDC) 없이 돌리면 미배치 IO 때문에 DRC 에서 멈춥니다 — 자원만 볼 때는
`route_design` 까지면 충분합니다.

## 2. verilator — 저장소 회귀

SoC 없이 wrapper 와 Main IP 만 세워 돌립니다. RVX 시뮬은 SoC 전체를 컴파일해야 해서
무겁고, 계약과 탐색을 확인하는 데는 이쪽이 훨씬 빠릅니다. **직접 verilator 를 부를 일은
없습니다** — 두 갈래 모두 `sim/Makefile` 이 진입점입니다.

### 2.1 두 갈래의 회귀

```bash
make -C hardware_bram/sim ports lint regress driver   # 통신 계층 + 자리 채우개 (몇 초)
make -C hardware_bram/sim real                        # 우리 통신 계층 + 정본 코어
make -C hardware_bram/sim final                       # 보드 정본 통째 (src/ 만으로)
make -C hardware_bram/sim bench250                    # 250쌍 궤적 벤치

make -C hardware_dram/sim                             # DRAM 갈래 (1분 30초쯤)
make -C hardware_dram/sim equiv                       # hardware_bram 과 궤적 대조 (40초 더)
```

모든 타깃이 `gen_csr.py --check` 를 먼저 돌립니다. 생성 헤더를 손으로 고쳐 놓고 회귀만
통과시키는 일이 생기지 않게 하려는 것입니다.

**빌드 디렉터리가 `/tmp` 로 나갑니다.** 저장소 경로에 공백(`중앙대학교 학부인턴`)이 있는데
GNU Make 가 공백 있는 디렉터리에서 verilator 생성 makefile 을 돌리지 못합니다.
Makefile 이 `--Mdir /tmp/...` 로 피해 가므로 그 줄을 건드리지 마십시오.

### 2.2 verilator 를 직접 부를 때

새 테스트벤치를 세울 때만 쓰는 형태입니다.

```bash
verilator --cc -Wno-fatal --Mdir /tmp/mytb -Isrc src/bbht_rvx_wrapper.v \
          --exe tb.cpp --build -j 4 -o sim_tb
/tmp/mytb/sim_tb
```

옵션 두 개가 **빠지면 안 됩니다.**

- `-Isrc` — 헤더(`bbht_grover_csr.vh`, `grover_param.vh`)를 찾는 include 경로이자,
  **하위 모듈을 찾는 검색 경로**입니다. 모듈 이름과 파일 이름이 같아서 이 하나로 전부
  해결되고 `*.v` 를 나열할 필요가 없습니다.
- `-Wno-fatal` — 없으면 경고 몇 건 때문에 `%Error: Exiting due to N warning(s)` 로 빌드가
  죽습니다. verilator 는 기본이 "경고 하나라도 있으면 실패"입니다.

`-Wno-fatal` 로 경고를 묻으면 **선언 누락이 조용히 1비트로 잘립니다.** 다중 엔진
실험에서 16비트 신호가 그렇게 잘려 한나절을 썼습니다
([PASS2_융합과_다중엔진_탐색_실측.md](PASS2_융합과_다중엔진_탐색_실측.md) 2절).
새 배선을 넣은 뒤에는 경고 목록을 한 번 읽으십시오.

### 2.3 tb.cpp

클럭을 직접 토글하고 매번 `eval()` 을 부릅니다. **입력 포트를 전부 초기화해야 합니다** —
안 하면 X 로 시작해 결과가 의미 없어집니다. `shready` 는 1로 두어야 AHB 가 멈추지 않습니다.
리셋은 `rstnn` 입니다 — 실물 Main IP 쪽 `rstn` 과 이름이 다르고, 그 차이는 어댑터가 흡수합니다.

```cpp
#include "Vbbht_rvx_wrapper.h"
#include "verilated.h"
#include <cstdio>

int main(int argc, char** argv) {
    Verilated::commandArgs(argc, argv);
    Vbbht_rvx_wrapper* dut = new Vbbht_rvx_wrapper;

    dut->clk = 0; dut->rstnn = 0;
    dut->psel = 0; dut->penable = 0; dut->pwrite = 0;    // APB
    dut->paddr = 0; dut->pwdata = 0;
    dut->shready = 1; dut->shresp = 0; dut->shrdata = 0; // AHB 마스터가 받는 쪽

    for (int i = 0; i < 8; i++) { dut->clk = !dut->clk; dut->eval(); }
    dut->rstnn = 1;

    for (int c = 0; c < 1000; c++) {
        dut->clk = 0; dut->eval();
        dut->clk = 1; dut->eval();
    }
    printf("prdata=%08x\n", (unsigned)dut->prdata);
    delete dut;
    return 0;
}
```

### 2.4 파형

`--trace` 를 붙여 빌드하고, `tb.cpp` 에서 `VerilatedVcdC` 를 열어 매 `eval()` 뒤에 `dump()` 합니다.

```bash
verilator --cc -Wno-fatal --trace --Mdir /tmp/mytb -Isrc src/bbht_rvx_wrapper.v \
          --exe tb.cpp --build -o sim_tb
```

```cpp
#include "verilated_vcd_c.h"

Verilated::traceEverOn(true);
VerilatedVcdC* tfp = new VerilatedVcdC;
dut->trace(tfp, 99);
tfp->open("wave.vcd");
// ... 루프 안에서 eval() 뒤에
tfp->dump(main_time++);
// ... 끝나고
tfp->close();
```

VCD 는 `gtkwave` 로 봅니다. 이 환경은 화면이 없으므로 파일을 내려받아 로컬에서 여십시오.

### 2.5 iverilog 는 지금 안 씁니다

`iverilog` 12.0 과 `vvp` 가 깔려 있기는 하지만, 저장소의 회귀는 전부 verilator 로
돕니다. `hardware_*/testbench/` 에는 테스트벤치 소스만 있고 Makefile 이 없습니다 —
그 소스들은 `sim/Makefile` 이 verilator 로 물어 갑니다.

## 3. Qiskit — 골든 모델 대조

Qiskit 은 빌드 사슬에 들어가지 않습니다. RTL 이 낸 결과가 맞는지 재는 **기준자**입니다.
[18장 골든모델 검증](../study_references/18_골든모델_검증.md)의 대조 상대가 이쪽이고, 비교
대상은 AerSimulator 와 NumPy 상태벡터 둘뿐입니다. **고전 선형 스캔과 속도를 견주지
않습니다** — 에뮬레이션은 선형 스캔보다 느리고, 그 비교는 우리가 주장하려는 것과 무관합니다.

### 3.1 설치 상태

CT 200 · CT 205 두 컨테이너에 같은 판이 올라가 있습니다.

| qiskit | aer    | numpy | scipy  | matplotlib |
| ------ | ------ | ----- | ------ | ---------- |
| 2.5.2  | 0.17.2 | 2.4.6 | 1.18.0 | 3.11.1     |

가상환경 없이 `/usr/local/lib/python3.12/dist-packages` 에 그대로 넣었습니다. 그래서 어느
디렉터리에서든 `python3` 로 바로 부르면 되고, 저장소의 다른 스크립트와 같은 인터프리터를
씁니다. 시스템 파이썬이 PEP 668 로 잠겨 있어서(`/usr/lib/python3.12/EXTERNALLY-MANAGED`)
플래그가 하나 필요합니다. 컨테이너를 새로 만들면 이렇게 되살립니다.

```bash
pip3 install --break-system-packages \
    qiskit==2.5.2 qiskit-aer==0.17.2 matplotlib==3.11.1
```

numpy·scipy 는 위 셋의 의존성으로 딸려 오므로 따로 적지 않습니다. 확인은 한 줄입니다.

```bash
python3 -c "import qiskit, qiskit_aer; print(qiskit.__version__, qiskit_aer.__version__)"
```

### 3.2 오라클은 데이터에서 만듭니다

IP 가 하는 일은 메모리에 실린 16비트 데이터 전체에 술어를 적용해 조건에 맞는 인덱스를
표시하는 것입니다. Qiskit 에서 이것에 대응하는 물건은 **대각 원소가 ±1 인 대각 게이트**
하나입니다. 조건에 맞은 자리만 -1 이 됩니다.

```python
import numpy as np
from qiskit import QuantumCircuit
from qiskit.circuit.library import DiagonalGate, grover_operator

Q = 14
N = 1 << Q
rng = np.random.default_rng(0)
data = rng.integers(-32768, 32768, size=N).astype(np.int16)   # 16비트 signed

marked = np.flatnonzero(data > 32000)      # GT 술어. LT/EQ/RANGE 도 이 줄만 바뀝니다
diag = np.ones(N)
diag[marked] = -1                          # 술어를 통과한 자리만 위상 반전

oracle = QuantumCircuit(Q)
oracle.append(DiagonalGate(diag.tolist()), range(Q))
G = grover_operator(oracle)                # 오라클 + 확산을 묶은 한 번의 반복
```

`marked` 를 미리 계산한다고 해서 오라클이 답을 아는 것은 아닙니다. 술어를 데이터 **전체**에
적용한 결과일 뿐이고, 하드웨어도 같은 일을 매 반복마다 합니다. 답을 아는 오라클을 만들면
검증이 성립하지 않으니, 조건에 맞는 인덱스를 손으로 적어 넣는 식으로 바꾸지 마십시오.

### 3.3 정답 개수를 알 때

`M` 을 알면 반복 횟수가 `floor(pi/4 * sqrt(N/M))` 으로 정해집니다.

```python
from qiskit import transpile
from qiskit_aer import AerSimulator

M = len(marked)
r = int(np.floor(np.pi / 4 * np.sqrt(N / M)))

qc = QuantumCircuit(Q)
qc.h(range(Q))                             # 균등 중첩
for _ in range(r):
    qc.compose(G, inplace=True)
qc.measure_all()

sim = AerSimulator(method="statevector")
counts = sim.run(transpile(qc, sim), shots=1024).result().get_counts()
```

위 데이터에서는 `M = 221`, `r = 6` 이 나옵니다. 조건을 만족하는 인덱스가 나올 이론 확률이
0.9967 이고 1024 샷을 뽑으면 그 언저리에서 흔들립니다. transpile 0.11초, 실행 0.02초로
끝납니다. Aer 가 대각 게이트를 분해하지 않고 그대로 처리해서 회로 깊이는 26 밖에 되지
않습니다.

### 3.4 정답 개수를 모를 때 — BBHT

실제 장비가 푸는 문제는 이쪽입니다. `M` 을 모른 채 반복 횟수 상한을 1.2배씩 늘려 가며
찍고, 나온 인덱스를 술어로 직접 검산해서 틀리면 다시 돌립니다.

```python
sim = AerSimulator(method="statevector")
cache = {}

def measure_once(j, seed):
    if j not in cache:                     # 같은 j 는 회로를 재활용합니다
        c = QuantumCircuit(Q)
        c.h(range(Q))
        for _ in range(j):
            c.compose(G, inplace=True)
        c.measure_all()
        cache[j] = transpile(c, sim)
    bits = list(sim.run(cache[j], shots=1, seed_simulator=seed).result().get_counts())[0]
    return int(bits, 2)

m, lam, seed = 1.0, 6 / 5, 0
while True:
    j = int(rng.integers(0, int(m) + 1))
    seed += 1
    idx = measure_once(j, seed)
    if data[idx] > 32000:                  # 검산은 고전적으로 -- 여기가 판정의 근거입니다
        break
    m = min(lam * m, np.sqrt(N))
```

`seed_simulator` 를 반복마다 바꿔야 합니다. 고정하면 같은 `j` 에서 같은 인덱스만 계속
나와 루프가 끝나지 않습니다. 위 데이터(`M = 221`)에서 시드를 바꿔 가며 20번 돌리면 누적
반복 횟수의 중앙값이 5, 최대가 41 이었습니다. `M` 을 알 때의 `r = 6` 과 견주면 평균은
비슷한데 꼬리가 깁니다. 이 편차가 체크포인트(현 정본 K3/H3)로 줄이려는 대상이고, 무엇을 아끼는지는
[14장 다중정답과 최솟값탐색](../study_references/14_다중정답과_최솟값탐색.md)에 있습니다.

### 3.5 세 갈래 중 무엇을 쓸 것인가

같은 계산을 하는 길이 셋인데 속도가 다섯 자릿수만큼 차이 납니다. Q = 14, r = 6 에서 실측한
값입니다.

| 경로                                  | 시간       | 언제                                 |
| ------------------------------------- | ---------- | ------------------------------------ |
| `qiskit.quantum_info.Statevector(qc)` | 16~25초    | 쓰지 마십시오                        |
| `AerSimulator` + `save_statevector()` | 0.1초 안팎 | 논문·보고서에 실을 기준값            |
| NumPy 배열 직접                       | 0.1밀리초  | 시드 50개 캠페인처럼 수천 번 돌릴 때 |

`quantum_info.Statevector` 는 파이썬에서 게이트를 하나씩 곱하기 때문에 Q = 14 면 20초대로
늘어집니다. 회로가 맞는지 눈으로 볼 때나 쓰고, 수치는 Aer 에서 받으십시오.

```python
qc = QuantumCircuit(Q)
qc.h(range(Q))
for _ in range(r):
    qc.compose(G, inplace=True)
qc.save_statevector()                      # qiskit_aer 를 import 하면 생기는 메서드
sv = sim.run(transpile(qc, sim)).result().get_statevector()
```

NumPy 로 같은 것을 쓰면 열 줄이 안 됩니다. 확산은 평균을 기준으로 한 반사라서 `mean()`
한 번이면 끝나고, 행렬을 만들 필요가 없습니다.

```python
psi = np.full(N, 1 / np.sqrt(N))
for _ in range(r):
    psi *= diag                            # 오라클: 통과한 자리 부호 반전
    psi = 2 * psi.mean() - psi             # 확산: 평균 기준 반사
```

셋의 결과는 진폭 기준 `1e-13` 안에서 일치합니다. 새 골든 모델을 넣을 때 이 세 값을 함께
찍어 보면, 틀린 것이 모델인지 기준자인지 바로 갈립니다.

### 3.6 그림

matplotlib 기본 백엔드가 이미 `agg` 라 헤드리스에서도 그대로 그려집니다. 창을 띄우는 대신
파일로 떨구면 됩니다.

```python
qc.draw("mpl", filename="circ.png")
```

터미널에서 바로 볼 때는 `print(qc.draw("text"))` 입니다. 다만 Q = 14 에 반복까지 펼친 회로는
텍스트로 보기에 너무 넓으니 `G` 한 벌이나 큐비트 서너 개짜리 축소판만 그리십시오.

### 3.7 이름이 바뀐 API

Qiskit 2.x 가 클래스들을 게이트 형태로 옮기는 중이라, 인터넷 예제 상당수가 경고를 냅니다.
3.0 에서 실제로 사라지므로 지금부터 새 이름을 쓰십시오.

| 옛 이름       | 지금 쓸 것        | 비고                |
| ------------- | ----------------- | ------------------- |
| `Diagonal`    | `DiagonalGate`    | 2.1 부터 deprecated |
| `PhaseOracle` | `PhaseOracleGate` | 2.2 부터 deprecated |

`qiskit_algorithms` 는 **깔려 있지 않습니다.** `from qiskit_algorithms import Grover` 로
시작하는 예제는 이 환경에서 돌지 않습니다. qiskit 본체에서 떨어져 나간 별도 패키지라 같이
따라오지 않으니, 3.2절처럼 `grover_operator` 로 직접 조립하는 편이 낫습니다. 반복 횟수와
오라클을 우리가 쥐고 있어야 RTL 과 조건을 맞출 수 있기도 합니다.

경고를 놓치지 않으려면 오류로 승격시켜 돌립니다.

```bash
python3 -W error::DeprecationWarning your_script.py
```
