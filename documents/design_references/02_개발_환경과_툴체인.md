## 2.1 도구의 역할과 판본

도구는 역할이 셋으로 갈립니다.

| 도구 | 역할 |
|---|---|
| RVX | 플랫폼 생성부터 SoC RTL 시뮬, 합성·구현·비트스트림까지 전 과정 |
| Verilator | 저장소 회귀 전용. SoC 없이 wrapper 와 Main IP 만 빠르게 돌립니다 |
| Qiskit · NumPy | RTL 밖에서 도는 기준자. 결과가 맞는지 대조하는 데만 씁니다 |

이 환경에서 직접 확인한 판본입니다 (RVX·Verilator 2026-08-21, Vivado 2026-08-22,
Qiskit 2026-09-03, 회귀 2026-09-09).

| 도구 | 판본 | 쓰는 자리 |
|---|---|---|
| `verilator` | 5.020 | 하드웨어 트리의 `sim/` 회귀 전체 |
| `vsim` (Questa) | 2022.1_2 | RVX `make sim_rtl` (SoC 전체) |
| `vivado` | 2026.1 (노드락) | `xc7a100tcsg324-1` 합성·구현·비트스트림 |
| RISC-V GCC | RVX 동봉 | ORCA 코어용 펌웨어 |
| RVX | `/opt/rvx` 로컬 전체 설치 | 플랫폼 생성·시뮬·구현. 원격 접속 불필요 |
| `iverilog` / `vvp` | 12.0 | 설치만 되어 있고 저장소에서 쓰는 곳이 없습니다 |
| qiskit / qiskit-aer | 2.5.2 / 0.17.2 | 기준모델 대조 ([4장](04_소프트웨어_기준모델과_정답_벡터.md)) |

보드 정본 비트스트림(2026-09-07)은 Vivado 2024.2로 구웠습니다. 지금 환경은 2026.1이라 두
빌드의 비트스트림 해시를 비교할 수 없습니다([20장](20_합성_구현_비트스트림.md)).

### 환경 제약

- 헤드리스입니다. `gtkwave`, Vivado GUI, RVX `make view` 는 설치 여부와 무관하게 띄울 수
  없습니다. Vivado 는 `-mode batch` 또는 `-mode tcl` 로만 돌리고, 파형은 파일로 남겨
  내려받아 봅니다.
- 저장소 경로에 공백이 있습니다 (`중앙대학교 학부인턴`). GNU Make 가 공백 있는 디렉터리에서
  Verilator 생성 Makefile 을 돌리지 못하므로 `sim/Makefile` 이 `--Mdir /tmp/...` 로 빌드
  디렉터리를 뺍니다. 이 설정은 유지해야 합니다.

## 2.2 저장소 회귀: Verilator

`hardware_*/testbench/` 에는 테스트벤치 소스만 있고 Makefile 이 없습니다. 진입점은
`hardware_bram/sim/Makefile` · `hardware_dram/sim/Makefile`, 그리고 모델 전용 회귀가 있는
`nocheckpoint` 모델의 `sim/Makefile` 이고, Verilator 를 직접 부를 일은 새 테스트벤치를 세울 때뿐입니다.

```bash
# BRAM 갈래 (hardware_bram). 어댑터가 들어가는 타깃은 MODEL=<모델>, 기본값 K3H3_E4_M2
make -C hardware_bram/sim ports lint regress driver   # 통신 계층 + 자리 채우개 (몇 초)
make -C hardware_bram/sim real [MODEL=K4H4_E4]        # 통신 계층 + 모델 어댑터 + Main IP (몇 분)
make -C hardware_bram/sim ports-models lint-models    # 모델 열 개 어댑터 전부 (몇 분)
make -C hardware_bram/sim top                         # 최상단 bbht_bram_top (1분 30초쯤)
make -C hardware_bram/sim bench250                    # 250쌍 궤적 벤치 (20분쯤)
make -C hardware_bram/sim predicate500 console-gen    # 네 술어 x 500 (수 분)

# 체크포인트 없는 판 (nocheckpoint 모델 전용 회귀)
make -C hardware_bram/models/hardware_bram_nocheckpoint/sim                           # ports + lint + real
make -C hardware_bram/models/hardware_bram_nocheckpoint/sim predicate500 predicate500-ref equiv

# DRAM 갈래 (hardware_dram)
make -C hardware_dram/sim                                        # ports lint store prep core top (1분 30초쯤)
make -C hardware_dram/sim equiv                                  # 체크포인트 판과 궤적 대조 (40초 더)
make -C hardware_dram/sim predicate500 [AXI_STALL=1]             # AXI 메모리 모델 위 2,000 실행
```

모든 트리가 CSR 생성 헤더(`software/contract/generated/`)를 씁니다. RTL 네 곳과 테스트벤치 세
곳이 `bbht_grover_csr.vh` 를, `bbht_grover_driver.h` 가 `bbht_grover_regs.h` 를 include 하므로
헤더가 없으면 아무것도 돌지 않습니다. 체크포인트 판은 모든 타깃이 `csr:`(`gen_csr.py --check`)를,
체크포인트 없는 판은 `csr:`(생성)를 선행 조건으로 먼저 돌립니다. 생성 파이프라인은
[13장](13_CSR_레지스터와_실행_모드.md)에 있습니다.

6단계 ablation 과 K/H 단독 실험은 standalone top 틀을 쓰므로 main 에 없습니다. 태그에서
worktree 를 따로 꺼내 돌립니다. 태그 안의 폴더 이름은 옛 이름 `hardware_bram/` 그대로입니다.

```bash
git worktree add /tmp/board board-k3h3-e4-m2
make -C /tmp/board/hardware_bram/sim anchor      # publication · kh 도 같은 자리
```

### Verilator 를 직접 부를 때

새 테스트벤치를 세울 때의 형태입니다.

```bash
verilator --cc -Wno-fatal --Mdir /tmp/mytb -Isrc src/bbht_rvx_wrapper.v \
          --exe tb.cpp --build -j 4 -o sim_tb
/tmp/mytb/sim_tb
```

옵션 두 개가 빠지면 안 됩니다.

- `-Isrc`: 헤더(`bbht_grover_csr.vh`, `grover_param.vh`)를 찾는 include 경로이자 하위 모듈
  검색 경로입니다. 모듈 이름과 파일 이름이 같아서 이 하나로 해결되고 `*.v` 를 나열할 필요가
  없습니다.
- `-Wno-fatal`: 없으면 경고 몇 건으로 `%Error: Exiting due to N warning(s)` 가 나며 빌드가
  죽습니다.

`-Wno-fatal` 로 경고를 묻으면 선언 누락이 조용히 1비트로 잘립니다. 다중 엔진 실험에서
16비트 신호가 그렇게 잘려 한나절을 쓴 적이 있으니, 새 배선을 넣은 뒤에는 경고 목록을 한 번
읽으십시오.

상대경로 파일이 `-I` 디렉터리 기준으로 먼저 찾아진다는 점도 주의합니다. 체크포인트 없는 판의
`sim/Makefile` 이 자기 어댑터를 `/tmp` 로 복사해 절대경로로 넘기는 이유가 이것입니다
([21장](21_체크포인트_없는_BRAM_판.md)).

테스트벤치 C++ 는 클럭을 직접 토글하고 매번 `eval()` 을 부릅니다. 입력 포트를 전부
초기화해야 하고(안 하면 X 로 시작합니다), `shready` 는 1로 두어야 AHB 가 멈추지 않습니다.
리셋은 `rstnn` 입니다(실물 Main IP 쪽 `rstn` 과의 차이는 어댑터가 흡수합니다).

```cpp
#include "Vbbht_rvx_wrapper.h"
#include "verilated.h"
#include <cstdio>

int main(int argc, char** argv) {
    Verilated::commandArgs(argc, argv);
    Vbbht_rvx_wrapper* dut = new Vbbht_rvx_wrapper;

    dut->clk = 0; dut->rstnn = 0;
    dut->psel = 0; dut->penable = 0; dut->pwrite = 0;    // APB
    dut->paddr = 0; dut->pwdata = 0;
    dut->shready = 1; dut->shresp = 0; dut->shrdata = 0; // AHB 마스터가 받는 쪽

    for (int i = 0; i < 8; i++) { dut->clk = !dut->clk; dut->eval(); }
    dut->rstnn = 1;

    for (int c = 0; c < 1000; c++) {
        dut->clk = 0; dut->eval();
        dut->clk = 1; dut->eval();
    }
    printf("prdata=%08x\n", (unsigned)dut->prdata);
    delete dut;
    return 0;
}
```

파형이 필요하면 `--trace` 를 붙여 빌드하고, `VerilatedVcdC` 를 열어 매 `eval()` 뒤에
`dump()` 합니다. 만든 VCD 는 내려받아 로컬에서 엽니다.

```cpp
#include "verilated_vcd_c.h"

Verilated::traceEverOn(true);
VerilatedVcdC* tfp = new VerilatedVcdC;
dut->trace(tfp, 99);
tfp->open("wave.vcd");
// 루프 안에서 eval() 뒤에
tfp->dump(main_time++);
// 끝나고
tfp->close();
```

## 2.3 RVX 플랫폼

RVX 는 `/opt/rvx` 에 전부 설치되어 있습니다. 새 터미널마다 한 번 환경을 잡습니다.

```bash
source /opt/rvx/rvx_setup.sh
```

따를 예제는 `platform/tip_quantized_cnn/` 입니다. 커스텀 IP 를 `user/rtl` · `user/api` 에 두는
구조가 우리와 같습니다.

### 플랫폼 셋

BRAM 모델마다, 그리고 DRAM 갈래에 RVX 플랫폼이 하나씩 있고, 각자의
`rvx/install_to_platform.sh` 가 자기 플랫폼에 설치합니다. BRAM 모델의 설치 스크립트는 공용 설치기
[`hardware_bram/rvx/install_model.sh`](../../hardware_bram/rvx/install_model.sh) 를 부릅니다. 모델별
플랫폼 이름은 [5장 5.2절](05_하드웨어_아키텍처_개요.md#하드웨어-트리와-bram-모델) 표에 있습니다.

| 트리 | 플랫폼 | 플랫폼 정의 |
|---|---|---|
| `hardware_bram/` 의 `K3H3_E4_M2` | `bbht_grover_upgrade` | [`bbht_grover_upgrade.xml`](../../hardware_bram/models/hardware_bram_K3H3_E4_M2/rvx/bbht_grover_upgrade.xml) (가속기 100 MHz) |
| `hardware_bram/` 의 다른 모델 아홉 | `bbht_grover_<모델 소문자>` · `bbht_grover_nocheckpoint` | SoC 구성은 upgrade 와 같음 |
| `hardware_dram/` | `bbht_grover_dram` | `include_slow_dram` · `use_large_ram_manually` 추가 ([22장](22_DRAM_갈래.md)) |

```bash
hardware_bram/models/hardware_bram_K3H3_E4_M2/rvx/install_to_platform.sh
cd $RVX_MINI_HOME/platform/bbht_grover_upgrade
make syn        # XML 로부터 RTL · 시스템 소프트웨어 생성
make sim_rtl    # Questa 시뮬 작업방 생성
make imp_fpga TARGET_IMP_CLASS=arty-100t && cd imp_arty-100t_<날짜> && make imp && make bbht_console
```

설치 스크립트가 옮기는 것과 플랫폼 폴더를 처음 만드는 절차는 [17장 17.1절](17_보드_운용.md#171-플랫폼-설치와-생성)에
있습니다. `hardware_bram/rvx/bbht_grover_user_region.vh.generated` 는 RVX `make syn` 이 뽑은 빈 템플릿이고,
RVX 가 IP 를 바꿨을 때 우리 user region 과 대조하는 용도입니다. 합성에는
`src/bbht_grover_user_region.vh` 를 씁니다.

### 새 플랫폼을 처음부터 만들 때

```bash
cd $RVX_MINI_HOME/platform
make copy_platform BEFORE=tip_quantized_cnn AFTER=grover_soc   # 가속기 IP 예제 복제
cd grover_soc && vim grover_soc.xml                             # IP 인스턴스와 파라미터
make syn
cd app && make new APP_NAME=grover && cd ..                     # 앱 뼈대
make sim_rtl && (cd sim_rtl && make grover.sim)                 # RTL 시뮬
make arty-100t && cd imp_arty-100t_<날짜> && make imp           # 합성·구현
```

### 명령은 어디서 치느냐로 갈립니다

| 위치 | 명령 | 하는 일 |
|---|---|---|
| `platform/` | `make new PLATFORM_NAME=<이름>` · `make copy_platform BEFORE=.. AFTER=..` | 새 플랫폼 · 복제 |
| `<플랫폼>/` | `make syn` | XML → RTL · SSW 생성 |
| `<플랫폼>/` | `make sim_rtl` · `make arty-100t` | 시뮬 작업방 · 구현 작업방 생성 |
| `<플랫폼>/` | `make fpga_list` · `make clean` | 보드 목록 · 산출물 정리 |
| `<플랫폼>/app/` | `make new APP_NAME=<앱>` | 새 앱 |
| `sim_rtl/` | `make <앱>.sim` | 빌드 + RTL 컴파일 + 시뮬 |
| `sim_rtl/` | `make <앱>.resim` · `make <앱>.all` | 앱만 다시 · 전부 처음부터 |
| `sim_rtl/` | `make <앱>.debug` · `make <앱>.debug_init` | 파형 남기며 · 부팅 순간부터 파형 |
| `sim_rtl/` | `make compile_test` · `compile_test_all` · `compile_check` | RTL 문법만 · 하나씩(빠진 include 찾기) · 실패한 것만 |
| `imp_*/` | `make project` · `make imp` · `make reimp` · `make check_imp` | 프로젝트 · 비트스트림 · 다시 · 리포트 확인 |
| `imp_*/` | `make program` · `make program_flash` | 보드에 굽기 · SPI 플래시에 굽기 |
| `imp_*/` | `make printf` · `make <앱>.run` | UART 콘솔 · 빌드 후 보드에서 실행 |

접미사 없는 `make <앱>` 은 `sim_rtl/` 에서는 `.sim` 과 같고, `imp_*/` 에서는 빌드만 합니다.
`make download` 라는 타깃은 없습니다. 빌드 모드는 기본 `debug` 이고
`make <앱>.sim BUILD_MODE=release` 처럼 바꿉니다(`debug` · `release` · `profile`).

`make fpga_list` 에는 `arty-100t` 를 포함해 여덟 보드가 나옵니다. RVX CLI 매뉴얼은 두 보드만
적고 있지만 설치본을 믿으십시오. 우리 보드는 `arty-100t` 입니다.

### SoC 시뮬 결과 읽기

`make <앱>.sim` 이 끝나면 로그 끝에 이렇게 나옵니다.

```
# [RVX/START] SIM@RTL
# Hello World!
# [PROC_STATUS]  1 cores have finished @  426794000 ns
# Errors: 0, Warnings: 0
```

`[RVX/START]` 이후가 앱의 `main()` 입니다. 이 줄 앞에서 멈췄다면 앱이 아니라 플랫폼·부팅
문제입니다. `main()` 이 return 하면 시뮬이 끝납니다.

### SoC 시뮬에서 콘솔 앱을 돌리는 법

`bbht_console` 의 UART 판은 SoC 시뮬에서 `read_line()` 에 멈춥니다. RVX 의 `ncsim_printf.v` 가
`uart_tx` 를 1로 묶어 두어 명령을 보낼 쪽이 없기 때문입니다. 그래서
[`rvx_each.mh`](../../hardware_bram/firmware/bbht_console/rvx_each.mh) 가 RTL 시뮬 빌드
(`TARGET_IMP_CLASS=rtl`)에만 `-DBBHT_CONSOLE_SCRIPT` 를 넣고, 콘솔은 명령을 컴파일 시점
배열에서 읽습니다. 보드 빌드 ELF 는 바이트 단위로 그대로입니다. 스크립트는
`BBHT_SCRIPT=<헤더>` 로 고릅니다.

```bash
(cd $RVX_MINI_HOME/platform/bbht_grover_upgrade/sim_rtl && make bbht_console.sim)   # 3분쯤
grep -c BBHT_CONSOLE_SCRIPT $RVX_MINI_HOME/platform/bbht_grover_upgrade/sim_rtl/rvx_app_build.log
```

두 가지를 지킵니다.

- 이 정의를 명령줄의 `DEFINE_CFLAGS` 로 넘기지 마십시오. `make bbht_console.sim` 이 시뮬 직전에
  앱을 다시 빌드하면서 빠지고, UART 판이 첫 명령을 기다리며 멈춥니다. 위 grep 이 0이면
  스크립트 모드가 아닙니다. 이 증상을 한동안 "원인 미확인 멈춤" 으로 잘못 기록했고, 진단
  순서는 [soc_rtl_console evidence](../../hardware_bram/models/hardware_bram_K3H3_E4_M2/results/2026-09-16_soc_rtl_console/evidence.md)
  에 남겼습니다.
- 스크립트만 바꿔 다시 돌릴 때는 앱 빌드 폴더(`app/bbht_console/rtl.debug`)를 지우십시오.
  `BBHT_SCRIPT` 는 컴파일 매크로라 make 가 바뀐 것을 모르고 앞서 빌드한 오브젝트를 씁니다.
  `rvx_app_build.log` 에 고른 스크립트 파일 이름이 찍혔는지 확인합니다.

응답 검사 절차는 [16장 16.5절](16_검증_체계.md#165-3층-soc-전체-rtl-시뮬)에 있습니다.

## 2.4 Vivado

RVX 의 `make project` · `make imp` 가 안에서 부르는 것이 Vivado 입니다. 따로 준비할 것 없이
`vivado` 로 바로 부릅니다.

| 항목 | 값 |
|---|---|
| 버전 | `vivado v2026.1` (`/usr/local/bin/vivado` 래퍼가 `/tools/Xilinx/2026.1/Vivado/bin/vivado` 를 부름) |
| 라이선스 | 노드락 `/opt/xilinx-lic/Xilinx.lic`. `XILINXD_LICENSE_FILE` 은 `/etc/profile.d/eda-tools.sh` 에서 잡힘 |
| 라이선스 기능 | `Vivado_Synthesis` · `Vivado_Implementation` · `Vivado_Simulation` · `Vivado_Basic_Package` |
| 만료 | 2027-08-21 |
| 부품 | Artix-7 설치됨. `xc7a100tcsg324-1` 사용 가능 (2026-08-28 `synth_design` 실측) |

라이선스는 이 컨테이너 `eth0` 의 MAC(`bc2411359cb8`)에 묶여 있습니다. 컨테이너를 새로 만들어
MAC 이 바뀌면 AMD 라이선스 포털에서 새 호스트 ID 로 다시 발급받아 `/opt/xilinx-lic/` 에
넣어야 합니다. 호스트 ID 는 `cat /sys/class/net/eth0/address` 로 확인합니다.

### IP 하나만 합성해 자원을 잴 때

```bash
cat > run.tcl <<'EOF'
read_verilog [glob ../src/*.v]
synth_design -top bbht_rvx_wrapper -part xc7a100tcsg324-1 -include_dirs {../src}
opt_design
place_design
route_design
report_utilization -file util.rpt
report_timing_summary -file timing.rpt
EOF

vivado -mode batch -nojournal -nolog -source run.tcl
```

`src/` 를 통째로 읽으면 `grover_policy_ooc_top.v` 와 `grover_policy_impl_wrapper.v` 때문에
최상위 후보가 셋이 됩니다. `-top` 을 줬으니 합성은 되지만, 최상위를 하나로 두려면 두 파일을
빼십시오. 핀 제약 없이 `write_bitstream` 까지 가면 미배치 IO 때문에 DRC 에서 멈추므로, 자원만
볼 때는 `route_design` 까지면 충분합니다.

Main IP 만 최종 파라미터로 재는 것은 스크립트로 있습니다.

```bash
hardware_bram/synth/run_main_ip.sh      # 2분쯤
```

결과를 [자원 ablation 묶음](../../hardware_bram/results/2026-09-08_resource_ablation_5config/evidence.md)
의 기대값과 나란히 보여 줍니다([20장 20.3절](20_합성_구현_비트스트림.md#203-main-ip-자원-재측정)).

## 2.7 증상별 대처

| 증상 | 대처 |
|---|---|
| Vivado `valid license was not found` | `echo $XILINXD_LICENSE_FILE` 가 `/opt/xilinx-lic` 인지, 호스트 ID(MAC)가 바뀌지 않았는지 (2.4절) |
| Vivado GUI · `make view` · `gtkwave` 가 안 뜸 | 헤드리스. `-mode batch` 로 돌리고 `vsim.wlf` · VCD 는 내려받아 로컬에서 엶 |
| RVX 명령이 변수를 못 찾음 | `source /opt/rvx/rvx_setup.sh` |
| `vsim` 의 `ADDR_NO_RANDOMIZE failed` 경고 | 무시해도 됩니다 |
| SoC 시뮬에서 콘솔이 첫 명령을 기다리며 멈춤 | 스크립트 모드가 빌드에 안 들어갔습니다 (2.3절) |
| Verilator 가 경고만 있는데 종료 코드 1 | `-Wno-fatal` |
| Verilator `Cannot find include file: grover_param.vh` | `-I` 로 `src` 를 안 넣었습니다 |
| Verilator 산출물이 옛 판이라 이상함 | `make -C hardware_bram/sim clean` (빌드 디렉터리는 `/tmp`) |
| pip 가 `externally-managed-environment` 로 거부 | `--break-system-packages` (2.5절) |
| `ModuleNotFoundError: qiskit_algorithms` | 안 깔려 있습니다. `grover_operator` 로 직접 조립 |
| `DeprecationWarning: Diagonal` · `PhaseOracle` | `DiagonalGate` · `PhaseOracleGate` 로 ([4장 4.6절](04_소프트웨어_기준모델과_정답_벡터.md#46-qiskit-과-numpy-로-대조하기)) |
