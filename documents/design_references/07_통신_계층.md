# 7장. 통신 계층

> [← 6장 데이터 표현과 메모리 맵](06_데이터_표현과_메모리_맵.md) · [문서 지도](00_문서_지도.md) · [8장 Main IP 최상위와 BBHT 제어 →](08_Main_IP_최상위와_BBHT_제어.md)

---

통신 계층은 네 파일입니다. RVX 가 만든 포트를 Main IP 에 잇고 CSR 접근과 데이터 적재를
처리합니다.

| 파일 | 역할 |
|---|---|
| [`bbht_rvx_wrapper.v`](../../hardware_bram/src/bbht_rvx_wrapper.v) | 셋을 묶는 결선판 |
| [`bbht_grover_mmio.v`](../../hardware_bram/src/bbht_grover_mmio.v) | APB 슬레이브 · CSR 38개 |
| [`bbht_ahb_loader.v`](../../hardware_bram/src/bbht_ahb_loader.v) | AHB 마스터 · 데이터셋 DMA |
| [`bbht_grover_core_adapter.v`](../../hardware_bram/models/hardware_bram_K3H3_E4_M2/src/bbht_grover_core_adapter.v) | 계약 이름·리셋 차이 흡수 |

DRAM 갈래의 mmio · loader 는 이 폴더의 것과 바이트 동일하고, 체크포인트 없는 판은 이 폴더의
통신 계층을 그대로 씁니다.

---

## 7.1 wrapper 의 제어 로직

```
i_grover_csr (APB slave)  → bbht_grover_mmio  → Main IP 설정·상태
i_grover_dma (AHB master) ← bbht_ahb_loader   → Main IP loader 포트
```

대부분은 배선이고, wrapper 가 직접 판단하는 것은 셋입니다.

1. start 수락 조건 ([5장 5.6절](05_하드웨어_아키텍처_개요.md#56-시작-명령-수락-조건))
2. `checkpoint_auto_enable = burst_enable && auto_shot`
3. manual 체크포인트 입력 전부 0 tie-off (production 설정)

두 번째 규칙 때문에 `auto_shot = 0` 인 수동 모드에서는 체크포인트가 걸리지 않습니다. 수동
모드는 펌웨어가 `j` 를 지정하는 검증용 경로라, 정책 엔진이 끼어들면 무엇을 재는지 알 수 없게
됩니다. 세 번째 규칙은 계획의 출처를 하나로 두려는 것입니다. 자동 경로와 manual 경로를 동시에
열면 정책 통계가 의미를 잃습니다.

클럭은 `gclk_accel`(100 MHz) 하나입니다. CDC 는 RVX 계층이 처리하므로 이 모듈에는 넣지
않습니다([5장 5.3절](05_하드웨어_아키텍처_개요.md#53-클럭과-리셋-소유권)).

## 7.2 mmio 의 레지스터 접근

APB 슬레이브를 받아 레지스터 파일로 만듭니다. 주소 맵의 정본은
[`bbht_grover_csr.json`](../../software/contract/bbht_grover_csr.json)이고, mmio 가 include 하는
`bbht_grover_csr.vh` 가 그 JSON 에서 생성됩니다. RTL 에는 오프셋 숫자를 직접 적지 않으며
`gen_csr.py --check` 의 세 번째 검사가 이것을 지킵니다([13장](13_CSR_레지스터와_실행_모드.md)).

| 성격 | 뜻 |
|---|---|
| `RW` | 설정. 저장되고 값이 출력 와이어로 상시 나갑니다 |
| `W1P` | 명령. 저장 공간이 없고 쓰면 1사이클 펄스만 나갑니다. 읽으면 0. 쓰는 데이터는 무시하고 쓰는 행위 자체가 명령입니다 |
| `RO` | 상태. 저장하지 않고 코어가 내보내는 와이어를 읽기 응답에 실어 보냅니다 |
| `RPOP` | `FIFO_DATA` 하나뿐. 읽기 완료 자체가 pop 이라 별도 POP 레지스터가 없습니다 |

`pready` 는 상수 1이고 대기 상태가 없습니다. 정렬되지 않은 접근과 미할당 주소는 `pslverr` 로
떨어집니다. 디코드는 `rpaddr[11:0]` 만 보므로 NoC 가 전체 주소를 주든 오프셋을 주든 동작합니다.

`done` 은 Main IP 에서 1클록 펄스로 나오므로 mmio 가 `done_sticky` 로 잡아 둡니다. 이것을
지우는 것은 `COMMAND` 쓰기뿐입니다. `STATUS` 를 읽어도, 설정을 바꿔도 안 지워집니다.

## 7.3 loader 의 사전 검사

시스템 SRAM 의 signed 16비트 배열을 AHB 마스터로 읽어 Main IP 의 generic loader 포트
(`data_wr_en` / `data_wr_addr` / `data_wr_data`)로 넘깁니다. 전송은 32비트 AHB SINGLE read,
single outstanding 이고 워드 매핑은 리틀엔디안입니다.

```
word[k][15:0]  -> data[2k]
word[k][31:16] -> data[2k+1]
```

`data_count` 가 홀수면 마지막 워드의 상위 16비트는 쓰지 않습니다. 버스트로 올리는 것은 DMA 가
실제 병목임이 측정된 뒤에 볼 일이고, 지금은 Q14 전체 적재가 246 us 인데 탐색 한 번이 그보다
훨씬 깁니다([6장 6.8절](06_데이터_표현과_메모리_맵.md#68-시스템-sram-과-적재)).

### 시작 전 검사 네 가지

하나라도 걸리면 전송을 시작하지 않고 오류 비트만 세웁니다.

| 검사 | 조건 | 오류 비트 |
|---|---|---|
| 정렬 | `data_addr[1:0] == 0` | `align_error` |
| 개수 | `1 <= data_count <= N` | `count_error` |
| 범위 | `[data_addr, data_addr + 4*words)` 가 SRAM 안 | `range_error` |
| 상태 | Main IP 가 busy 가 아닐 것 | `busy_error` |

배열이 일부만 적재된 상태에서 오라클을 돌리면 경고 없이 그럴듯한 오답이 나옵니다. 결과만
보고는 원인을 찾기 어려워서 전송 전에 설정을 검사합니다. 전송 중 AHB 응답 오류는
`resp_error`, 완료는 `dma_done_sticky` 로 나옵니다([13장 13.6절](13_CSR_레지스터와_실행_모드.md#136-dma_status-0x060)).

## 7.4 어댑터

계약 이름 `bbht_grover_core` 와 실물 모듈 `bbht_grover_main_ip`, 리셋 이름(`rstnn` ↔ `rstn`)
사이를 잇는 래퍼입니다. 포트 61개는 1:1이고 폭 변환도 논리도 없습니다. K·H·E·M 파라미터의
기본값이 여기 있습니다([8장 8.2절](08_Main_IP_최상위와_BBHT_제어.md#82-컴파일-파라미터-8개)).

배선만 하므로 논리가 생기지 않습니다. 2026-09-16 구현의 계층 리포트에서 어댑터와 그 안의
Main IP 가 같은 LUT 수를 갖습니다.

`bbht_bram_top` 은 어댑터를 거치지 않고 Main IP 에 직접 연결됩니다
([5장 5.2절](05_하드웨어_아키텍처_개요.md#52-모듈-계층과-파일-지도)).

## 7.5 계약만 보고 쓴 구현과 실물의 대조

통신 계층 RTL 은 인수인계 문서의 계약(§1.4 CSR 맵, §1.5 비트 정의, §3.3 포트, §3.4 Main IP
인터페이스, §3.5 동작)만 보고 쓴 별도 구현이었습니다. 실물 Main IP 가 들어오면서 해석이 갈릴 수
있던 자리를 이렇게 정리했습니다.

| # | 항목 | 우리 구현 | 실물과 대조한 결과 |
|:-:|---|---|---|
| 1 | `pending_valid` 의 의미 | mmio 의 `done_sticky`. 직전 완료가 안 읽힌 상태에서 새 start 를 막음 | 계약에 정의가 없어 우리 해석을 유지. T1~T9 가 이 의미로 고정 |
| 2 | `done` / `enum_done` 이 펄스인가 레벨인가 | 상승 에지로 latch. 어느 쪽이든 같게 동작 | 실물이 1클록 펄스. 그대로 동작 |
| 3 | 코어 모듈 이름 | 계약 이름 `bbht_grover_core` | 실물은 `bbht_grover_main_ip`. 어댑터가 흡수 |
| 4 | `search_busy` | 계약에 없어서 `busy & ~load_busy` 로 유도 | 실물도 따로 안 내보냄. 유도 유지 |
| 5 | `clk` / `rstnn` 이름 | 계약표가 적지 않아 RVX 관례를 따름 | 이름·리셋 차이도 어댑터가 흡수 |
| 6 | AHB 세션당 사이클 | 워드당 3사이클 (SINGLE + 16비트 쓰기 2회) | 정본 통신 계층과 같은 TB 에서 같은 사이클 |
| 7 | `rpaddr` 가 전체 주소인가 오프셋인가 | `rpaddr[11:0]` 만 디코드 | 보드 E2E 로 확인 |

보드에 구운 통신 계층은 PJK 판(wrapper 가 Main IP 를 어댑터 없이 직접 물고, mmio 가 오프셋을
localparam 으로 적음)이었고 지금 main 은 우리 판입니다. 두 판의 CSR 오프셋 표는 38개가 전부
일치하고, 옛 판은 태그 `board-k3h3-e4-m2` 에 있습니다. 두 판이 같은 보드에서 같은 결과를 낸다는
것은 [18장](18_보드_확인과_실측.md)에서 확인합니다.

## 7.6 통신 계층 검증

| 묶음 | 대상 | 무엇을 |
|---|---|---|
| T1~T9 | [`tb_bbht_rvx.v`](../../hardware_bram/testbench/tb_bbht_rvx.v) | CSR 라운드트립, W1P 펄스, `rpslverr`, DMA 정상/거절, Single 결과, `done_sticky` 클리어 규칙, 열거 FIFO read-to-pop |
| D1~D11 | [`tb_driver.cpp`](../../hardware_bram/testbench/tb_driver.cpp) | 실제 펌웨어 드라이버 C 코드를 그대로 컴파일해 RTL 에 붙임. 오프셋 하나나 폴링 순서가 틀리면 여기서 잡힘 |
| H1~H15 | [`tb_bbht_bram_top.v`](../../hardware_bram/testbench/tb_bbht_bram_top.v) | 최상단에 APB 로 호스트 순서를 흉내 내고 Q14 전체 적재, NORMAL/CKPT 궤적 비교, 열거까지 |

`CORE=stub` 이면 Main IP 자리에 선형 스캔 자리 채우개
([`bbht_grover_core_stub.v`](../../hardware_bram/testbench/bbht_grover_core_stub.v))를
넣습니다. 이때 통과는 통신 계층이 계약을 지킨다는 뜻이지 탐색이 맞다는 뜻이 아니므로 탐색
결과를 인용하면 안 됩니다. `CORE=real` 이면 어댑터를 거쳐 실물 Main IP 를 뭅니다.

두 통신 계층 판(보드 정본과 현재 판)이 같은 테스트벤치에서 T1~T9 · D1~D11 을 모두 통과했고,
D5 단일 탐색 사이클이 63,963 으로 같았습니다. 포트 배선 자체는 `check_ports.py` 가 wrapper
19신호 + core 61신호를 대조합니다([16장 16.2절](16_검증_체계.md#162-0층-포트-계약)).
