## 4.2 세 계층의 기준 모델

| 계층 | 위치 | 무엇을 확인하나 |
|---|---|---|
| Float64 상태벡터 | [`models/numpy_model/`](../../software/models/numpy_model/) | 알고리즘이 맞는지. 고정소수점 영향이 없는 기준 |
| Qiskit Aer | [`models/qiskit_model/`](../../software/models/qiskit_model/) | 같은 회로를 독립 구현으로 확인 |
| Q1.22 bit-exact | [`models/rtl_reference_model/`](../../software/models/rtl_reference_model/) | RTL 과 같은 수가 나오는지 |

| 파일 | 역할 |
|---|---|
| `models/common/final_hardware_contract.py` | Q14 · P32 · Q1.22, CSR 오프셋(`CSR_OFFSETS`)과 입력 범위, 실행 모드(`RUN_MODES`), 체크포인트 상수 |
| `models/common/benchmark_dataset.py` | M 별 공식 데이터셋 생성·검증, 오라클 타겟 마스크, 술어별 데이터셋 규칙 `generate_predicate_image` |
| `models/common/bbht_control_semantics.py` | BBHT `m` 경계, 논리 예산, attempt · FIFO 의미 검사 |
| `models/common/model_config.py` · `result_records.py` · `trace_recorder.py` | 실험 설정 · 결과 자료형 · 오라클 전후와 확산 후 상태 기록 |
| `models/numpy_model/numpy_grover_backend.py` | Float64 오라클 · 확산 상태벡터 계산 |
| `models/qiskit_model/qiskit_grover_backend.py` | Qiskit Aer 로 requested-j 회로 준비·실행 |
| `models/qiskit_model/bbht_qiskit_runner.py` | 같은 J-LFSR · 측정 규칙으로 NumPy/Qiskit BBHT 수행 |
| `models/rtl_reference_model/fixed_point_statevector.py` | RTL Q1.22 산술, LFSR, 측정의 bit-exact 기준 |
| `models/rtl_reference_model/checkpoint_bbht_model.py` | BBHT · 열거 실행 기준. Normal · K4/H4 · K3/H3 · DRAM all-j 정책 |

### RTL 기준 모델이 재현하는 범위

| 재현함 | 재현 안 함 |
|---|---|
| Q1.22 산술 (포화 · round-even 포함) | `cycle_count` |
| J-LFSR 과 7스텝 점프 타이밍 | 정책 풀이 지연 |
| 측정 난수(xorshift64)와 정수 CDF | plan FIFO 대기 |
| K3/H3 정책의 결정 규칙 | E4 · M2 의 사이클 효과 |
| 물리 반복 수 `actual_grover_iterations` | |

오른쪽은 하드웨어 타이밍이라 일부러 빼 두었습니다. 정책 지연과 파이프라인 대기까지 흉내 내면
RTL 과 독립된 검증이라는 의미가 약해집니다. 사이클은 RTL 시뮬이나 보드에서 인용합니다.

모델은 CSR 모드 이름(`CKPT_SINGLE` 등) 대신 정책 이름으로 부릅니다. `RUN_MODES` 에
`K3H3_*` · `K3H3_E4_M2_*` · `K4H4_*` · `K4H8_*` 가 있고 `CKPT_*` 는 없습니다.
`checkpoint_bbht_model.py` 는 `mode="K4H8"` 을 옛 K4/H4 정책으로, `"K3H3_E4_M2"` 를 K3/H3 로
옮겨 받습니다. 이름이 갈라진 이유는 [1장 1.4절](01_프로젝트_개요.md#14-최종-구성-k3h3-e4-m2)에 있습니다.

`DRAM_ALL_J` 도 정책 모델로 들어 있습니다. DRAM 갈래([22장](22_DRAM_갈래.md))의 발상을
알고리즘 수준에서 비교하려는 것이고 DRAM 전송 지연은 모델링하지 않았습니다.

### 열거를 모델로 돌리는 법

`enum_enable=True` 면 `run_configured()` 가 열거로 가고, `burst_enable=True` 면 K3/H3 체크포인트
정책을 씁니다.

```python
import sys
for sub in ("common", "rtl_reference_model"):
    sys.path.insert(0, f"software/models/{sub}")

from benchmark_dataset import build_controlled_v098_dataset
from checkpoint_bbht_model import V098AutomaticCore

dataset = build_controlled_v098_dataset(
    predicate_mode="EQ", data_count=16384, target_count=4,
    enum_enable=True, burst_enable=True, fail_repeat_limit=3)
result = V098AutomaticCore(dataset, dataset.config).run_configured(max_results=256)
```

## 4.3 Common500 비교 실험

보드와 같은 500 워크로드를 백엔드 여덟에 걸어 4,000행을 냅니다.

| 축 | 값 |
|---|---|
| M (타겟 수) | 1, 4, 16, 64, 256 |
| 시드 | M 마다 공식 로스터 100쌍 |
| 워크로드 | 총 500 |
| 데이터셋과 오라클 | 보드와 같은 5개 데이터셋, `EQ` |
| 소프트웨어 backend | NumPy, Qiskit Aer, Fixed Normal, K4/H4, K3/H3 |
| FPGA backend | Normal, K4/H4, K3/H3-E4-M2 (2026-09-08 보드 실측 CSV, 고치지 않고 합침) |

### 다시 돌리기

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r software/requirements.txt
bash software/experiments/common500_benchmark/run_full_benchmark.sh
bash software/experiments/common500_benchmark/check_benchmark_status.sh    # 진행 상황
```

스크립트는 자기 위치를 기준으로 경로를 잡으므로 저장소 어디서 불러도 됩니다. `python` 을
부르므로 가상환경을 켜 둔 상태여야 하고, NumPy · Aer 스레드는 1로 고정합니다. 중간에
끊겨도 같은 명령을 다시 부르면 `software_resume_records.jsonl` 을 읽고 끝난 backend 를
건너뜁니다.

### 정합성 결과

비교는 짝을 지어 합니다. NumPy · Qiskit 은 float64 측정이라 Q1.22 쪽과 궤적이 같을 이유가
없으므로 둘끼리만 맞대고, 고정소수점 모델은 같은 정책의 보드 구성과 맞댑니다.

| 검사 | 비교 필드 | 결과 |
|---|---|---:|
| NumPy ↔ Qiskit | `result_index` · `trial_count` · `L_BBHT` | 500/500 |
| Fixed Normal ↔ 보드 Normal | 위 셋 + `actual_grover_iterations` | 500/500 |
| K4/H4 모델 ↔ 보드 K4/H4 | 논리 셋 / 물리 반복 | 500/500 / 500/500 |
| K3/H3 모델 ↔ 보드 K3/H3-E4-M2 | 논리 셋 / 물리 반복 | 500/500 / 500/500 |
| 보드 세 구성끼리 | 논리 셋 | 500/500 |

체크포인트는 논리 결과를 바꾸면 안 되고, 같은 정책이면 모델과 보드의 물리 반복 수도 같아야
합니다. 두 조건이 모두 500/500 입니다.

### 시간은 측정 경계가 서로 다릅니다

| backend | 무엇을 쟀나 |
|---|---|
| NumPy | 상태벡터 계산 코어만 |
| Qiskit | Aer 실행만 (회로 build · transpile 은 원시 결과의 별도 열) |
| 고정소수점 모델들 | 파이썬 벽시계 |
| FPGA | 보드의 명령 발행부터 결과까지. DMA 적재 제외 |

FPGA 구성끼리의 배수만 성능 주장에 씁니다(M = 1 에서 Normal 대비 9.192x, 전체 7.626x).
서버 소프트웨어와 보드의 절대시간 비율은 플랫폼과 측정 경계가 달라 참고값입니다. 같은 칩
위의 대조군은 ORCA 1코어 기준선이고, 그 배수에 붙일 단서는
[1장 1.5절](01_프로젝트_개요.md#15-성능-지표와-인용-기준)에 있습니다.

## 4.4 Predicate500 기댓값

Common500 은 EQ 하나입니다. 같은 모양(M 다섯 × 공식 시드 100쌍)을 LT · GT · EQ · RANGE 에 각각
건 2,000 워크로드의 기댓값을 `experiments/predicate500_benchmark/` 가 만듭니다. EQ 500개는
Common500 과 데이터셋·시드가 바이트 단위로 같고, 기댓값이 보드 500런 실측과 네 축 모두
500/500 같습니다.

```bash
python3 software/experiments/predicate500_benchmark/run_predicate500_golden.py   # 30초쯤
```

- Q1.22 bit-exact 모델(`V098AutomaticCore`)이 NORMAL · K3H3 · DRAM_ALL_J 셋 모드로 돌리고, 논리
  궤적이 셋 모드에서 같은지 생성기가 스스로 확인합니다.
- DRAM 의 물리 반복은 열이 하나 더 있습니다(`actual_iter_dram_session`). DRAM 표가 적재 사이에
  살아 있어서 한 데이터셋에서 시드를 차례로 돌면 앞 시드가 채운 슬롯을 뒤 시드가 씁니다. 이것을
  재현하려고 `run_single` 에 `checkpoint=` 인자를 더했습니다.
- 결과는 `expected/predicate500_expected.csv`(2,000행)와 `predicate500_datasets.csv`(20개)이고,
  보드 자동 테스트와 RTL 벤치가 이 둘을 읽습니다([19장](19_Predicate500_자동_테스트.md)).

## 4.5 RTL 정답 벡터

시뮬레이션 회귀가 직접 물고 가는 기대값입니다. [`software/rtl_vectors/`](../../software/rtl_vectors/).

### requested-j bit-exact 256케이스

`requested_j_bit_exact/requested_j_bit_exact_256_cases.zip`: 방향성 28개(`dir_*`), 앵커
1개(`anchor_*`), 무작위 227개(`rnd_*`). 케이스마다 폴더 하나입니다.

| 파일 | 내용 |
|---|---|
| `config.json` | 술어 · 임계값 · `DATA_COUNT` · `j_target` 과 프로파일(Q14 · P32 · F22 · AMP_W 23) |
| `data_signed16.hex` · `data_ahb_words.hex` · `data_memory_image.hex` | 같은 데이터셋의 세 표현 (인덱스 순 · AHB 워드 · P32 메모리 이미지) |
| `target_mask_p32.hex` | 오라클 타겟 마스크 |
| `initial_amp.hex` | 초기 Q1.22 진폭 |
| `iter_###_after_oracle.hex` · `iter_###_row_partial_sum.hex` · `iter_###_after_diffusion.hex` | 반복별 중간값 (FULL trace 56케이스만) |
| `expected_final_amp.hex` · `expected_core.json` | 최종 진폭과 결과 · 물리 반복 · 포화 횟수 · 진폭 해시 |

검증 범위는 수동 코어 산술로 한정됩니다. `expected_core.json` 의 `scope` 가
`MANUAL_CORE_BIT_EXACT` 이고, 자동 BBHT 의 J 난수 · 측정 난수 · 정책 텔레메트리 · `cycle_count`
는 이 벡터의 주장에서 빠져 있습니다(`excluded_from_claim`). 그쪽은 Common500 이 맡습니다.
단계별 비교 순서는 [6장 6.9절](06_데이터_표현과_메모리_맵.md#69-정답-벡터와-비교-순서)에 있습니다.

### 열거 두 방식

| 폴더 | 뜻 |
|---|---|
| `enumeration/software_reload/` | 찾은 값을 비타겟으로 바꾸고 데이터셋을 다시 적재 |
| `enumeration/projected_mask_mem/` | 하드웨어 found-mask 방식 (최종 RTL 이 채택) |

두 방식에 같은 다섯 케이스(`q14_eq_m1` · `q14_range_m4_pad50` · `q14_gt_m8_pad75` · `q14_lt_m0` ·
`q16_eq_m2`)가 있고, 케이스마다 다음을 비교합니다.

| 파일 | 뜻 |
|---|---|
| `data.hex` | signed16 데이터셋 |
| `config.json` | Q, 술어, 임계값, `DATA_COUNT`, 시드, backend |
| `expected_result.json` | 결과 목록, 샷, 반복 수, 종료 사유 |
| `round_*_mask_before.hex` · `round_*_mask_after.hex` | 라운드 전후 found mask. 워드는 `row = index>>5`, `bit = index&31` |

`q16_eq_m2` 는 폐기된 Q16 확장의 기록이므로 Q14 보드 구현의 검증 근거로 쓰지 않습니다.

### 벤치 워크로드 생성기

| 생성기 | 자극 |
|---|---|
| [`dump_bench_workload.py`](../../software/rtl_vectors/tools/dump_bench_workload.py) | `bench250` · `bench500` (`--seeds 50|100`) |
| `dump_predicate500_workload.py` | Predicate500 RTL 벤치. 데이터셋 해시를 기댓값과 대조 |

`dump_bench_workload.py` 는 데이터셋을 다시 계산하지 않고 `experiments/.../inputs/` 에서
복사하며, 돌 때마다 해시 · 로스터 · 부분집합 관계(250 이 500 의 부분집합)를 스스로 검사합니다.
보드 벤치가 쓴 데이터셋 다섯 개는 `experiments/common500_benchmark/inputs/datasets/` 와
`hardware_bram/firmware/bbht_paper_bench/tools/reference_dataset/` 에 sha256 이 같은
채로 있고, 시드 로스터 100쌍도 `inputs/official_board_seed_roster.h` 와
`hardware_bram/results/2026-09-08_publication_6stage/seeds.csv` 에 같은 값으로 있어서
numpy 없이 복사만 합니다.

## 4.6 Qiskit 과 NumPy 로 대조하기

Qiskit 은 빌드 사슬에 들어가지 않습니다. 새 골든 모델을 넣거나 결과가 이상할 때 손으로
대조하는 기준자입니다. 비교 대상은 AerSimulator 와 NumPy 상태벡터 둘이고, 고전 선형 스캔과는
속도를 견주지 않습니다.

### 오라클은 데이터에서 만듭니다

IP 가 하는 일은 메모리에 실린 16비트 데이터 전체에 술어를 적용해 조건에 맞는 칸을 표시하는
것입니다. Qiskit 에서 이것에 대응하는 것은 대각 원소가 ±1 인 대각 게이트 하나입니다.

```python
import numpy as np
from qiskit import QuantumCircuit
from qiskit.circuit.library import DiagonalGate, grover_operator

Q = 14
N = 1 << Q
rng = np.random.default_rng(0)
data = rng.integers(-32768, 32768, size=N).astype(np.int16)   # 16비트 signed

marked = np.flatnonzero(data > 32000)      # GT 술어. LT/EQ/RANGE 도 이 줄만 바뀝니다
diag = np.ones(N)
diag[marked] = -1                          # 술어를 통과한 자리만 위상 반전

oracle = QuantumCircuit(Q)
oracle.append(DiagonalGate(diag.tolist()), range(Q))
G = grover_operator(oracle)                # 오라클 + 확산을 묶은 반복 한 번
```

`marked` 를 미리 계산한다고 오라클이 답을 아는 것은 아닙니다. 술어를 데이터 전체에 적용한
결과이고 하드웨어도 매 반복 같은 일을 합니다. 정답 인덱스를 손으로 적어 넣는 식으로 바꾸면
검증이 성립하지 않습니다.

### 정답 수를 알 때와 모를 때

```python
from qiskit import transpile
from qiskit_aer import AerSimulator

M = len(marked)
r = int(np.floor(np.pi / 4 * np.sqrt(N / M)))    # M 을 알 때의 최적 반복

qc = QuantumCircuit(Q)
qc.h(range(Q))
for _ in range(r):
    qc.compose(G, inplace=True)
qc.measure_all()
sim = AerSimulator(method="statevector")
counts = sim.run(transpile(qc, sim), shots=1024).result().get_counts()
```

위 데이터에서는 `M = 221`, `r = 6` 이 나옵니다. 조건을 만족하는 인덱스가 나올 이론 확률이
0.9967 이고, transpile 0.11초 · 실행 0.02초입니다. Aer 가 대각 게이트를 분해하지 않아 회로
깊이는 26 입니다.

M 을 모를 때가 실제 장비가 푸는 문제입니다. 반복 상한을 1.2배씩 늘려 가며 찍고, 나온
인덱스를 술어로 검산해 틀리면 다시 돌립니다.

```python
cache = {}
def measure_once(j, seed):
    if j not in cache:                     # 같은 j 는 회로를 재활용
        c = QuantumCircuit(Q)
        c.h(range(Q))
        for _ in range(j):
            c.compose(G, inplace=True)
        c.measure_all()
        cache[j] = transpile(c, sim)
    bits = list(sim.run(cache[j], shots=1, seed_simulator=seed).result().get_counts())[0]
    return int(bits, 2)

m, lam, seed = 1.0, 6 / 5, 0
while True:
    j = int(rng.integers(0, int(m) + 1))
    seed += 1
    idx = measure_once(j, seed)
    if data[idx] > 32000:                  # 검산은 고전적으로. 판정의 근거는 여기
        break
    m = min(lam * m, np.sqrt(N))
```

`seed_simulator` 를 반복마다 바꿔야 합니다. 고정하면 같은 `j` 에서 같은 인덱스만 나와 루프가
끝나지 않습니다. 이 데이터에서 시드를 바꿔 20번 돌리면 누적 반복의 중앙값이 5, 최대가
41이었습니다. 평균은 `r = 6` 과 비슷한데 꼬리가 길고, 이 편차가 체크포인트로 줄이려는
대상입니다([11장](11_체크포인트와_정책_엔진.md)).

### 세 경로 중 무엇을 쓸 것인가

Q = 14, r = 6 에서 잰 값입니다.

| 경로 | 시간 | 언제 |
|---|---|---|
| `qiskit.quantum_info.Statevector(qc)` | 16~25초 | 쓰지 않음. 파이썬에서 게이트를 하나씩 곱함 |
| `AerSimulator` + `save_statevector()` | 0.1초 안팎 | 보고서에 실을 기준값 |
| NumPy 배열 직접 | 0.1밀리초 | 수천 번 돌리는 캠페인 |

```python
qc = QuantumCircuit(Q)
qc.h(range(Q))
for _ in range(r):
    qc.compose(G, inplace=True)
qc.save_statevector()                      # qiskit_aer 를 import 하면 생기는 메서드
sv = sim.run(transpile(qc, sim)).result().get_statevector()

psi = np.full(N, 1 / np.sqrt(N))           # 같은 것을 NumPy 로
for _ in range(r):
    psi *= diag                            # 오라클
    psi = 2 * psi.mean() - psi             # 확산: 평균 기준 반사
```

셋의 결과는 진폭 기준 `1e-13` 안에서 일치합니다. 새 골든 모델을 넣을 때 이 세 값을 함께
찍으면 틀린 것이 모델인지 기준자인지 바로 갈립니다.

### 이름이 바뀐 API

Qiskit 2.x 가 클래스를 게이트 형태로 옮기는 중이라 인터넷 예제 상당수가 경고를 냅니다. 3.0 에서
실제로 사라지므로 새 이름을 씁니다. 경고를 놓치지 않으려면
`python3 -W error::DeprecationWarning your_script.py` 로 돌립니다.

| 옛 이름 | 쓸 것 | 비고 |
|---|---|---|
| `Diagonal` | `DiagonalGate` | 2.1 부터 deprecated |
| `PhaseOracle` | `PhaseOracleGate` | 2.2 부터 deprecated |

Q = 14 에 반복까지 펼친 회로는 텍스트로 그리기에 너무 넓으니 `G` 한 벌이나 큐비트 서너 개짜리
축소판만 `qc.draw("mpl", filename="circ.png")` 로 그립니다.
