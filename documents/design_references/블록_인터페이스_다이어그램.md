## 3. 클럭과 리셋 소유권

| 경계 | network 쪽 | user 쪽 | CDC | 소유 |
|---|---|---|---|---|
| APB CSR | `gclk_noc` | `i_grover_csr_clk = gclk_accel` | `sni_apb_asynch` | **RVX 생성** |
| AHB DMA | `gclk_noc` | `i_grover_dma_clk = gclk_accel` | `mni_ahbm_asynch` | **RVX 생성** |
| 가속기 내부 | — | `gclk_accel` 하나 | 없음 | SJS |

`user_slaveif_apb_clkout` / `user_masterif_ahb_clkout` 을 쓰므로 **클럭은
유저가 넣어 줍니다.** `user_region` 의 이 두 줄이 그것입니다.

```verilog
assign i_grover_csr_clk = gclk_accel;
assign i_grover_dma_clk = gclk_accel;
```

리셋은 두 인터페이스가 같은 reset group(3)에서 나오므로 함께 풀립니다.
wrapper 는 `i_grover_csr_rstnn` 하나를 받아 전체에 씁니다. 비동기 assert,
음논리입니다.

**wrapper 안이나 Main IP 안에 CDC 를 또 넣으면 안 됩니다.** RVX 가 만들어
주는 것이 실보드에서 검증된 구조이고, 중복 삽입은 그 검증을 무효로 만듭니다
(인수인계 §3.2).

## 4. start 수락 조건

```
start_accept = cmd_search_start          COMMAND 쓰기가 만든 1사이클 펄스
             && !search_busy             실행 중이 아닐 것
             && !load_busy               적재 중이 아닐 것
             && res_empty                직전 열거 결과가 남지 않았을 것
             && !done_pending            직전 완료가 아직 안 읽혔지 않을 것
```

**start 큐를 두지 않습니다.** 조건이 안 맞으면 그 펄스는 조용히 버려지고,
펌웨어가 `COMMAND` 를 쓰기 전에 `STATUS` 를 확인하는 것이 규약입니다.
큐를 두면 "언제 시작했는지"가 소프트웨어에서 안 보이고, 그 상태에서
카운터를 읽으면 서로 다른 시점의 값이 섞입니다.

`done_pending` 은 mmio 의 `done_sticky` 입니다. `COMMAND` 쓰기가 그것을
클리어하고 한 사이클 뒤에 `cmd_search_start` 가 나오므로, 정상 순서
(설정 → `COMMAND` → 폴링)는 항상 통과합니다. 걸리는 것은 앞 실행을 읽지
않고 곧바로 다음 start 를 밀어 넣는 경우뿐입니다.

`search_busy` 는 코어가 따로 내보내지 않습니다 — 인수인계 §3.4 가
`busy = search_busy | load_busy` 로 정의하므로 `busy & ~load_busy` 로
유도합니다.

## 5. 데이터가 들어오는 길

```
  호스트가 만든 배열                보드에서 GEN
        │                                │
        ▼                                ▼
  ┌───────────────────────────────────────────────┐
  │  System SRAM  0xE0000000 ~ 0xE001FFFF (128KiB)│
  │  static unsigned int dataset[8192]            │  32 KiB, 4B 정렬
  └───────────────┬───────────────────────────────┘
                  │ DATA_ADDR / DATA_COUNT / DMA_COMMAND
                  ▼
  ┌───────────────────────────────────────────────┐
  │  bbht_ahb_loader                              │
  │   검사: 정렬 / 개수 / 범위 / main busy         │
  │   32b AHB SINGLE read, single outstanding     │
  │   워드당 3사이클 (주소 1 + 데이터 1 + 쓰기 1)  │
  └───────────────┬───────────────────────────────┘
                  │ data_wr_en / data_wr_addr[13:0] / data_wr_data[15:0]
                  ▼
  ┌───────────────────────────────────────────────┐
  │  Main IP generic loader → data mem            │
  └───────────────────────────────────────────────┘
```

엔디안 규약입니다. `data_count` 가 홀수면 마지막 워드의 상위 16비트는
쓰지 않습니다.

```
  word[k][15:0]  → data[2k]
  word[k][31:16] → data[2k+1]
```

Q14 전체(16,384 항목 = 8,192 워드)면 24,576 사이클, 100 MHz 에서 약 **246 µs**
입니다. 버스트로 올리는 것은 DMA 가 실제 병목임이 측정된 뒤에 볼 일입니다
(인수인계 §4.3).

## 6. 결과가 나오는 길

```
  Single 모드                        Enumeration 모드
  ─────────────                      ────────────────
  result_valid + result_index        Result FIFO 14b x 256
        │                                  │ res_dout / res_empty / res_count
        ▼                                  ▼
  CSR RESULT_INDEX (0x028)           CSR FIFO_DATA (0x040)
        │                                  │  읽기 완료 → res_pop 1사이클
        ▼                                  ▼
  STATUS.result_valid 확인 후 읽기    FIFO_COUNT / STATUS.fifo_empty 로 확인
```

**`FIFO_DATA` 는 읽는 것 자체가 pop 입니다.** 별도 POP 레지스터가 없고,
mmio 가 APB access 위상에 `res_pop` 을 한 사이클 냅니다. `pready` 가 상수 1
이라 access 위상이 정확히 한 사이클이므로 읽기 한 번에 pop 한 번입니다.
비어 있으면 pop 하지 않습니다.

**인덱스 0 이 정상 결과일 수 있으므로 값 0 을 empty 로 해석하면 안 됩니다.**

열거에서는 `done` 만 기다리면 안 됩니다. FIFO 가 256칸이라 그보다 많은 해가
나오면 하드웨어가 full stall 에 걸려 진행이 멈춥니다. `busy` 인 동안에도
계속 뽑아야 합니다 — 드라이버의 `bbht_search_enum()` 이 그렇게 되어 있습니다.

## 7. 정본이 하나여야 하는 곳

CSR 정의가 **세 곳에 따로** 있다가 서로 어긋난 적이 있습니다.

| 어디 | 무엇 |
|---|---|
| 옛 펌웨어 헤더 `grover_regs.h` | 8바이트 간격 제안안. 폐기 |
| 옛 설계안 `grover_mmio.v` | n=15 시절 초안. 폐기 |
| PJK proof app 각각의 `main.c` | 실제 맵을 앱마다 복사 |

앞 둘은 `trash_bin/` 으로 내려갔습니다. 거기서는 인용하지 마십시오.

그래서 JSON 정본 하나(`software/contract/bbht_grover_csr.json`)에서 넷을 생성하고,
회귀가 `--check` 로 생성물이 최신인지 먼저 확인하게 했습니다. 2026-09-13 `software/`
재편 때 빠졌다가 2026-09-16 에 되살렸습니다 (자리가 `software/csr/` 에서
`software/contract/` 로 바뀌었습니다).

```
  정본     software/contract/bbht_grover_csr.json      여기만 손으로 고칩니다
  생성물   software/contract/generated/bbht_grover_csr.vh    RTL 이 include
           software/contract/generated/bbht_grover_regs.h    펌웨어가 include
           software/contract/generated/bbht_grover_csr.py    호스트 CLI 가 import
           design_references/CSR_레지스터_규격.md            사람이 읽는 기록
```

같은 숫자를 들고 있으면서 생성 대상이 **아닌** 곳이 둘 더 있습니다. 기준모델
`final_hardware_contract.py` 는 CSR 과 다른 축인 정책 이름을 같이 담아서 생성으로
바꾸면 그 이름이 사라지고, `bbht_paper_bench/src/main.c` 는 보드 ELF 소스라 sha256 이
같아야 해서 한 글자도 못 고칩니다. 그래서 둘은 `--check` 가 **읽기만 하고 대조**합니다
(main.c 는 이름을 줄여 쓴 것이 열 개라 오프셋 기준으로 봅니다). 셋째 검사는 방향이
반대로, 생성 헤더를 우회해 RTL 안에 값을 다시 박는 것을 막습니다.

## 8. 회귀 게이트

통신 계층을 고치면 이 순서로 확인합니다. 위에서 아래로 갈수록 느리고 무겁습니다.

| 단계 | 명령 | 무엇을 보는가 | 걸리는 시간 |
|:-:|---|---|---|
| 0 | `make -C hardware_bram/sim ports` | **포트 계약 §3.3/§3.4 대조** | 즉시 |
| 1 | `make -C hardware_bram/sim lint` | 합성 대상 RTL lint | 초 |
| 2 | `make -C hardware_bram/sim regress` | CSR·DMA·FIFO 계약 (T1~T9) | 초 |
| 3 | `make -C hardware_bram/sim driver` | 드라이버 ↔ RTL 일치 (D1~D11) | 초 |
| 3b | `make -C hardware_bram/sim real` | 위 넷을 통신 계층 + 어댑터 + Main IP 로 | 분 |
| 3d | `make -C hardware_bram/sim bench250` | 250쌍 궤적 벤치 | 분 |
| 4 | `make sim_rtl` + 5개 proof app | SoC 전체 경로 | 분 |
| 5 | `make arty-100t && make imp` | 100 MHz 타이밍 | 수십 분 |
| 6 | 실보드 5개 시나리오 | E2E | — |

**4~6 을 통과하기 전에는 baseline 교체를 논의하지 않습니다** (인수인계 §4.2).
0~3d 는 원래 이 저장소 안에서 다 돌아갑니다 — Main IP 실물이 `src/` 에 있기
때문입니다. **다만 2026-09-13 부터는 CSR 생성 헤더와 포트 계약표가 빠져서 0~3d 가
멈춰 있습니다** (7절, `CLAUDE.md` 5절 끝). 4 이상은 RVX 플랫폼과 Vivado 가 필요합니다.

0 단계는 두 갈래(`ports` 자리 채우개 · `ports-real` 어댑터)로 나뉩니다. **배선이
계약대로인지 사람 눈 대신 확인하는 수단**입니다. `contract/port_contract.tsv`
는 인수인계 docx 에서 뽑아 커밋했던 것이고(추출기 `extract_contract.py`,
docx sha256 을 헤더에 남겼습니다), 셋 다 2026-09-13 에 저장소에서 빠졌습니다.
되살리면 아래 항목을 다시 잡습니다.

| 무엇을 잡는가 | 예 |
|---|---|
| 포트 이름 | `rpsel` vs 계약의 `psel` |
| 방향 | `IN` ↔ `OUT` 뒤바뀜 |
| 폭 | `j_target` 이 8비트 (계약 7) |
| signed | `threshold_a` 에 `signed` 누락 |
| 미연결 | wrapper 가 `seed_meas` 를 코어에 안 물림 |
