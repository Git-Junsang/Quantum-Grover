# DRAM 갈래 대 BRAM 정본 — 500 워크로드 대조

## 무엇인가

두 갈래를 같은 표본에서 맞댄 결과입니다. `make -C hardware_dram/sim bench500` 이
같은 테스트벤치(`tb_dram_bench500.v`)를 DRAM 갈래 코어와 `hardware_bram/src/` 의
정본 코어(K3/H3-E4-M2)에 각각 물려 500 워크로드를 돌립니다.

- 워크로드: 타겟 수 M = 1/4/16/64/256 × 시드 100 = **500**. 보드 500런·6단계
  ablation 이 쓴 것과 같은 로스터입니다
- 갈래 셋: `dram` / `bram normal`(mode0) / `bram ckpt`(K3/H3-E4-M2)
- 설정: `predicate=EQ`, `threshold_a=12345`, `data_count=16384`, `auto_shot=1`,
  `shot_cap=100`, `enum_enable=0`
- 통신 계층은 끼지 않습니다. DRAM 갈래에 아직 없으므로 두 갈래 모두 Main IP
  포트를 직접 흔듭니다

250쌍 벤치(시드 50)를 500 으로 올린 이유는 정본 근거와 표본을 맞추기
위해서입니다. 250쌍 로스터로는 보드 500런·6단계 캠페인과 총합을 맞댈 수 없습니다.

## 이 사이클은 보드와 같은 축입니다

통신 계층 없이 잰 값인데도, bram 코어를 물린 쪽이 두 정본 근거와 사이클까지
같습니다.

| 대조 상대 | 일치 |
|---|---:|
| `hardware_bram/results/2026-09-10_bench500_final_core/` (드라이버 하네스) | mode0 500/500, ckpt 500/500 |
| `hardware_bram/vivado/.../2026-09-08_k3h3_e4_m2_board_500run/per_run_m2.csv` | 500/500 |

`CSR_CYCLE_COUNT` 의 계측 구간이 탐색 자체라 통신 계층이 끼든 안 끼든 바뀌지
않기 때문입니다. 그래서 아래 dram 대 ckpt 비교는 보드 실측과 같은 사이클 축
위에 있습니다.

## 정합성 — 세 갈래가 같은 계산을 합니다

`trial_count` · `L_BBHT` · `result_index` 가 **500/500 × 3갈래 전부 일치**하고
`config_error` 0 건입니다. DRAM 갈래가 진폭을 DRAM 에서 복원해도 보드 검증
정본과 같은 답·같은 궤적을 낸다는 근거입니다.

## 비용 — 정본이 이깁니다

DRAM 지연을 세 가지로 줘서 재었습니다. 어느 쪽이든 결론이 같습니다.

| DRAM 지연 | dram 사이클 | bram ckpt | 차이 | 승/무/패 (dram 기준) |
|---|---:|---:|---:|---|
| `fast` (WR 0 / RD 1) | 9,332,398 | 5,328,877 | **+75.13%** | 13 / 0 / 487 |
| `model` (WR 4 / RD 12, TB 기본) | 9,380,081 | 5,328,877 | **+76.02%** | 13 / 0 / 487 |
| `slow` (WR 9 / RD 31 + 백프레셔) | 11,893,069 | 5,328,877 | **+123.18%** | 1 / 0 / 499 |

타겟수별로 보면 희소할수록 dram 이 그나마 붙습니다 (`model` 기준).

| M | bram ckpt | dram | 배수 |
|---:|---:|---:|---:|
| 1 | 2,232,584 | 3,000,246 | 1.34x |
| 4 | 1,323,661 | 2,368,906 | 1.79x |
| 16 | 892,367 | 1,882,407 | 2.11x |
| 64 | 543,909 | 1,281,787 | 2.36x |
| 256 | 336,356 | 846,735 | 2.52x |
| **전체** | **5,328,877** | **9,380,081** | **1.76x** |

mode0(Normal) 과 맞대면 `model` 지연에서 사이클 -20.41%, `slow` 에서 +0.91% 로
거의 비깁니다. 즉 DRAM 갈래는 체크포인트 없는 Normal 과 비슷한 자리에 있고
정본 체크포인트에는 못 미칩니다.

## 왜 지는가 — 지연 탓이 아닙니다

DRAM 갈래는 물리 Grover 반복을 압도적으로 줄입니다.

| | dram | bram ckpt | |
|---|---:|---:|---|
| 물리 반복 | 245 | 9,582 | dram 이 **39.11배** 적음 |
| 반복당 사이클 | 38,091 | 556 | dram 이 **68.5배** 비쌈 |

반복을 39배 줄이고도 반복 하나가 68배 비싸서 총합에서 집니다. 그리고 지연을
거의 0(`fast`)으로 줘도 +75.13% 라 **지연이 원인이 아닙니다.** 라운드마다
512행을 DRAM 슬롯에 넣고 빼는 고정 비용이 원인이고, 이것은 MIG 를 아무리 빠른
것으로 바꿔도 남습니다. 물리 바인딩을 붙이기 전에 이 고정 비용부터 줄일
방법(라운드 간 프리페치, 버퍼 B 활용)을 봐야 한다는 뜻입니다.

## 경계

- **dram 사이클은 동작 수준 DRAM 모델 위의 값입니다.** 물리 MIG/AXI 바인딩은
  아직 없습니다. 인용할 때 어느 지연으로 쟀는지 반드시 같이 적으십시오
- **버퍼 B 를 쓰는 라운드 간 프리페치가 아직 없습니다.** 그 구현이 붙으면
  반복당 비용이 달라질 수 있으므로, 이 표는 현재 RTL 초안의 값입니다
- 단일탐색 전용입니다. `enum_enable=1` 은 `config_error` 로 거절합니다
- bram 쪽 mode0 사이클을 6단계 ablation 의 `Normal-E1` 과 맞대지 마십시오.
  저쪽은 `INTRA_ENGINES=1` 별도 빌드입니다

## 재현

```bash
make -C hardware_dram/sim bench500              # TB 기본 지연
make -C hardware_dram/sim bench500 DLAT=fast    # 지연 0 에 가까운 상한
make -C hardware_dram/sim bench500 DLAT=slow    # 백프레셔까지 있는 하한
```

한 벌에 10분쯤 걸립니다 (dram 1분 + bram 8분 + 리포트).
